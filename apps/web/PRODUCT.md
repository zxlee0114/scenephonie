# Product

## Platform

web

## Users

- **主要：受邀的台灣職業影視編劇。** 人數少、由作者邀請，v1 不公開註冊（Google OAuth ＋ allowlist）。使用情境是**一個人連續寫稿好幾個小時** —— 判準是八小時後的疲勞度，不是一屏塞多少。他們的工作：以場次為單位寫劇本，同時整理交件文件（交件大綱、分場大綱、人物介紹），最後匯出合規的 PDF 交稿。
- **次要：分享連結的讀者。** 製片、導演與劇組各職位，透過唯讀分享頁（即時分享或凍結分享）讀劇本與場次表。只讀、不登入、不編輯。
- **次要入口：訪客。** 還沒有帳號、想先體驗的人。login 頁的「以訪客身分體驗」會給他一份自己的範例劇本（閒置七天清除）。訪客入口視覺上次一階，**設計決策不以訪客為準**。

## Product Purpose

台灣影視編劇工具。要治的病是「大家用 Word 寫劇本，所以**格式就是內容的一部分**」—— 三角形、簡表還是行內 metadata 全刻在文字裡，換一種格式等於重排全文。

Scenephonie 把劇本存成**一組帶 metadata 的場次**（時間、內外、地點、登場人物、群演），讓格式與內容脫鉤，各種格式退化成渲染樣式；同時讓劇組其他職位能取用劇本裡的結構化資訊（場次表）。

成功＝編劇能在這裡從頭寫完一部劇本、不必想格式，並一次匯出符合 GHSA 優良電影劇本獎格式的交件 PDF。

## Positioning

「格式不該是你的事」—— 與 Final Draft／WriterDuet 的「保證你的格式沒錯」正面相反。編輯器呈現劇本的**閱讀與創作語意**，不模擬任何輸出格式（不變式 G，`docs/adr/0010`）；結構化在資料裡（場次有永久 id、人物與地點是被引用的獨立記錄），而不是畫在螢幕上。

## Operating Context

- 主要畫面：專案儀表板 `/projects` → 專案 hub（文件平鋪清單）→ 劇本編輯器（Tiptap 區塊編輯器，`/` 選單、場次導覽 sidebar、「劇本／場次表」切換）→ 散文文件頁 → 匯出 PDF；唯讀分享頁 `/s/<token>`、`/s/<token>/table`。
- 編輯器以鍵盤為主（規格 §7.1 快捷鍵總表）、中文 IME 輸入（§7.6）。
- 劇本規模：單一劇本專案，可到 130 場以上。
- 交付物：GHSA 格式 PDF（規格 §9）。PDF 版面是獨立的輸出模板，與螢幕呈現無關。

## Capabilities and Constraints

- v1 功能邊界見規格 §3.1（F1–F18）；不做的見 §3.2（即時協作、多格式輸出、影集、匯入、資料儀表板等）。
- **v1 沒有行銷頁、沒有 landing page、不公開註冊。**
- 三條硬性架構約束（規格 §2）：場次是穩定錨點；**資料模型不含呈現性資訊**；不得堵死協作。
- 不變式 G：編輯器不是 PDF 預覽，不沿用 GHSA／TNUA 模板的數字（`docs/adr/0010`、`docs/editor-typography.md`）。
- 技術：Next.js App Router ＋ TypeScript ＋ Drizzle ＋ Postgres；部署 Vercel Hobby ＋ Supabase Free（`docs/tech-stack.md`）。
- 術語權威：`CONTEXT.md`（場次 ≠ 場景、場次號是呈現標籤不是識別碼、交付、分享…）。
- 未決（規格 §3.3）：新手引導的形式、場次 Tag、全文搜尋、按人物聚合的清單視圖。

## Brand Commitments

- 名稱 **Scenephonie**；無中文品牌名、無 tagline、**v1 無 brand color**（規格 §7.12）。
- 品牌資產止於 wordmark（Source Sans 3，`Scene` 600／`phonie` 400，SVG outline）＋ favicon（深色圓角容器＋反白 `S`）。不新增獨立 mark。
- **介面文案說劇組語言。** 只講編劇與劇組聽得懂的話；概念名稱以 `CONTEXT.md` 為準，同一個概念全站一個詞（不要「景／光」「內外／時間」「時間」三套並存）。CONTEXT.md 裡偏建模的詞（如「實體」）不直接對使用者說，改說「人物」「地點」。語氣平實、不賣萌、不拿 emoji 當語氣。繁體中文。

## Evidence on Hand

- 範例劇本：訪客與新手引導用的範例專案（票 07、73）。
- 研究：`.scratch/scenephonie-mvp/research/`（台灣劇本格式、GHSA 交件文件、CJK 字型與載入、UI tokens 草案）。
- 尚無：真實劇本語料（字型覆蓋率與 `--text-base`／`--leading-base` 都等它回頭量）、使用者見證、業界訪談結論（票 21 進行中）。**不得捏造。**

## Product Principles

1. **格式不是內容。** 螢幕上任何只為模擬某種輸出而存在的東西都出局；能留下的只有劇本的閱讀語意（場次成塊、動作與對白的節奏、對白較窄的閱讀寬度）。
2. **為一個人寫八小時而設計。** 沉靜優先於資訊密度；介面像作業系統，內容像稿子。
3. **缺漏不可被預設 UI 隱藏。** metadata 預設可見；空 metadata → 自動草稿 → 匯出前被攔，這條防呆不能變成驚喜。
4. **一條路走通，但不堵死岔路。** v1 只做一種（格式、專案類型、場次表層級），架構預留擴充。
5. **永久身分高於顯示序號。** 所有引用、跳轉與下游文件掛在場次 id 上，不掛在「第 12 場」上。

## Accessibility & Inclusion

- **WCAG 2.2 AA** 為下限：文字對比 4.5:1（大字與非文字元件 3:1）、focus 永遠可見。可操作元件與 placeholder 不得低於 AA（票 86）；純裝飾性文字依 1.4.3 豁免。
- **鍵盤優先**：編輯器全程可用鍵盤完成寫稿；保護 Tab 焦點串接，不把每個 affordance 都塞進 Tab 序（規格 §7.10）。
- **中文 IME**：組字中不得觸發快捷鍵、選單或提交（規格 §7.6）。
- 尊重 `prefers-reduced-motion`。
