# UI 素材的存放慣例

素材為 [票券 26](../../../issues/26-ui-visual-direction.md) 服務，討論在 [`../../ui-visual-direction.md`](../../ui-visual-direction.md)。

## 兩個資料夾，不可混放

| 目錄     | 放什麼                                     | 對應      |
| -------- | ------------------------------------------ | --------- |
| `ref/`   | **別人怎麼做** —— 既有產品的截圖           | 討論檔 §1 |
| `draft/` | **我想要什麼** —— 自己或 AI 生成的暫定素材 | 討論檔 §2 |

⚠️ 分開的理由跟討論檔分節一樣：混在一起之後，「我想要什麼」會慢慢變成「大家都這樣做」。

## 命名

**`ref/`：`<產品>-<畫面>.png`** —— 例：`finaldraft-editor.png`、`notion-blocks.png`。不加編號，參考素材是會增刪的集合，不是序列。

**`draft/`：`<類別>-<主題>-v<輪次><候選字母>.png`** —— 例：`icon-v1-a.png`、`icon-v1-b.png`、`icon-v2-a.png`、`mood-editor-v1.png`。

- **同一輪的並列候選用字母**，**重新生成的新一輪換數字**。兩個維度分開，是因為要做的比較有兩種（「這一輪裡哪個好」／「第二輪有沒有比第一輪好」），共用一組編號會把它們攪在一起。
- **風格圖按畫面命名，不按主題** —— 最後要判斷的是「這個風格套到場次表還成立嗎」，按畫面切才問得出這句話。

**都不加日期。** git 已經記了時間，檔名裡的日期只會過期。

## AI 生成的素材必須留 prompt

沒有 prompt 就**不可迭代** —— 看到某張比較好、想在它基礎上微調時，只能從頭猜。

**規則：`draft/prompts/<同 basename>.md`。** 同名即配對，不需要另外維護對照表。

檔案內容：生成工具（Midjourney／DALL·E／Ideogram…）、完整 prompt、seed（若有）、以及參考圖（若有）。

## 落選的不要刪

票券 26 定案後，落選的素材留在 `draft/` 當 primary source。**「為什麼不是 B」跟「為什麼是 A」一樣值錢。**

## 這裡不放什麼

**Typography 與色彩系統不是圖片。** 它們是一組會被程式讀的**值**，住在 [`../../ui-tokens-draft.md`](../../ui-tokens-draft.md)。色票的截圖不是色彩系統，是色彩系統的照片 —— 之後還得有人手動抄成 hex。
