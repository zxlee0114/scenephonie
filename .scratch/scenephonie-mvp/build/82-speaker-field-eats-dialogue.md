# 82 — 實體欄位改成 Enter 才解析；人物欄選定說話者就進台詞，台詞不再被切成人物

**What to build:** 選完說話者之後直接打台詞，台詞留在人物欄裡，打到「，」就被即時切成 chip —— 台詞變成一顆待建立的人物，
前半句不見。**資料遺失，而且就在寫對白的主路徑上**。修法不是在現有模型上補洞，而是把三個實體欄位的輸入模型改掉
（grilling 2026-10-27，見下方「定案」）。

**Blocked by:** 無

**Status:** verified

## 重現（修之前）

示範劇本（訪客）任一場：

1. `/對白` → 人物欄打「阿」→ Enter 選「阿盈」
2. 直接打「你不說話，我就當你答應了。」→ Enter

結果：人物欄多一顆待建立的人物 chip「＋我就當你答應了。」，「你不說話，」消失；台詞是空的。

## 成因

對白人物欄**是多值欄**（`nodes/blocks.tsx` 為了齊聲給了 `multiple`），所以跟地點欄、登場人物欄一樣走
`splitNamesLive`（`packages/schema/src/names.ts`）：`NAME_SEPARATORS`（`、，,；;`）**打下去的當下就切 chip、建實體**。
選中阿盈之後游標還留在人物欄（Enter 一下是「選中」、再一下才是「離開」），接著打的台詞就落進這套規則。

> 開票時寫「對白人物欄是單值欄（見票 58）」是錯的，已更正。

## 定案（grilling 2026-10-27）

**三欄共通：打字時不切，Enter 才整串解析**（地點欄、登場人物欄、對白人物欄）

- [x] 打字過程中分隔符只是字，不切 chip、不建實體。**Enter 時整串一次解析**，分隔符照舊是整套 `、，,；;`（三欄同一份）。
  - 理由：即時切會讓同一串名字分成兩種待遇 —— 「小八、吉伊」打到頓號時小八已經悄悄建好，吉伊還要等 Enter。
    §4.7「立刻看到命中還是新建」對注音（以及倉頡、速成、拼音）使用者本來就不成立：組字中 Enter 屬於 IME（§7.6 不變），
    字送出之前這一欄什麼都還沒發生。改成 Enter 才解析，結果仍在 Enter 那一下當場看得到。
- [x] 選單（以及組字中的唯讀預覽）只看**最後一段**（最後一個分隔符之後正在打的那段）。
  現象（使用者回報）：現在組字預覽只認得第一個命中的名字，頓號之後就看不到 —— 一起修。
- [x] Enter 時，最後一段照選單選中的那一列處理；前面各段照現行 `resolve` 的規則（命中既有，否則建立新的，chip 帶「＋」）。
- [x] **離開欄位**（滑鼠點走、Shift+Tab）走同一份解析，只是游標不跟著去台詞 —— 一個字都不掉。
- [x] **一次 ⌘Z 退回 Enter（或離開）之前的樣子**：整串字回到輸入框，這一下建的 chip、新實體、搬進台詞的字一起撤。
  沿用票 37／53「⌘Z 把打的字還回來」的接縫，不另寫一套。
- [x] 貼上走同一份解析（貼上後同樣等 Enter）。kernel 的 `splitNamesLive` 不再有「即時」的呼叫端 —— 改名或收斂成單一解析函式，
  「頓號怎麼切，伺服器端與這裡同一個答案」那條照舊成立。

**對白人物欄獨有**

- [x] **Enter 定案名字之後，游標直接進同一句對白的台詞**（選單選中、打完新名字 Enter 都是）。
  例外：選了之後還要回答問題的那幾列（建立群演、升格、確認取代）照舊留在欄位裡問完，問完才進台詞。
  輸入框空著、已有 chip 時按 Enter ＝ 進台詞，不變。
- [x] 齊聲的寫法就是「、」：「阿盈、建」→ 選單過濾「建」→ Enter 選中建鳴 → 兩顆 chip 一起定案、進台詞。
- [x] 字串裡出現**分隔符以外的台詞標點** `。？！…—「」：` 時，選單第一列從「＋ 建立新人物」換成 **「↓ 移到台詞」**。
  Enter 把那串字插到**台詞開頭**，游標停在插入那串字的尾端；已有的 chip 保留，不建任何實體。
  真有人名帶這些標點，按 ↓ 選「建立新人物」。離開欄位時同樣照這一列搬過去。
- [x] 移完之後人物欄是空的 ＝ 一句沒有說話者的對白，照現行規則（草稿判定見 66），本票不另處理。
- [x] **不加**輸入框的淡字提示 —— 陷阱（選完人還留在人物欄）已經拿掉，選單本身就是提示（59 的原則）。

## 已知的漏網（接受）

沒有句末標點的台詞（「你不說話，我就當你答應了」）會被讀成兩個新人物、帶「＋」的 chip。看得見，⌘Z 一下整串退回輸入框。
用它換三欄同一份分隔規則（grilling Q11：「阿盈，建鳴」在三欄都是兩個人）。

## Comments

**實作（2026-10-27）**

- kernel：`splitNamesLive` 收斂成 `parseNameDraft`（前面各段 ＋ 正在打的最後一段），另加 `hasDialogueMark`／`DIALOGUE_MARKS`。
- **群演欄也改成 Enter 才解析**（使用者裁決：四欄同一套鍵，`splitNamesLive` 不留即時呼叫端）。
- **⌘Z 範圍**（使用者裁決）：欄位內 ⌘Z 一次退整串（不再只有單筆）；對白人物欄 Enter 進台詞之後，台詞裡的 ⌘Z 撤到那一步時整串字回到人物欄、焦點跟著回去（`DialogueView` 看 history transaction 把這一句退回定案之前的樣子）。**點走之後的 ⌘Z 照票 37 不插手**。
- 例外列照票面：建立群演、升格留在欄位（空欄位上再按 Enter 進台詞）；別名、改名問完第二步才進台詞；確認取代只在單值欄出現。⚠️ 建立群演在人物欄裡其實沒有下一個問題 —— 驗收時若覺得多按一下，改成直接進台詞只是一個旗標。
- 定案那一步自成一個 undo 事件（`closeHistory`），接著打的台詞不併進來。
- 手上握著一顆 chip 時，它屬於**最後一段**（選單與抬頭說的那段）；前面某段原封打出它的名字才輪得到。

**第一輪人工驗收（2026-10-28）**

- **點走那一下的定案，⌘Z 把整串字還給那一欄**（使用者回報：「用移除焦點的方式讓打的字變成實體，cmd + Z 會將欄位清空」；
  裁決：四欄都接）。撤到那一下的 ⌘Z 不論打在哪裡（內文、別欄），整串字回到那一欄、焦點跟著回去；撤的是別的動作就不插手。
  做法：欄位記下「定案那一刻焦點跟著走了」的那一下（`Committed.away`；點走、對白人物欄 Enter 進台詞），宿主（場次 node view、
  對白 node view）在每次 history transaction 當下讀 doc、交給欄位比對（`after-history.ts` 的 `useAfterHistory`、
  `afterHistory`）。群演欄原本沒有「⌘Z 還字」，這次只補點走這一格（含第二下 ⌘Z 收字、⌘⇧Z 做回）。
  **Enter 定案、焦點留在欄位裡的那一下照票券 37 不變**：點走之後再 ⌘Z，欄位不插手。點走時「↓ 移到台詞」那一下也撤得回來。
  這一條推翻了實作時「點走之後的 ⌘Z 照 37 不插手」的範圍裁決。
- **新增群演定案也直接進台詞**（裁決：原本照票面留在欄位裡，要在空欄位多按一次 Enter）。
- **沒有句末標點的台詞**：猜它是不是句子（裁決：長度＋人稱代名詞）。一段**不認得**的字（不是既有人物、本場群演、手上那一筆）
  超過四個字、或帶「我／你／妳／您」，選單第一列就是「↓ 移到台詞」；群演的人數尾綴（`眾人 x20`）不算長度。
  kernel 的 `readsLikeSpeech`。「你不說話，我就當你答應了」→ 台詞；「阿盈，建鳴」「小八，吉伊」→ 人名。上方「已知的漏網」因此收窄成：
  兩段都在四個字以內、又不帶人稱的短句（「好，走吧」）仍會被讀成兩個人。
- 拆出去的：92（整串結果的預覽）、93（群演與人物互相轉換）、94（⌘A 第二層反白看起來亂，與本票無關）。
