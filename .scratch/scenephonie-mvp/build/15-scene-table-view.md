# 15 — 場次表檢視

**What to build:** 第一層投影，純從劇本推導、零新增資訊（§8）。`projectSceneTable(doc): { rows, missingRefs }` —— **簽名裡沒有 doc 以外的輸入**（型別本身在強制「零新增資訊」；有人想加一欄製作端另填的東西會發現簽名裝不下）。六欄：場次號（推導，`12`／`5.1`／`26`，草稿不出現）、景（內外）、光（時間）、地點、登場人物、群演。地點欄與登場人物欄印 `實體名（這一場的顯示名）`，**只在兩者不同時才印括號**（`海豚公寓房間（未知大樓房間）`、`小明（男子）`）。子場次**自佔一列**，緊接主場次之後，縮排僅作視覺次級；群組成員各自一列；**群組本身、草稿、子場次的 `種類` 都不進表**。雜景不拆：印編劇填的地點清單，留空時印推導文字「參照敘述」（不建垃圾實體）。`missingRefs` 是 projection 的**診斷輸出**，不參與渲染、不被持久化、消費者的業務邏輯不得讀它。與 PDF、匯出前草稿清單**共用同一次走訪**。**不建投影表**（讀取當下純函式推導）；日後要加就是這函式輸出的快取，key ＝ `doc_seq`，可 `DROP` 重建、可有真外鍵。UI（§7.10）：劇本編輯器 ↔ 場次表是**子路由 ＋ 頁內 segmented control**（「劇本／場次表」），否決 split view；切換時以游標所在場次為 scroll anchor 互相對位。**場次表沒有自己的寫入路徑**（要改就回頭改 doc、走 command 層）。列可點，跳回編輯器並定位到該場 —— 跳轉掛在**永久 id** 上，重排場次也不跳錯。搜尋框：v1 只做**清單篩選**（比對場次號／地點／人物／時間，純前端 filter over 已在記憶體的投影），全文搜尋不做。
