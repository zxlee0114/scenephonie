# 15 — 場次表檢視

**What to build:** 第一層投影，純從劇本推導、零新增資訊（§8）。`projectSceneTable(doc): { rows, missingRefs }` —— **簽名裡沒有 doc 以外的輸入**（型別本身在強制「零新增資訊」；有人想加一欄製作端另填的東西會發現簽名裝不下）。六欄：場次號（推導，`12`／`5.1`／`26`，草稿不出現）、景（內外）、光（時間）、地點、登場人物、群演。地點欄與登場人物欄印 `實體名（這一場的顯示名）`，**只在兩者不同時才印括號**（`海豚公寓房間（未知大樓房間）`、`小明（男子）`）。子場次**自佔一列**，緊接主場次之後，縮排僅作視覺次級；群組成員各自一列；**群組本身、草稿、子場次的 `種類` 都不進表**。雜景不拆：印編劇填的地點清單，留空時印推導文字「參照敘述」（不建垃圾實體）。`missingRefs` 是 projection 的**診斷輸出**，不參與渲染、不被持久化、消費者的業務邏輯不得讀它。與 PDF、匯出前草稿清單**共用同一次走訪**。**不建投影表**（讀取當下純函式推導）；日後要加就是這函式輸出的快取，key ＝ `doc_seq`，可 `DROP` 重建、可有真外鍵。UI（§7.10）：劇本編輯器 ↔ 場次表是**子路由 ＋ 頁內 segmented control**（「劇本／場次表」），否決 split view；切換時以游標所在場次為 scroll anchor 互相對位。**場次表沒有自己的寫入路徑**（要改就回頭改 doc、走 command 層）。列可點，跳回編輯器並定位到該場 —— 跳轉掛在**永久 id** 上，重排場次也不跳錯。搜尋框：v1 只做**清單篩選**（比對場次號／景／時間／地點／人物／群演，純前端 filter over 已在記憶體的投影），全文搜尋不做。

## Comments

**2026-10-22 實作（使用者裁決）：實體名不在 doc 裡，投影拆兩段。** 地點／登場人物欄要印 `實體名（顯示名）`，
但實體名住在專案的 `characters`／`locations` 表（ADR-0005），`missingRefs` 也只有看得到實體表才判斷得了。
裁決：`projectSceneTable(doc) → { rows }` **維持只吃 doc**（列上帶原始引用 `{ id, displayName }`）；
另一支純函式 `labelSceneTable(table, names)` 只多吃一份 id → 名字的查表，印出格子裡的字並產出 `missingRefs`。
「零新增資訊」的強制力完整留在投影上 —— 第二段加不出新的欄。（§6.4／ADR-0007 寫的
`projectSceneTable(doc): { rows, missingRefs }` 因此與實作差一個欄位，`missingRefs` 搬到第二段。）

**實作落點與幾個規格沒寫死的選擇**：
- **編輯器搬進 `[screenplayId]/layout.tsx`**，`page.tsx`／`table/page.tsx` 是空頁、只決定網址。layout 跨子路由不重新掛載
  → 切到場次表時編輯器不卸載，表讀的是**記憶體裡的 doc**（還沒存檔的字也在），回來時游標與復原堆疊都在。
- 對位：劇本 → 場次表以游標所在場次對位；游標在草稿裡（草稿不進表）對位到它**前面最近的一列**。
  場次表 → 劇本（segmented control）捲回編輯器的游標場次 —— 場次表沒有游標，讀者在表上捲到哪裡不帶回去。
- 搜尋：驗收時改為比對**表上每一欄**（原規格只比場次號／地點／人物／時間；編劇裁決加入景與群演，spec §7.10 已同步）。空白分開的幾個詞**全部**要對上；場次號**整個比**（`5` 找得到 `5`、`5.1`，找不到 `15`、`50`）。
- 點列**先開這一場的唯讀預覽**（驗收時編劇裁決：整列可點太容易誤按）。預覽印這一場的內文 —— 動作、對白
  （說話者印這一場的叫法）、插入畫面、子場次（依文件順序）；群組成員印屬於它的片段。點外面／Esc／「關閉」關，
  「到劇本這一場」才依 `sceneId` 跳回編輯器。spec §7.10 已同步。
- 窄螢幕：場次／景／光不折行，文字欄至少 8em；放不下就表內橫捲（頁面不出 x 軸），場次欄釘在左側，橫捲一欄一欄停
  （scroll snap，對齊線是場次欄右緣）。
- `missingRefs` 在 client 推導場次表時刻意丟掉；§6.6 要的伺服器端結構化日誌**還沒接**（沒有伺服器端讀場次表的路徑，
  第一個會是分享連結／PDF）。
