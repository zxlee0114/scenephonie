# 14 — 草稿場次

**What to build:** 推導出來的狀態，**不是要手動「轉換」的狀態**（§4.8）—— 因此沒有任何時刻有東西在編劇背後改他的文件，欄位填完它自己就變回正式場次。`是草稿 = manualDraft 為真 OR metadata 不完整`。資料模型只多一個 `manualDraft` 布林值，**不存狀態機**。三條會讓場次自動成為草稿的不變式（零新機制，全部接到「metadata 不完整」）：同一群組的成員之間 metadata 完全相同、子場次的 metadata 與主場次完全相同、metadata 有空欄（雜景的地點欄除外）。「metadata 不完整」的判定**隨 `內外` 的值改變**：`內外＝雜景` 時地點欄留空**合法**。不參與正式場次編號，另有推導標籤 `S11[D1]`／`S11[D2]`，**錨定前一個正式場次**（錨定後一場會與真正的 `S12` 撞號）；排在全劇第一場之前 → `[D1]`。**不進 PDF、不進場次表。** 父場次是草稿 → 子場次一律是草稿；子場次可以單獨是草稿而父場次不是。「不再提醒」記的必須是 `sceneId`。草稿與正式場次在編輯器中要有視覺區隔（`draft` semantic token，判準是常駐、大量、**不疲勞**）。

## Comments

**2026-10-21 來自票券 12 驗收（使用者裁決）**：同一群組的成員之間**同地點、同時間**（kernel `sameSpaceTime`：地點與時間都填了且相同）也算自動草稿條件 —— 不變式 ③ 的寬鬆版。建立對剪時 `intercutTo` 已經擋；但編劇事後手動把成員改成一樣時**不在編輯當下擋**（改 metadata 一欄一欄改，會經過中間狀態），交給草稿推導。判準已在 `packages/schema/src/subscenes.ts`，本票接上即可。

**2026-10-21 實作（使用者裁決三項）**：
1. **登場人物不參與「metadata 不完整」**：完整只看時間、內外、地點（雜景的地點除外）。沒人入鏡的空景是合法場次。登場人物仍參與不變式 ②③ 的「完全相同」比對。
2. **草稿標籤錨在自己的層級**：頂層草稿錨前一個正式頂層號（`5`、`5.1` 之後是 `S5[D1]`），草稿子場次錨前一個正式子場次（`S5.1[D1]`）。同一錨點底下共用一條 D 序列，不撞號。
3. **SceneMenu 加「標記為草稿／取消草稿標記」**，背後是 kernel command `setManualDraft`。

「不進 PDF、不進場次表」在本票的落點是 `projectScenes` 每一列的 `draft`：場次表（15）、PDF（18）、匯出前清單（19）各自濾掉。「不再提醒」記 `sceneId` 歸票 19，那邊直接讀 `SceneNumber.sceneId`。所以這一條勾選框留給 15／18 驗收。

**2026-10-21 使用者裁決：草稿在編輯器裡「離開時才判定」**（實作前）。剛新增的一場馬上被標成草稿很怪 —— 編劇才剛開始寫它。

> 畫面上一場是不是草稿，在**游標進入時鎖住**，**游標離開時才重新判定**。新建的場次進場時鎖成「正式」。

- 新增場次 → 正式場號 → 游標離開時 metadata 不完整 → 草稿 → 游標回來，維持草稿（填完也不變）→ 離開時已完整 → 正式場號。
- **只是編輯器的顯示層**：doc 不寫任何東西，`projectScenes` 不動；場次表、PDF、匯出前清單讀的是真實狀態。
- **手動標記立即生效、不鎖**（編劇明確的動作）。三種自動原因（不完整、與主場次相同、成員撞時空）一起鎖。
- **所有新建都起步成正式**：`/next`、子場次、「對剪到…」新成員。
- **焦點單位是游標直接所在的那一場**：主場次走進子場次就算離開主場次；片段算它的成員。
- **只有游標移到別場才算離開**。編輯器整個失焦（切視窗、點外面的 UI）不算 —— 標籤不會趁編劇不在時變形。
- 代價（接受）：新場次先佔號，後面的場次先 +1，離開時若轉草稿再退回。

**2026-10-21 實作後 review 補的兩條**（延伸上一則裁決，不是新規則）：
- **還沒開工的場次（metadata 全空且沒有內文，票 31 的判準）進場時也鎖成正式**，等同剛新增。否則新劇本的第一場、重新整理後的空末場，焦點一落進去就是 `[D1]` —— 正是上一則要避免的那個「怪」。
- **程式自己搬動的游標不算「移到別場」**：kernel command 整份 replace 會把 selection map 到文件一端再 `view.focus()`，那之後的 selection／focusin 不看，等編劇自己的下一筆 transaction。連帶修正：「標記為草稿」改成保住游標位置（只動 attr）。
- 已知不處理：⌘Z 再 ⌘⇧Z 重做 `/next` 帶回來的場次不算「新增」—— redo 一次新增與 undo 一次刪除分不出來，兩者都是把舊的帶回來。
