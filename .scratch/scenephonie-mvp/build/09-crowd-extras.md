# 09 — 群演

**What to build:** 場次限定實體。場次上一個 `{ extraId, 描述, 人數 }[]` 清單（可多組：`咖啡廳客人 x8、服務生 x2`）。id 只在該場次內有意義，不進人物表。**入口不走 `/` 選單**（否決 `/extra`、`/crowd` —— 群演是 metadata 欄位而非區塊）—— 走內嵌簡表的群演欄 ＋ 對白人物欄的自動補全（可在那裡直接新建一筆，解掉「寫對白寫到一半跳去簡表」的心流問題）。描述可跨場次自動補全，但**只補字串、不建立連結**（不做「這是同一批人」的假承諾）。對白的人物欄合法目標是「人物」或「本場次的群演」；分界：**一個人說話 → 人物**（即使名字只是「路人甲」）；**一群人齊聲說 → 群演**。群演進場次表第一層（唯一消費者），**不進 PDF**。跟著場次被複製時一起複製（**不去重** —— id 只在該場次內有意義，跟著複製是正確的）。「臨演」與「群眾演員」不拆；「特約」不是群演（那是有台詞的小角色，已被人物吸收）。

## Comments

**2026-09-10 — 實作收票。** 群演的兩半各自有家：

| 半 | 家 |
|---|---|
| 值語意（id、解析、讀取正規化、場次表那一格） | `packages/schema/src/extras.ts` |
| 寫入 | `packages/schema/src/commands/extras.ts` 的 `setSceneExtras` |
| 簡表的入口 | `apps/web/src/editor/extras-field.tsx` |
| 對白人物欄的入口 | `entity-field.tsx` 的 `sceneExtras`／`onCreateExtra` 兩個 prop |
| 跨場次描述（**只有字串**） | `apps/web/src/editor/extras-catalog.ts` |

### 五個實作當下才定案的決定

1. **群演欄不是 `EntityField`。** 兩者長得像，但自動補全命中的東西不同 —— 實體欄命中一筆
   實體，群演欄命中**幾個字**，而第三列「作為既有實體的另一個名字」在群演上根本沒有東西
   可以指。共用的是**規則**（多值分隔、組字期間不動作、Backspace 還原）不是程式碼；那三條
   規則本來就住在 kernel 與同一套鍵盤慣例裡。

2. **沒寫人數就是 1，`x0` 退回去當描述。** `count` 不允許 null（schema 既有決定），所以
   「未填」這個狀態不存在，而「一位」是 `服務生` 這串字最誠實的讀法。`x0` 不當人數 ——
   0 個背景演員等於沒有這一筆，而系統不該替編劇判斷那是筆誤還是名字的一部分。

3. **在對白人物欄新建的群演，與指向它的引用是同一個 transaction。** 群演的家就是這份 doc，
   所以「先建立實體、再寫入 doc」在這裡收斂成一次寫入：`onCommit` 把 `setSceneExtras` 與
   `setDialogueCharacters` 串起來，中間那個 doc 不落地。分成兩次的話 ⌘Z 要按兩次，而編劇
   眼中那只是一個動作（票券 08 第十輪那個回饋的同一條理由）。

4. **拿掉一筆群演不回頭改對白。** 對白可能正指著它，拿掉之後那個引用懸空 —— 而懸空引用是
   合法的讀取狀態（§6.6）：顯示名照印、不跳警告、不少印一句台詞。反過來做（連帶清掉人物欄）
   等於系統在編劇背後動他寫好的對白。**重新編輯一筆群演則保住 `extraId`**（改人數不換 id），
   否則那句台詞的引用會在改人數的當下懸空。

5. **群演不進登場人物欄。** 票券 08 留了一個暫時措施「在對白人物欄新建的**人物**順手掛進
   登場人物欄」，群演**不套用**：那一欄的判準是入鏡的**人物**，而群演連人物都不是。
   （那個暫時措施本身仍待票券 10 換回提示選單。）

### 一條驗收的誠實話（同票券 08）

「進場次表第一層、不進 PDF」的兩個消費者是票券 15 與 18，今天都還不存在。本票交付的是
它們日後會用的那支 projection（`extrasLabel`／`formatExtra`：`咖啡廳客人 x8、服務生 x2`）與
讀取正規化 `sceneExtras`，都有測試。`extrasLabel` 與 `referenceLabel` 一樣**先不進 barrel**
—— 沒有讀者的公開介面是債，第一個呼叫端會是票券 15。

### 待人工驗收

1. 簡表最後一格打「咖啡廳客人 x8、服務生 x2」→ 兩個 chip；點 chip 可以改人數（id 不變）。
2. 對白人物欄打「眾人 x20」→ 選單兩列並排：`＋ 建立新實體` 與 `👥 新增群演「眾人」20 人`；
   挑後者 → 簡表的群演欄立刻多一筆，登場人物欄一個字都沒多，⌘Z 一次全回去。
3. 打「路人甲」→ 那是**人物**（一個人說話），不會變成群演。
4. 別場打過「咖啡廳客人」→ 這一場打「咖啡」時補得到那串字，但定案後兩場的 `extraId` 不同。
5. 注音組字期間：頓號不切 chip、Enter 不定案，浮出的預覽按不到。

**2026-09-10 — code review 之後改的五件事。** 兩軸各自跑了一遍（standards／spec）。

spec 軸抓到兩個真缺陷，都是「引用會在編劇背後斷掉」的同一家族：

1. **改對白上的群演 chip 會憑空建出一筆人物。** `resolve()` 只在「字沒改」時用回原 id，改了字
   就落回命中／新建那條路 —— 於是一個 `ex_` 引用悄悄變成一筆**人物**。而一人說話與一群齊聲說
   的分界是**編劇的宣告**，不該由改名這個動作替他翻面。修法：手上那一筆是群演時，改字改的是
   「這一場顯示的名字」（CONTEXT.md 早就寫著「群演欄寫『咖啡廳客人 x8』，對白顯示『眾人』」，
   這一條本來就該存在）。反證過：拿掉它，測試確實 fail。
2. **寫入被拒時待寫的群演會被清掉。** 那一筆沒進 doc、引用卻還在欄位裡，下一次寫入就會被
   不變式擋下，編劇的說話者靜靜消失。改成寫成功了才清。
3. **群演欄改到一半打成沒有描述的字（只剩 `x8`）會把那一筆吞掉。** 重新編輯是「把 chip 拿下來
   改」，中途打成解析不出來的字，該放回去而不是消失。

standards 軸的採納：

4. **「讀現況再併上」搬進 kernel**（`addSceneExtras`）。原本對白那一側自己走 doc 找場次、讀
   `extras`、併起來再寫 —— 那是把 doc 的 read-modify-write 放在畫面那一側，而畫面讀到的可能是
   上一次重繪的那一份（票券 08 那個時間差家族第四次出現）。
5. **記號常數移到中性的 `field-marks.ts`**：實體欄位與群演欄刻意不是同一個元件，讓其中一邊
   import 另一邊的常數會造出一條假的從屬關係。

另外依 standards 軸的建議，把上面「五個實作當下才定案的決定」裡屬於**領域層級**的四條寫回
`CONTEXT.md` 的「群演」詞條（人數沒有未填、拿掉群演不改對白、群演不進登場人物欄、顯示名可與
描述不同）—— 那是這個 repo 記錄裁決的地方，票券只是它的出處。

**兩處刻意超出票券原文**（spec 軸點名，保留並記錄理由）：
- `parseExtra` 認得 `x／X／×／＊／*` 與**全形數字**。注音鍵盤打出來的數字常是全形，把它當成
  另一種寫法會讓編劇打的字莫名其妙不生效。
- 群演欄也掛了一份 ⓘ 說明。理由同票券 08 那一輪：同一排裡有的有 icon、有的沒有，看起來像漏了；
  而「一人說話 vs 一群齊聲」正是這一欄最需要**事前**講清楚的一條判準。
