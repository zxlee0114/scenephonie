# 61 — 對白人物欄：在最前面按 ← 走不回上一個區塊

**What to build:** 對白人物欄的游標已經在最前面（第一顆 chip 前面、或空欄位），再按 ← **沒有反應**。
該有的行為：走出這一格，回到**上一個區塊的內文尾端** —— 同一顆鍵在內文裡跨區塊時的樣子。

開工前要確認的：

- ↑ 從人物欄出去是不是已經會回上一個區塊（`chip-nav.ts` 有 `exitUp`／`exitDown`，沒有向左的出口）；
  ← 要不要與 ↑ 同一個落點。
- 場次第一個區塊是對白時，← 的上一站是不是場次抬頭的 chip row（地點／登場人物欄）。
- 反方向：上一個區塊內文尾端按 → 會不會走進這一句的人物欄（對稱與否要問）。

**Status:** open

## 從哪來的

票券 10 瀏覽器驗收時使用者撈到的（2026-09-29），與 10 無關。

## 線索（未驗證）

`chip-caret.ts:83` 處理「在最前面按 ←」（`atStart`），`chip-nav.ts` 定義欄位的出口。對白人物欄
可能沒有接上向左／向上一個區塊的出口。

## 開工前定案（grilling 2026-10-27）

1. **← 與 ↑ 同一個落點。** 上一個區塊的文字末端；本場第一個區塊 → 本場 chip row 最後一格（群演欄）。
   （grilling 時說「全劇第一個區塊 → 鍵還給瀏覽器」是錯的：每個區塊都在某一場裡，第一個區塊上面一定有
   本場的 chip row，所以全劇第一句對白一樣進群演欄。實作時更正。）同 chip row 第一排 ←／↑ 共用出口的規則（`vertical-nav` 檔頭：
   水平兩顆是垂直那條路的另一種走法）。
2. **四種情況都算「在最前面」**：空欄位；輸入框排在第一顆 chip 前面且游標在字首；焦點在第一顆 chip 上
   （那道縫已經走過，`chip-caret` 的 `exit` 轉過來）；輸入框有沒定案的字、游標在字首 —— 照樣走出去，
   `blur` 把字定案成 chip。最後一條與 → 對稱（字尾按 → 不管有沒有字都進台詞）。
   ⚠️ 欄位裡已經有一位、打的是**第二個名字**時，那串字要先問過（齊聲確認），`blur` 照 entity-field 的
   規則不定案 —— ← 一樣走得出去，字留在框裡等回答。這不是這張票改的。
3. **反方向不在這張票。** 從上面走進對白（上一個區塊的 →／↓、chip row 的 ↓／→／Enter／Tab）一律落台詞、
   跳過人物欄 —— 不對稱但環沒斷（人物欄 ← → 上一段末端 → 台詞開頭 ← → 人物欄）。另開票 [89](./89-enter-dialogue-from-above-lands-on-speaker.md)。
4. **群組片段一起修。** 人物欄的 `focusPreviousBlockEnd`（`nodes/blocks.tsx`）不看 `fragmentIndex`：
   片段第一句一律請 `sceneChipsEnd` 給「這段所屬那一場」—— 第二段以後的片段應該回**上一段片段末端**，
   第一段應該去群組**最後一個成員**的 chip row（緊貼著的那一排）。台詞的 ↑（`vertical-nav` 的 `goUp`）
   已經這樣分；人物欄改成與它共用同一套判斷，不各寫一套。（讀程式碼推的，瀏覽器未驗。）

## 驗收

- [ ] 對白人物欄最前面按 ←（上面四種情況）→ 游標到上一個區塊的文字末端
- [ ] 場次第一個區塊是對白：人物欄 ← 進本場群演欄，與 ↑ 一致
- [ ] 全劇第一個區塊是對白：← 進本場群演欄（不是按了沒反應）
- [ ] 人物欄有打到一半的字、游標在字首按 ← → 字定案成 chip，游標到上一個區塊
- [ ] 群組第二段片段第一句是對白：人物欄 ←／↑ 回上一段片段末端
- [ ] 群組第一段片段第一句是對白：人物欄 ←／↑ 進最後一個成員的群演欄
