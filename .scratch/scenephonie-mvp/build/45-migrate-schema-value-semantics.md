# 45 — 遷移批次 1：群演的值語意改吃四種樣子，顯示改用括號

**What to build:** `packages/schema` 這一側全部搬到新形態 —— 打「路人」不再憑空生出一個
數字，印出來是 `路人（8）`／`路人（3-5）`／`路人（10+）`／`路人（若干）`，**不是乘號**。

顯示改用括號是編劇指定的（票券 41 第二輪）：`x` 只讀得懂整數，`路人 x3-5` 會被讀成兩個
數字相乘或一段壞掉的字。括號對四種樣子都成立。

⚠️ **顯示改了，輸入不能跟著收窄**：本子裡已經有 `路人 x3` 這種資料，編劇的手也記得 `x8`。
繼續認 `x`／`×`／`*`，只是不再印它。

**Blocked by:** 43（不解析裸數字那條線）、44（新形態與純函式縫）

**Status:** ready-for-agent

## 往返是硬約束

`parseExtra(formatExtra(e))` 必須等於 `e`。

⚠️ 票券 41 第八輪之後，**編輯路徑已經不再回填 `formatExtra` 的輸出**（框裡只有名稱），
所以這條往返不再是「回填」的理由。**但它仍然保留當不變式** —— 場次表、複製貼上、匯入
都靠它，而且它是「括號那個格式自己讀得回來」的唯一機器檢查。

描述**自己帶括號**時往返也要成立，因為只認**結尾那一段**：`路人（8）（若干）` 讀回來是
描述 `路人（8）` ＋ 人數若干。這條要有測試。

## 壞形狀補「若干」，不再補 1

`sceneExtras` 現在人數壞掉補 1。那條要跟著重讀：**補「若干」比補 1 誠實** —— 壞掉的人數
說的是「這裡不知道」，而 1 是一個系統自己宣告的數字，正是這張票要消滅的東西。

同一個函式裡順便留一條**容錯**（不是遷移）：裸數字讀成「確切 N」。它不拿 schema 版本、
不寫遷移鏈 —— `doc_schema_version` 是「PM node schema 的可讀性」版本，不是值語意的版本
（見票券 50）。複製貼上、匯入、測試 fixture 這些路徑繞得過寫入端，所以這條容錯留著。

## 解析是全有全無的

要嘛從結尾讀出一個**認得的**人數，要嘛把**整串**當描述。所以 `路人（三五個）` 得到的不是
「一筆人數壞掉的群演」，而是**描述叫「路人（三五個）」、人數若干**的一批。資料層的人數
永遠只有那四種樣子，一致性不靠使用者守規矩來維持。
