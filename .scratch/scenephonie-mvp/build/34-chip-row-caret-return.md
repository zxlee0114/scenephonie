# 34 — chip row 與內文之間的鍵盤往返（方向鍵）

**What to build:** 讓焦點在**內嵌簡表（chip row）**與**場次內文**之間用方向鍵雙向走通。
今天只有單向的一條路：Tab 從 metadata 一格一格串到內文，**進去就回不來**。

**Blocked by:** 04（`extensions/block-cycle.ts`、chip row 的 focus 串接都在該票交付）。
落點那一格是群演欄，由 09 交付 —— 排在 09 之後。

**Status:** open

## 症狀（使用者回饋 2026-09-10，票券 09 驗收期間順帶發現）

> 「如果在場次內容用方向鍵，沒辦法導回 metadata 欄位，感覺有點反直覺，如果直接跳進內容區塊，
> shift tab 也沒辦法直接回去，而是倒轉動作到插入畫面、對白一圈後才跳回去，且會在原地留下對白區塊。」

## 根因（已定位，不必再查）

兩件互相獨立的事湊在一起：

1. **方向鍵那條路根本不存在。** chip row 是 `contentEditable={false}`（`nodes/scene.tsx`），
   ProseMirror 的游標進不去，所以 ArrowUp 在場次第一個區塊沒有任何 handler 接 —— 不是壞掉，是沒做。

2. **Shift+Tab 被 `BlockCycle` 接走，那是反向轉型不是反向移動。**
   `extensions/block-cycle.ts` 把 `Shift-Tab` 綁到 `cycleBlock(editor, -1)`：動作 → 插入畫面 → 對白。
   轉到對白且該區塊是空的時候，`focusSpeaker` 把焦點丟進人物欄那顆 `<input>`；在那裡再按一次
   Shift+Tab 就是瀏覽器原生的反向 focus，於是「繞一圈才回到 metadata」。
   **代價是那個區塊已經被改成對白留在原地** —— 使用者要的是「回去」，付出的是內容被改。

第 2 點的每一步都是各自的設計意圖（§7.3 的環、票券 04 的 `focusSpeaker`），組合起來才成為壞經驗。

## 形狀（建議，開工前確認）

- **ArrowUp** 在場次**第一個區塊的第一行**、游標在行首以外也算 → 焦點進 chip row 的**最後一格**（群演欄）。
- **ArrowDown** 在 chip row 任一格的輸入框 → 回內文（進第一個區塊）。
  這一條順帶收掉使用者提的另一件事（見下面「已否決」）—— 它就是那條逃生鍵：
  不必 Tab 走完剩下的格子才進得了內文。
- **Tab 環一個字都不改。** §7.3：「環能當心流按鍵，靠的是按下去總能再按回來」；
  讓 Shift+Tab 在某個位置離開環，環就不對稱了。方向鍵是空間移動，沒有環的包袱，
  而且那正是使用者的第一直覺。

### 待決

- ArrowUp 的落點是「最後一格」（＝ Tab 順序的反向）還是「上次離開時那一格」？
  後者是「依看不見的狀態做不同的事」，傾向前者。
- chip row 的輸入框裡有自動補全選單開著時，ArrowUp／ArrowDown 是選單的（選項上下移動）——
  只有選單關著才是離開欄位。這一條沒有商量餘地，寫測試釘住。
- 場次**不是**第一場時，ArrowUp 走到場次開頭該進本場 chip row（不是上一場的內文）。

## 已否決：把登場人物／群演欄移出 Tab 循環

使用者的原始提案是「既然能靠內容新增這兩種實體，也許沒必要進 Tab 循環」。不做，三個理由：

1. **它們不是內容那條路的重複捷徑。** 登場人物的判準是**入鏡**不是台詞 —— 沒有一句話的角色只能
   從這一欄填；群演能從對白建的只有「一群齊聲說」那種，**不出聲的背景演員**（`咖啡廳客人 x8`）
   沒有第二個入口。
2. **鍵盤唯一的路就是那顆 input。** chip 的 `×` 與「點 chip 改人數」都是 `tabIndex={-1}` 的滑鼠路徑。
3. §9「metadata 預設可見，且缺漏不可被預設 UI 隱藏」的同一條理由 —— 移出鍵盤路徑是部分隱藏。

**真正的問題（Tab 走完 metadata 太長）由上面的 ArrowDown 解掉**，而不是讓某幾格退出循環。
「依已填未填決定要不要停」更不行：§7.3 已否決過「同一顆鍵依看不見的狀態做不同的事」。
