# 32 — 零場次時的空狀態（upkeep）

**Status:** verified

**What to build:** 當劇本一場都不剩時（⌘+A 全選到整份再刪除，或載入一份空稿），編輯器顯示一個
**可點的空狀態**：一句話 ＋ 一顆「＋ 新增下一場」，並提示 ⌘+Enter。不自動補一場。

**為什麼：** 空 doc 是合法的 —— schema 是 `scene*` 而非 `scene+`（`scene` 的 `sceneId` 無 default，
對 ProseMirror 而言非 generatable，放在必填位置會讓 schema 建構直接失敗；見 `schema.ts` 的
`content: "scene*"` 註解與 §5.1）。kernel 也**救得回來**：`createNextScene` 在空 doc 上
`afterSceneId` 為 null → `insertAt = 0`，實測成功。

壞掉的是畫面不是模型。零場次時 contenteditable 沒有內容、高度接近零：場次腳部的「＋ 新增下一場」
住在場次裡所以一起消失，沒有可點的區域，也沒有任何字說明還能做什麼。焦點還在編輯器裡時 ⌘+Enter
仍有效，但只要點掉焦點、或存檔後重整回來，就沒有東西可以點回去 —— 那才是死路。

## 決定：空狀態，不是「全清時自動重置」

考慮過的另一條路是「偵測到零場次就自動補一場空的」。否決，四個理由：

1. **⌘+Z 要留得住。** 自動補會讓「刪掉全部」變成兩步歷史，或把補回來的那一場混進 undo stack。
   空狀態什麼都不動，⌘+Z 一次把整份稿救回來。
2. **不對文件說謊。** 使用者按了刪除，稿子就是零場 —— 持久化、日後的場次表（票券 15）與匯出前
   防呆（票券 19）看到的都是零場，那是真的。悄悄長回一場的編輯器，是會讓人開始不信任它的編輯器。
3. **這條規則本來就是「初始化的責任」不是「修補的責任」。** `empty-screenplay.ts` 的註解已經
   寫定：「劇本至少有一場」是編輯器初始化／command 層的事。自動重置是把它改成一個持續監看、
   隨時修補文件的東西 —— 那是另一種契約，而且是在使用者背後執行的那種。
4. 空狀態同時涵蓋兩條入口（剛刪完、重整後載入空稿）；重置方案在「載入」那條要靠**開檔時改稿**
   才成立，更糟。

## 影響檔案

- `apps/web/src/editor/ScreenplayEditor.tsx` —— 零場次時在 `EditorContent` 旁（或之上）渲染空狀態；
  「劇本有幾場」要能跟著 doc 更新（`editor.state.doc.childCount`，訂閱 `update`）
- `apps/web/src/styles/editor.css` —— 空狀態的版面。**不畫框**（不變式 G）：靠位置與間距，
  文案用 `--font-ui`、`--text-faint`，比照 `.save-status` 的「不畫東西，只說話」
- `apps/web/src/editor/extensions/next-scene.ts` —— 不必改。空狀態的按鈕共用
  `requestNextScene(editor, null)`，三個入口的形狀不變，只是在沒有場次時換個地方站

**kernel（`packages/schema`）完全不動。**

## Comments

**開票（2026-09-04）** —— 票券 27 的本機驗收中由使用者發現：「全選所有場次然後刪除時，劇本就
完全不會有場次」。當場討論了「全清時重置狀態」與「呈現空狀態」兩案，選後者，理由見上。

**實作（2026-09-04）** —— `EmptyScreenplayState` 住在 `ScreenplayEditor.tsx`，零場次時渲染在
`EditorContent` 之後；場次數在 render 期直接讀 `doc.childCount` ＋ 訂閱 `update` 重繪（存成 state
的話首次 render 一定是 0，非空的稿子會閃一下空狀態）。按鈕共用 `requestNextScene(editor, null)`，
kernel 完全沒動。迴歸測試 `empty-document-state.test.tsx`（7 條）。

順帶修掉 `requestNextScene` 用 `??` 取 `afterSceneId` 的問題：呼叫端明確傳進來的 `null`（「接在
全劇最後一場之後」）會跟「沒傳」混為一談，又掉回靠 selection 推算 —— 正是該檔案自己警告的滑鼠
入口風險。改成只有 `undefined` 才推算。

**本機驗收回饋（2026-09-04，兩輪）**

1. **新場次的浮現動畫跑完後底色會固定，要等游標進到內文才消失。** 病灶不在動畫在選取範圍：空 doc
   沒有任何文字位置可站，selection 是 `AllSelection(0, 0)`；command bridge 整份 replace 之後它被
   map 成罩住新生的那一場，而整場選取的反白與浮現動畫共用 `--selection-bg`。修在 command bridge
   —— 新場次誕生時若選取範圍還不是收合的，就把游標放進該場第一個區塊（游標本來就收合的情形不動，
   三個入口的既有落點行為不變）。⌘+A 全選整份後按 ⌘+Enter 是同一個毛病，一併治好。迴歸測試已確認
   拿掉修正就會紅。
2. **文案與按鈕形狀。**「＋ 新增下一場」在零場次時語意不對 —— 一場都沒有，就沒有「下一場」。改成
   敘述現況＋出口，按鈕長在句子裡：「這份劇本現在是張白紙。／點擊 ［＋ 新增場次］ 或使用快捷鍵
   ⌘ + Enter 開始寫作」。按鈕給實線外框並在懸停／按下時各深一階 —— 腳部那顆靠 hover 浮現是因為
   它住在場次之間、只是順手的入口；空狀態這顆是唯一的出口，形狀要先講清楚它可按。動的只有顏色
   不是尺寸（腳部那顆用寬度收合造成過版面閃動，2026-09-03 第四輪）。快捷鍵與按鈕文字同色 ——
   兩條路在句子裡該讀起來一樣重。場次本體仍不畫框：不變式 G 約束的是文件的視覺結構，介面控制項
   不在射程內。

**待決的收束** —— 文案定為上述版本；⌘+Enter 提示常駐（空狀態下它是鍵盤使用者唯一看得見的線索）；
新場次建立後焦點落在內外景欄已由迴歸測試守住。**空狀態的版面（間距、置中與否、按鈕尺寸）日後可能
再調**，屬視覺調整、不影響上述行為。

**驗收通過（2026-09-04）** —— 使用者本機逐條走過，兩輪回饋均已修掉。

**驗收後追加（2026-09-04）** —— 合併前 CI 紅了一次，查出來是兩個真的 bug，不是測試不穩。

1. **焦點串接會被自己排的 `focus("end")` 打斷。** 載入零場次的稿時 `initialFocus: "documentEnd"`
   走到最後一行 `editor.commands.focus("end")`，而 tiptap 的 focus 命令是排進
   `requestAnimationFrame` 的 —— 那一幀若落在使用者按下「＋ 新增場次」之後，就把焦點從新場次的
   內外景欄搶回內文。機器越忙越容易中，CI 上必中、本機多半贏，所以在本機看不見。分野不是「該不該
   給焦點」而是「用哪一種 focus」：同步的 `view.focus()` 在 `onCreate` 當下就做完，沒有那個縫。
   測試補上「焦點留得住」的斷言 —— 原本只等焦點到位就過，守不住之後被搶走。

2. **零場次時打字會憑空長出一場。** 編輯器 schema 的 `sceneId` 為了滿足 Tiptap「每個 attr 都要有
   default」補了 `default: null`，於是 `scene` 在 view 這一側是**可生成的**：空 doc 上一有輸入，
   ProseMirror 就自己 `createAndFill` 出 `scene > action` 把字放進去 —— 繞過 command bridge
   （§6.3），chip 全空、沒有浮現動畫、沒有焦點串接，而且注音在組字中途被結構修復打斷，未確認的
   字就落地了。資料沒壞（`extensions/scene-ids.ts` 會立刻補鑄真的 sceneId），壞的是行為。

   IME 擋不掉：`compositionstart` 與 composition 的 `beforeinput` 依規範都不可取消，只要焦點在
   contenteditable 上就沒辦法。**決定：零場次時把 contenteditable 關掉**（`syncEditable`）——
   也比較誠實，那個狀態確實沒有任何可以寫字的位置。使用者選的是「打字沒反應，必須先建場」，而不是
   「打字就建一場並寫進去」（後者與『新場次的落點是內外景欄』這條既有約定衝突，且注音第一次仍會斷）。

   代價：`keydown` 在 prosemirror-view 裡是 edit-only handler，tiptap 的 `Tabindex` 擴充在不可
   編輯時又會拿掉 `tabindex` —— 編輯器的鍵盤路徑整條斷掉。所以零場次的鍵盤合約改由空狀態自己接：
   焦點落在「＋ 新增場次」（Enter／空白即建場），⌘+Enter 建場，⌘+Z／⌘+⇧+Z 還原。這不是把 keymap
   複製一份 —— 零場次時**只有**這兩件事做得到，這就是那個狀態的全部合約。還原成功後焦點交還編輯器。
