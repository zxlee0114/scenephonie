# 32 — 零場次時的空狀態（upkeep）

**What to build:** 當劇本一場都不剩時（⌘+A 全選到整份再刪除，或載入一份空稿），編輯器顯示一個
**可點的空狀態**：一句話 ＋ 一顆「＋ 新增下一場」，並提示 ⌘+Enter。不自動補一場。

**為什麼：** 空 doc 是合法的 —— schema 是 `scene*` 而非 `scene+`（`scene` 的 `sceneId` 無 default，
對 ProseMirror 而言非 generatable，放在必填位置會讓 schema 建構直接失敗；見 `schema.ts` 的
`content: "scene*"` 註解與 §5.1）。kernel 也**救得回來**：`createNextScene` 在空 doc 上
`afterSceneId` 為 null → `insertAt = 0`，實測成功。

壞掉的是畫面不是模型。零場次時 contenteditable 沒有內容、高度接近零：場次腳部的「＋ 新增下一場」
住在場次裡所以一起消失，沒有可點的區域，也沒有任何字說明還能做什麼。焦點還在編輯器裡時 ⌘+Enter
仍有效，但只要點掉焦點、或存檔後重整回來，就沒有東西可以點回去 —— 那才是死路。

## 決定：空狀態，不是「全清時自動重置」

考慮過的另一條路是「偵測到零場次就自動補一場空的」。否決，四個理由：

1. **⌘+Z 要留得住。** 自動補會讓「刪掉全部」變成兩步歷史，或把補回來的那一場混進 undo stack。
   空狀態什麼都不動，⌘+Z 一次把整份稿救回來。
2. **不對文件說謊。** 使用者按了刪除，稿子就是零場 —— 持久化、日後的場次表（票券 15）與匯出前
   防呆（票券 19）看到的都是零場，那是真的。悄悄長回一場的編輯器，是會讓人開始不信任它的編輯器。
3. **這條規則本來就是「初始化的責任」不是「修補的責任」。** `empty-screenplay.ts` 的註解已經
   寫定：「劇本至少有一場」是編輯器初始化／command 層的事。自動重置是把它改成一個持續監看、
   隨時修補文件的東西 —— 那是另一種契約，而且是在使用者背後執行的那種。
4. 空狀態同時涵蓋兩條入口（剛刪完、重整後載入空稿）；重置方案在「載入」那條要靠**開檔時改稿**
   才成立，更糟。

## 影響檔案

- `apps/web/src/editor/ScreenplayEditor.tsx` —— 零場次時在 `EditorContent` 旁（或之上）渲染空狀態；
  「劇本有幾場」要能跟著 doc 更新（`editor.state.doc.childCount`，訂閱 `update`）
- `apps/web/src/styles/editor.css` —— 空狀態的版面。**不畫框**（不變式 G）：靠位置與間距，
  文案用 `--font-ui`、`--text-faint`，比照 `.save-status` 的「不畫東西，只說話」
- `apps/web/src/editor/extensions/next-scene.ts` —— 不必改。空狀態的按鈕共用
  `requestNextScene(editor, null)`，三個入口的形狀不變，只是在沒有場次時換個地方站

**kernel（`packages/schema`）完全不動。**

## 待決

- 空狀態的文案。方向是敘述現況＋出口，不是驚嘆號（例：「這份劇本還沒有場次。」＋按鈕）。
- 新場次建立後焦點落在該場的內外景欄（§7.1 焦點串接）—— 從空狀態按下去也該如此，
  `focusNewSceneMeta` 已經處理，驗收時確認一下就好。
- 空狀態出現時，⌘+Enter 的提示要不要一直在？傾向要 —— 它是鍵盤使用者唯一看得見的線索。

## 驗收

- [ ] ⌘+A 按到整份劇本再刪除，畫面出現空狀態（一句話 ＋ 可點的「＋ 新增下一場」），不是空白畫面
- [ ] 從空狀態按下按鈕建出一場，焦點落在新場次的內外景欄（§7.1 焦點串接不回歸）
- [ ] 空狀態下 ⌘+Enter 一樣建得出場次
- [ ] 刪光之後 ⌘+Z **一次**就把整份稿救回來（沒有被自動補的場次卡在歷史裡）
- [ ] 存檔一份零場次的稿、重整回來，看到的仍是空狀態且救得回來（不是死路）
- [ ] 有場次時空狀態不出現（不佔版面、不影響既有捲動與焦點行為）
- [ ] `pnpm lint` / `typecheck` / `test` / `build` 全綠
