# 10 — 登場人物提示

**What to build:** 提示不是推導 —— 推導替編劇做決定，提示只指出落差、決定權在他手上。觸發條件：某人物在本場有**一般**發聲方式的對白，且不在本場的登場人物欄。標了 V.O./O.S. 的**絕不提示**（編劇已明確宣告那個人不入鏡）；反方向（在登場人物欄但沒台詞）也不提示。提示是一個**可忽略的選單**：`＋ 新增為登場人物` ／ `✕ 不新增 —— 他不入鏡`。**ESC 與「不新增」語意刻意分開**：ESC ＝「現在別煩我」，不記錄任何判斷、下次還會提示；「不新增」＝明確判斷，存進場次的 `dismissedCharacterIds`，這一場的這個人不再提示。「不再提醒」記的是 `sceneId`（標籤只負責讓人在彈窗裡看懂是哪一場）。系統不自動把有台詞的人加進登場人物欄。

## Comments

**2026-09-29 — 實作收票。**

### 開工前的兩個裁決（使用者）

1. **發聲方式的輸入入口另開票（59）。** `voiceStyle` attr 早就在 schema 裡，但沒有 UI 設得到
   V.O./O.S.。本票的判準照讀那個 attr（kernel 測試量得到「V.O./O.S. 不觸發」），瀏覽器裡要等
   59 落地才驗收得到那一半。在那之前每一句對白都是一般發聲。
2. **時機 ＝ 離開一句對白的那一刻，浮在那一句的人物欄底下。** 不在人物欄定案那一刻（選單會
   蓋在他正要寫的台詞旁邊），也不做常駐的幽靈 chip（就是當初被否決的「一直看著它」）。

### 實作當下定的

- **不搶焦點、沒有預選列、繼續打字不收。** 選單出現時游標已經在下一段；預選第一列的話一個
  順手的 Enter 就是被加進登場人物欄。寫得快的人第一個字就會收掉它的話，等於沒問，所以收起的
  只有 Esc、點到別處、做出選擇，或落差自己消失。
- **鍵盤不能選列**，只有 Esc。游標在內文裡，Enter 與方向鍵屬於內文。
- **「＋ 新增」接在隊尾，顯示名用台詞上那個名字。** 走新 command `addAppearingCharacter`
  （讀現況再接上留在 kernel，同 `addSceneExtras` 的理由）；「✕ 不新增」走 `dismissAppearingPrompt`。
  兩支都登記在 `COMMAND_CONTRACTS`。
- **按選單不搬游標**：bridge 多一個 `keepCaret`（整份 replace 會把座標 map 到 doc 一端；
  這兩支只改 attr，原座標放回去就對）。反證過：拿掉它，測試確實 fail。
- **群演、沒有 id 的過渡引用不問** —— 登場人物欄只收人物。
- **載入時不問**：plugin 只在游標**走進過**一句對白之後，才把「離開」當一回事。
- 票券 08 的暫時措施（新建人物自動掛登場人物欄）與 `EntityBirth` 型別一起拆掉。

### 待人工驗收

1. 一場裡 Tab 出一句對白、人物欄打「小明」（新建）、寫台詞、Enter 到下一段 → 人物欄底下浮出
   選單；chip row 的登場人物欄**沒有**被自動加上小明。
2. 選單開著時繼續打字 → 字照常落在下一段，選單還在。
3. `＋ 新增為登場人物` → 小明接在登場人物欄隊尾，選單收起，游標沒動。
4. 另一場同樣走一次，按 Esc → 收起；點回那句台詞再離開 → 又出現。
5. `✕ 不新增 —— 他不入鏡` → 收起；點回那句再離開 → 不再出現；⌘Z 一次 → 那個判斷撤掉。
6. 選單開著時自己去 chip row 把小明加進登場人物欄 → 選單自己收起。
