# 21 — 交件文件與分場大綱

**What to build:** `documents` 表：`id`、`project_id`（**必填**）、`screenplay_id`（**可為 null**）、`kind`、`body jsonb`、`doc_schema_version`、`doc_seq`。**不變式 F：`documents.kind` 固定其合法層級，不由使用者決定。** 每個 `kind` 有**自己的 node schema 與自己的遷移鏈**（那一列的 `doc_schema_version` 是該 kind 的版本，不是全域數字）。三種 kind（§6.2）：

- **`交件大綱`（專案層）** —— 可多份、各自命名、附**字數計數器**；字數上限**不寫死**（各案特例：GHSA 800–1200／TFC 無上限／高雄拍 500／編劇高雄 1500／公視每集 ≤300），產品只提供計數器、不執行規則。
- **`角色設定表`（專案層）** —— 有序的人物引用清單 `{ 人物 id, 順序 }`，`body` 是 PM doc（每個節點一筆人物引用，節點裡是那一位的介紹內文 —— 2026-10-26 驗收改判，原本放在人物的描述欄）。它是人物實體的**第三個引用來源**（回頭補表時自動補全命中既有實體，不冒出第二個小明）。「主要人物」不是旗標，就是有沒有被這份表收錄。⚠️ 選 PM doc 是**有效期條件的**：職責僅止於「有序人物引用清單 ＋ PDF 排版來源」；若演化成有篩選／分類／群組／搜尋的 entity browser，重評它是 document 還是 projection。
- **`分場大綱`（劇本層）** —— 自由文字、**不與場次關聯**（呼應它在業界本來就沒有硬性格式、屬私下溝通工具）。

**為什麼交件大綱與角色設定表掛專案而非劇本**：它們描述的創作單位是**整部作品**（[ADR-0009](../../../docs/adr/0009-documents-hang-on-the-creative-unit-they-describe.md)）；v1 沒有可觀測變化（1:1 下兩層等價），這條買的是影集那天接得上。**為什麼角色設定表選 PM doc 而非關聯表**：引用只有**一種住所**（「存在＝被引用」的判定不必同時掃 doc 又掃表），拖曳排序／⌘Z／command／projection 全部免費復用。

**專案 meta 欄位**（§4.2，匯出交件 PDF 的前置頁來源）：片名（開）、劇情大綱／可改名故事大綱（開）、人物介紹（開）、**編劇姓名（預設關 —— GHSA 與 TFC 都明文不得署名，唯一預設與直覺相反的欄位）**、分場大綱（關）。全部**可改名、可開關、可排序**，編劇可自訂欄位，但**自訂欄位只能裝文件層級的散文，不得裝場次層級的資料**。「劇本內文」不是欄位、不進這個清單 —— 它是那份 PDF 的主體，前置欄位可自由排序，**內文永遠押尾、永遠在**。否決「匯出時選投哪個獎」。

**四區段交件 PDF**（§9.7）：`標題頁 → 長版劇情大綱 → 人物介紹 → 劇本內文`，各自獨占一頁（短區段也要），**一趟 `page.pdf()`、不需要 pdf-lib 合併層**，頁碼跨區段連續，浮水印掛 `@page`；TFC 是同樣三件、順序一致，只少一個標題頁；**不放圖片、不留「插入自備圖片頁」的逃生口**。專案首頁 hub 補上「專案層文件／劇本層文件」兩區（導覽形狀本身在教 ADR-0009 的掛載規則）。
