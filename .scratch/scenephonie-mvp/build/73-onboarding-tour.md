# 73 — 引導：帶看一份範例專案

**What to build:** 帶著一份**範例專案**走完整個流程 —— 儀表板 → 建立流程 → 交件大綱 → 角色設定表 → 劇本撰寫。
範例內容已經寫好，使用者**只看，不用填**。首次註冊的人與訪客看同一套。

**Blocked by:** 71、21

**Status:** needs-triage

## 為什麼

劇本撰寫是最需要引導的地方。與其指著儀表板說明，不如帶人走過完整的流程；有範例就不用讓使用者真的填東西。

## 已定（使用者裁決，2026-10-23 grilling）

1. **誰會看到**：首次註冊的人，以及訪客。**不是**「一個專案都沒有的人」。
2. **什麼時候算用掉**：一直出現，直到他按「跳過」或走完（或建好第一個專案）為止。只是關掉分頁不算。
   - 要記錄的只有「這個人跳過或完成引導了沒」。
   - 儀表板上常駐一顆按鈕，任何人都能隨時重看。
3. **範例從哪來**：
   - 訪客：照舊，進來時建一份範例專案（票 07 的 `landingProject(opening)`），**先到儀表板**再開始引導 ——
     改變票 07 的落點（原本直接進範例專案）。
   - 首次註冊的人：**按下「開始引導」時**在他的儀表板上建一份標著「範例」的專案。按鈕本身是明確的動作，
     不違反 71 的「明確按下建立才建立」。看完可以留著、封存或刪除（72）。
   - 引導走的是**真頁面＋真資料**，不做唯讀展示模式（那會讓每一頁多一種「不能存、不是你的」狀態，還得繞過不變式 H）。
4. **既有使用者**視為已經看過。訪客轉成 Google 帳號時，引導狀態跟著帶過去。

## 開工前要定的事

- **「看過引導」記在哪**：ADR-0011 規定 domain 只讀 `users.id`；這個狀態是 UI 偏好，不是 domain 概念，
  放 `users` 的一欄（像 `is_demo` 那樣當 lifecycle metadata）還是另一張表？
- **訪客轉 Google 帳號**：票 07 之後兩個身分並存（訪客那一列七天後清掉），「帶過去」實際上是把一個旗標從訪客寫到新帳號。
- **導覽的形式**：疊在頁面上的步驟提示（coach marks），還是一頁一頁的說明？「只看不填」在劇本編輯器裡怎麼成立 ——
  範例專案是使用者自己的，編輯器本來就能打字。
- **範例內容**：訪客的開場稿（票 07）要不要擴充成帶交件大綱、角色設定表的完整範例。
