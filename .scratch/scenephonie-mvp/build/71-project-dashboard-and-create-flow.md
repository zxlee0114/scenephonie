# 71 — 專案儀表板與建立專案流程

**What to build:** 登入之後先看到**專案儀表板**，總覽自己所有的專案；按下「建立專案」打開一個三步的彈窗精靈
（名稱 → 文件 → 確認），走到最後按「建立專案」或「建立並開始寫劇本」時，才一次建好專案、劇本與兩份大綱。
中途離開不留任何東西在資料庫，只在這台瀏覽器留一份草稿，下次建立時問要不要接著做。
劇本從這張票起有自己的**劇本名稱**（見 CONTEXT.md）。

**Blocked by:** 無（06 已完成）

**Status:** verified

## 為什麼

使用者一直以來想像的流程就是這樣：登入 → 總覽專案 → 明確建立 → 備好文件 → 寫劇本。
票 06 實作時把 `/projects` 做成轉接口、第一次登入就自動開專案（開工決定第 3 條），理由是「v1 使用者只會有
一個專案在寫」。**那一條是實作時寫在 Comments 裡的判斷，不是使用者裁決過的**；看到 `/projects` 這個路徑，
使用者以為建立專案的地方只是還沒做。本票補上的是使用者原本的流程，不是推翻一個裁決。

## 已定（使用者裁決）

2026-10-23 grilling 定了第 1、2、5、6 條；2026-10-24 grilling 推翻原第 3、4 條（片名可留白、每步可略過、
第一畫面就有「直接開始寫」），改成下面第 3–9 條。

### 儀表板

1. **登入落點是儀表板**（`/projects`），不再自動開專案。一個專案都沒有的人看到空的儀表板，上面一顆「建立專案」。
   - `/`、`/login`（已登入）、Google 登入的 `callbackURL` 都照舊指向 `/projects`，只是它從轉接口變成畫面。
   - `landingProject()` 的「沒有就開一個」退場。訪客入口仍然要替訪客建範例專案（票 07），那條路不受影響，
     範例專案的內容也不動（不預先建兩份大綱）。
2. **建立專案不問類型。** v1 只有單一劇本（§4.2「v1 不提供類型選擇、不做 UI」照舊成立），`projects.type`
   照樣寫單一劇本。系列劇本做出來那天，類型這一步插回流程最前面。
3. **儀表板卡片**：主標題**專案名稱**；**劇本名稱**與專案名稱不同時才印在副標題；一行「最後編輯 X」。
   最近編輯的在前。「已封存」「已刪除」兩區的位置先留給 [72](./72-project-archive-and-delete.md)。
   - **暫定** —— 看到卡片實際呈現的樣子之後可能再調。
   - **最後編輯**＝查詢時算出：這個專案底下劇本與**未刪除**文件的 `updated_at` 最大值。`projects` 不另存一欄
     （沒有任何路會更新 `projects.updated_at`，另存一欄就得每條存檔路都往上寫，漏一條就悄悄錯）。
     改名不算編輯 —— 卡片回答的是「我最近在寫哪一部」。
4. **既有使用者不受影響**：已經有專案的人登入後看到儀表板，上面就是他原本那個專案。

### 建立精靈

5. **儀表板上的純彈窗，沒有網址。** 重新整理、上一頁都等同關閉；進度靠本機草稿接回（第 8 條），不靠網址。
   **點彈窗外面不關閉**（多步表單最常見的誤觸）；離開只有 ×、「取消建立」、Esc 三種明確動作。
6. **三步**：
   1. **名稱**（不可略過）：**專案名稱**、**劇本名稱**兩欄都必填（去頭尾空白後非空；沒填按「下一步」時在欄位下方
      提示，按鈕不鎖）。劇本名稱欄下一個「☐ 與專案名稱相同」，**預設不勾**（專案名稱常是「某某計畫」這種工作代號）。
      勾著時劇本名稱唯讀、跟著專案名稱走；取消勾選時保留當下的字、可以接著改。勾選狀態只活在精靈裡，
      建好之後兩個名稱各自獨立。
   2. **文件**：**故事大綱**、**分場大綱**兩個頁籤，在同一個畫面切換（沒有先後）。編輯器就是 `DocumentEditor`，
      存檔注入成「寫進本機草稿」；彈窗裡**不顯示伺服器存檔狀態**（「已儲存」在這裡是假話）。
      底部只有「上一步」「下一步」，**沒有「略過」** —— 空的就建空文件，有字就帶著字建。
      **角色設定表**的頁籤在票 21 第 ② 片完成時補進來（它的每一列是人物實體的引用，ADR-0005，不在這張票做）。
   3. **確認**：摘要（專案名稱、劇本名稱、兩份大綱的字數，0 字寫「尚未開始」），按鈕
      「上一步」「取消建立」「建立專案」（次要）「建立並開始寫劇本」（主要，最右邊）。
      「取消建立」與 × 是同一件事。
7. **建立是一個 server action、一個交易**：專案（專案名稱、單一劇本類型）→ 劇本（劇本名稱、一場空戲）→
   故事大綱 → 分場大綱（掛在劇本上，所以在劇本之後）。兩份大綱**一律建**，空的就是空文件。
   - 按下任一顆建立按鈕，**兩顆立刻 disabled**，按的那顆顯示「建立中…」。
   - 冪等是第二道防線：精靈在 client 鑄一個**建立 id** 隨 POST 送出，伺服器當唯一鍵；同一個 id 第二次進來，
     回傳第一次建好的那個專案。（另一個分頁還原同一份草稿再按一次，按鈕擋不住，唯一鍵擋得住。）
   - 失敗：交易整組回滾，彈窗停在第三步顯示錯誤，草稿還在，可以再按。
   - 成功：清掉草稿，導到 hub 或劇本編輯器。
   - 「第一次打開時才建立」那條路（票 21）保留給舊專案；新專案用不到它。

### 本機草稿

8. **草稿的一生**：
   - 存在這台瀏覽器的 localStorage，**一個使用者一格**（key 帶 `usr_` id）—— 同台電腦換帳號或訪客看不到別人的。
   - 四樣（兩個名稱、兩份文件）任何一樣有內容就隨打隨存；全空不存。也記住目前在哪一步、哪個頁籤。
   - 清除：建立成功時；還原提示選「重新開始」時。取消、關閉彈窗**不清**。
   - **還原提示**：按「建立專案」時若有草稿，彈窗開頭先問「上次沒完成的『〈專案名稱｜未命名〉』（X 分鐘前），
     要接著做嗎？」—— 「接著做」回到上次那一步那個頁籤；「重新開始」清掉草稿從第一步開始。
   - 登出時清不清：跟票 [69](./69-unsaved-draft-local-backup.md) 的隱私問題一起定，這張票不先下判斷。
9. **只有真的會丟東西時才問。**
   - 草稿**存得進去**：×、取消、Esc、上一頁、重新整理、關分頁一律不問 —— 什麼都沒丟。
   - 草稿**存不進去**（寫入丟例外：網站資料被禁用、配額滿）：彈窗底部一行「這台瀏覽器存不了草稿，關閉之後填的內容就會不見」；
     ×、取消、Esc 先確認「要捨棄目前填的內容嗎？」；並註冊 `beforeunload`。之後一旦寫入成功，這些全部撤掉。
   - 不存伺服器草稿：那等於資料庫裡有一個半成品專案，推翻第 7 條「按下去之前什麼都不寫」。

### 劇本名稱

10. **劇本名稱是劇本上的新值**，與專案名稱是兩個值（CONTEXT.md「劇本名稱」）。既有劇本遷移時回填成它所屬專案的名稱。
11. **哪裡印哪個**：

    | 位置 | 印 |
    |---|---|
    | hub 大標題 | 專案名稱（不變） |
    | hub「劇本」區那張卡片 | **劇本名稱**（原本印專案名稱） |
    | 交付 PDF 的檔名 | **劇本名稱**（原本印專案名稱）—— 讀現值，不凍進交付快照 |

    `projectTitle()`（註解「它也是劇本的名稱」）拆成各讀各欄的兩個函式。PDF 內文沒有封面、分享頁不印名稱，都不用改。
12. **hub 上 0 字的固定文件卡片寫「尚未開始」** —— 判準從「文件存不存在」改成「有沒有字」，新舊專案才一致
    （新專案的兩份大綱一開始就存在）。寫了又全刪掉的也回到「尚未開始」。

### 不在這張票

- 改專案名稱、改劇本名稱 → [75](./75-rename-project-and-screenplay.md)，緊接著做。這張票上線到 75 上線之間，打錯的名字改不回來。
- 角色設定表頁籤 → 票 21 第 ② 片。

## 驗收

**儀表板**
- [x] 登入（Google、已登入時打開 `/`、`/login`）落在 `/projects` 儀表板，不再自動建立專案。
- [x] 沒有專案的帳號看到空的儀表板與「建立專案」；既有帳號看到原本那個專案。
- [x] 卡片印專案名稱；劇本名稱不同時才印副標題；印最後編輯時間；最近編輯的在前。
- [x] 改了故事大綱（或分場大綱、自由文件）的專案浮到最前面；刪除的自由文件不算；改名不算。
- [x] 訪客入口照舊建範例專案，落在儀表板（範例專案在上面）；hub 頁首有「← 我的專案」回儀表板（驗收時改）。

**精靈**
- [x] 點彈窗外面不會關閉；×、「取消建立」、Esc 會關閉。
- [x] 第一步兩個名稱沒填（或只填空白）不能前進，欄位下方有提示。
- [x] 「與專案名稱相同」預設不勾；勾著時劇本名稱跟著專案名稱變；取消勾選保留當下的字。
- [x] 第二步兩個頁籤可切換、各自保留內容；格式選單、Markdown 捷徑、字數計數器與正式文件頁相同；看不到伺服器存檔狀態。
- [x] 第二步沒有「略過」。
- [x] 第三步摘要正確（0 字寫「尚未開始」）。
- [x] 「建立並開始寫劇本」進劇本編輯器，「建立專案」進 hub；兩者都建好專案、劇本、兩份大綱（空的就是空文件）。
- [x] 按下建立後兩顆按鈕立刻 disabled；同一個建立 id 重送只建一個專案（整合測試）。
- [x] 建立中途失敗：資料庫沒有留下任何一列，彈窗停在第三步顯示錯誤，草稿還在（整合測試覆蓋回滾）。

**草稿**
- [x] 填了東西後關閉／重新整理／關分頁，再按「建立專案」會問要不要接著做；接著做回到原本那一步那個頁籤、內容都在。
- [x] 「重新開始」清掉草稿；建立成功也清掉草稿。
- [x] 什麼都沒填就關閉，下次不問。
- [x] 另一個使用者在同一個瀏覽器登入，看不到前一個人的草稿。
- [x] localStorage 寫入失敗時（測試裡讓 `setItem` 丟例外）出現提示一行，×／取消／Esc 先確認，`beforeunload` 生效；寫入恢復後全部撤掉。

**劇本名稱**
- [x] 遷移後既有劇本的劇本名稱等於其專案名稱。
- [x] hub 大標題印專案名稱、劇本卡片印劇本名稱；PDF 檔名用劇本名稱。
- [x] hub 上 0 字的故事大綱／分場大綱卡片寫「尚未開始」。

**開票（2026-10-23）**：票 21 第 ① 片驗收前，使用者問「登入後第一個看到什麼」時發現流程跟預期不同。

**grilling（2026-10-24）**：使用者重畫了建立流程（名稱必填 → 文件頁籤 → 進入專案或劇本，中途取消整組取消、
草稿下次問要不要還原）。劇本因此長出自己的名稱，CONTEXT.md 新增「劇本名稱」「專案名稱」兩個詞條；
改名 UI 另開票 75。不寫 ADR：加一欄與本機草稿日後反悔都不貴。

**驗收通過（2026-10-25，PR #95）**：驗收時改了四處，都已併入：
- 第一步名稱沒填齊時「下一步」停用（`aria-disabled`，照按才在欄位內以 placeholder 提示），標籤加 `*`；不再在欄位下方另起一行錯誤訊息。
- 第二步 bubble menu 第一次反白跑到視窗左上角（Tiptap 一開始掛 `position: absolute`，Floating UI 用錯基準）—— 出現那一刻先改 fixed。
- 訪客入口改成落在儀表板；hub 頁首加「← 我的專案」。驗收清單那一條跟著改。
- 存不了草稿的提示一打開精靈就顯示（先試寫一次），文字改為使用者給的那句。
- 第三步按鈕改名為「建立專案」（次要）「建立並開始寫劇本」（主要）。
