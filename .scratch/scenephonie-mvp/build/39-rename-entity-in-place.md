# 39 — 把實體改名，要有一個正經入口

**What to build:** 改實體的名字今天**只有一條路**，而且藏在別名流程的第三層底下：
打一個目錄裡沒有的名字 → `🔗 作為既有實體的另一個名字…` → 挑出那筆實體 →
`同時把實體改名為「X」`（`entity-field.tsx` 的 `aliasMode`）。也就是說，編劇想改名，
得先**假裝自己在取別名**。這張票給它一個直說的入口。

**Status:** done

## 現況（能力已經接好了，缺的是入口）

改名的整條管線是通的：`onRenameEntity` → `catalog.rename` → `renameEntityAction` →
`entity-store` 的 `renameCharacter`／`renameLocation`。這張票**不碰那條線**，只加入口。

而「改別名」其實已經有路了：別名住在**引用**上（ADR-0005），所以改這一場的叫法＝
把 chip 拿回來改它的顯示名 —— 票券 38 之後這條路不再冒「建立新實體」，已經順了。

⚠️ 所以先釐清需求：這張票要補的是**改實體正式名稱**那一半。開票時編劇的原話是
「無論是正式名稱或者是別名」—— 如果別名那半有別的不順（例如想一次改掉某個實體在**所有**
場次的叫法），那是另一件事（見下面「不在範圍」的合併／代換那條）。

## 形狀

在**把 chip 拿回來改**的那份選單裡多一列 —— 條件是「手上那一筆命中，但框裡的字不等於它在
目錄裡的名字」：

```
📍 test1（1 場）                    ← 命中：指回同一筆實體，這一場顯示 `test`
✏️ 把實體改名為「test」（1 場）      ← 新的這一列
🔗 作為既有實體的另一個名字…
```

兩列的差別要讀得出來：上面那列是「這場顯示為 test，實體還是 test1」，下面那列是
「這筆實體從此叫 test」。

⚠️ **改名不代換全文** —— 這是既有決策（`entity-field.tsx` 的 `alias-rename` 註解）：
別場的顯示名是**那一場的別名**，不該被順手改掉。但改名之後編劇會看到別場仍印舊字，
所以那一列得把場數寫在按下去之前（`（1 場）`），比照升格那列的做法（ADR-0006）。

**待裁決：**（已裁決，見下面的 Comments）兩種都能說出道理 —— 所以**不在票裡裁死，交給按下去
的當下**：別場還印著舊名時才問，問完才動。

## ⚠️ 硬約束

- **改名是專案層級的動作。** 實體屬於專案，不屬於劇本 —— 改完之後**別的劇本也會看到**。
- **⌘Z 回不來。** 改名走 server action，不進 ProseMirror 的 history。這與票券 37
  （undo 回到打過的字）是同一個接縫，做之前先看那張票落地成什麼樣。
- **孤兒改不了名。** 改名列只在手上那一筆或目錄命中時出現，不放寬 `existing()`
  （ADR-0005，票券 38 那條界線）。

## 不在範圍

- **合併兩筆實體**（把指向 A 的引用全部改指向 B，A 變孤兒自動消失 —— ADR-0005 講過形狀）。
- **代換全文**：改名連帶改掉所有場次的顯示名。上面「待裁決」那段先有答案才談。
- 從場次簡表以外的地方改名（人物總表之類的面板，v1 還沒有那個畫面）。

## 驗收

- [x] 把 chip 拿回來改、輸入一個與實體名不同的字 → 選單出現 `✏️ 把實體改名為「X」（N 場）`。
- [x] 按下去 → 目錄裡那筆的名字變成 X；**這一場**的顯示名也變成 X。
- [x] 別的場次引用同一筆實體時，顯示名**不動** —— 除非編劇在第二步選了「連那 N 場一起改」。
- [x] 框裡的字等於實體名（沒改）時，那一列**不出現** —— 沒有東西要改。
- [x] 孤兒不出現改名列。
- [x] 地點欄、登場人物欄、對白人物欄走同一段程式碼。
- [x] 別名那條舊路（`🔗` → 挑實體 → `同時把實體改名為…`）行為不變 —— 留著的理由見下。

## Comments

### 2026-09-11 — 開票

票券 38 的人工驗收期間編劇問的：「有辦法做出將實體一鍵改名的功能嗎？無論是正式名稱
或者是別名」。同一輪驗收還抓到一條重覆列的 bug，那條已在票券 38 內修掉。

### 2026-09-11 — 收票

**裁決（編劇）：代換全文不在票裡裁死，交給按下去的當下。** 「顯示名剛好等於實體名」是還沒
取名、不是別名，所以它**可以**跟著改 —— 但那是編劇的話，不是系統的預設值。於是改名那一列
按下去之後，若還有別場印著舊名就展開第二步：

```
✏️ 把實體改名為「海豚公寓客廳」（3 場）      ← 第一步
   只改這一場的叫法 —— 另外 1 場繼續印「海豚公寓房間」
   連那 1 場一起改成「海豚公寓客廳」
```

沒有別場印舊名就一步改完 —— 沒得問就不問。真正取過名的引用（顯示名 ≠ 實體名）**永遠不動**。

**開票時的形狀改了一處：改名列排在 `＋ 建立新實體` 後面，不是命中列後面。** 第一列是 Enter
會做的事，而改名是專案層級、⌘Z 回不來的動作 —— 它該是按出來的，不該是打完字順手 Enter 就
發生的。命中列與改名列並列的樣子仍在（拿回來的是別名、字沒動時）。

**條件也不是開票時寫的「手上那一筆命中」。** 打了新字之後手上那一筆就不再算命中（票券 38 的
`editingMatch` 刻意如此），而那正好是要改名的時候。實際條件是**手上握著一筆實體、且框裡的字
不是它在目錄裡的名字**；孤兒仍然進不來（它沒有被握在手上）。

**舊入口留著。** 新的 ✏️ 只認手上那一筆，做不到「打一個新名字 → 指向另一筆既有實體 → 順手把
那筆改名」；舊的 🔗 路做得到。兩者不重疊，所以不收。

### 2026-09-11 — code review 之後改掉的四件事

1. **第一列的數字換算法。** 原本印「這筆實體用在 N 場」，聽起來像會動到那麼多場 —— 但改名
   預設一場都不代換。改成印**代價**：`✏️ 把實體改名為「X」（還有 N 場印著「舊名」）`，
   與第二步同一個數字（`scenesShowingName`）。一場都沒有時連括號都不印。
2. **「那 N 場」包含編劇正站著的這一場。** 他改的是**這一欄那一筆**，同一場的別欄（登場
   人物欄與對白人物欄常是同一個人）仍印著舊名 —— 那一場確實還印著舊名。所以措辭是
   「還有 N 場印著…」而不是「別的 N 場」，第二步第一列也改稱「只改**這一筆**的叫法」。
3. **寫不進 doc 時整個改名都不做。** 原本先改目錄、再寫 doc，command 被拒絕就只 warn ——
   留下「目錄改了、稿沒改」而且 ⌘Z 回不來的半套。順序反過來：doc 先，拒絕就整個不動。
4. **打的字剛好是另一筆存在實體的名字時，改名列不出現。** 那會讓目錄有兩筆同名；編劇要的
   多半是「這一場指的是那一筆」（`📍` 那一列），或把兩筆併起來 —— 合併不在這張票裡。
   同一條線本來就擋掉了 `＋ 建立新實體`，理由一樣。

另外把三個欄位的接線抽成 `editor/retitle-others.ts`（原本 scene.tsx 與 blocks.tsx 各抄一份）。

### ⚠️ 留給票券 37 的：⌘Z 只退得回一半

改名橫跨兩個權威：目錄走 server action（不進 history）、那幾場的顯示名走 kernel command
（進 history）。所以選了「連那 N 場一起改」之後按 ⌘Z，**那幾場的字退回舊名、目錄仍是新名**
—— 它們於是變成別名。開票時寫的是「⌘Z 回不來」，現在更精確：**回一半**。
沒有在這張票裡處理（票券 37 是那個接縫），但程式碼註解與這裡都記下了。

### 2026-09-11 — 收票回饋：三件關於「回饋感」的事

人工驗收之後編劇提了三條，都不在原票的七條驗收裡 —— 它們問的不是「改名做不做得到」，
而是**編劇看不看得出來自己在做什麼**。

1. **命中列的場次數少算一場（bug，不是措辭）。** `entityUsage` 走 doc，而把 chip 拿回來的
   第一步就是把引用從 doc 上撤掉 —— 於是 `📍 派出所（3 場）` 在編輯的那一刻變成 `（2 場）`。
   那筆實體並沒有變小，編劇也還沒決定要不要留下它。判準與 ADR-0005 那條邊界同一條：
   **手上那一筆不是孤兒**。改法是在 `editRef` 呼叫 `onCommit` **之前**先問一次場次數並記住
   （`heldScenes`）；同一場的別欄也引用它時不會多算一場，因為快照本來就是場次單位。
2. **字全刪光時完全沒有回饋。** `menuOpen` 的條件是框裡有字，刪到空的那一刻選單整個收掉 ——
   畫面上沒有任何東西說「你手上還握著『派出所』」，看起來跟從沒填過一模一樣。但後果完全不同：
   **空著離開就是把這一場的它拿掉**。
3. **編輯 chip 時看不到改名這條路。** 字還等於實體名時沒有任何一列提到改名（確實沒東西可改），
   於是編劇不會去試一個他不知道存在的東西。

②③ 是**同一行字的兩種狀態** —— 選單頂端一行唯讀抬頭（`heldNote`）：

```
✏️ 手上是「派出所」—— 打字可改名，空著離開就是拿掉它     ← 框裡是空的
✏️ 改這裡的字，就能把這筆實體改名                        ← 字還沒改
（沒有抬頭）                                             ← 字改了：真正可按的 ✏️ 已經在選單裡
```

它**不進 `rows`**：選不到、Enter 碰不到、`aria` 上是 `presentation`。標籤放結果、說明另外放
—— 這條分工是票券 36 立的，等 36 的側邊說明欄落地，這一行可以搬進去。

**沒有做的兩件事，以及為什麼：**

- **括號裡不塞第二個數字。** 一度想把改名列寫成「這筆用在 3 場，其中 2 場印著舊名」，編劇
  否決：別名多的時候一列括號會扛太多資訊。改名列維持一個數字（代價，`scenesShowingName`），
  命中列維持一個數字（這筆實體多大，`entityUsage`）—— 兩列各回答一個問題。
- **不提前做票券 36 的側邊說明欄。** 那是一整個跟著 active row 走的 detail pane；這裡要的
  只是一行固定的抬頭，形狀不同。
- 順帶澄清一條**不是 bug 的行為**：拿起一個**別名** chip、字沒動時 `✏️ 把實體改名為「分局」`
  照樣出現。那不違反「改字才能改名」—— 那個字本來就不是實體名，確實有東西可改。

**落地：** `entity-field.tsx`（`heldScenes` 快照、`scenesOf`、`heldNote`）、`styles/editor.css`
一條樣式、測試 6 條（`entity-field.test.tsx` 的「手上握著一筆實體時的回饋」）。既有兩條測試的
期望值從 `2 場` 改成 `3 場` —— 那本來就是實機會看到的數字，是測試 Host 的 `usage` 假成常數才
沒抓到；Host 的 `usage` 現在收得到欄位上還剩哪些引用。
