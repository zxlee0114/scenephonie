# 48 — 遷移批次 4：改人數走一層子選單，預設值寫在看得見的地方

**What to build:** 編輯狀態的選單多一列 `修改數量…`，按下去進到**人數子選單**：
第一列是 `↰ 不修改數量（8），回上一步`，接著 `若干`、`1`、一個自由輸入格，格子底下一行
唯讀提示。挑完人數**退回描述那一關**，名稱還能接著改。

**Blocked by:** 47、37（⌘Z 把編劇打的字還回輸入框）

**Status:** ready-for-agent

## 版面

```
修改（原本是 8）
┌──────────────────────────────────┐
│ ↰ 不修改數量（8），回上一步        │
├──────────────────────────────────┤
│ 若干                             │
│ 1                                │
├──────────────────────────────────┤
│ ▌                                │
│ { 提示 ／ 預覽 ／ 警告 }          │
├──────────────────────────────────┤
│ ↩︎ 不修改，返回                   │
└──────────────────────────────────┘
```

原本提的 `10+／20+／30+／40+` 階梯**拿掉**（編劇：「好像可有可無」）—— 它是猜的，而自由
輸入格加即時預覽比猜四個數字誠實。`1` 那一列只在與第一列不重複時才印（原本就是 1 的話
不必印兩次）。

## `↰` 與 `↩︎` 是**兩列**，不合併

使用者裁決 2026-09-12：**不要因為兩者在這一層結果相同就合併成同一個動作，它們代表的是
導航語意。**

- `↰ 不修改數量（8），回上一步` —— 退回描述那一關，名稱那一側的待定改動**留著**。
  它本身不是兩件事的合體，它是一列 `↰`，只是順便說出它不動的那個值。
- `↩︎ 不修改，返回` —— **整輪編輯作廢**，待定人數與名稱改動一起丟，手上那一筆原封放回。

（票券 41 第八輪原文寫成「一列兼兩職」，那句話**已被推翻**，不要照字面只做一列。
票券 42 第 2 條「選單走到哪一階段它都要在」在這裡同樣適用，所以 `↩︎` 在子選單裡也在。）

## `8（原訂）` 那條裁決搬到了第一列

第七輪提的 `8（原訂）` 解決的是同一個坑：第二關的預設若是「若干」，修改時它會**偷偷抹掉
原本的 8**。把預設值**從行為裡搬到畫面上**，那個坑就不存在了。第八輪之後它的位置在
`不修改數量（8），回上一步` 這一列 —— 措辭用「原訂」是編劇原話，但這一列已經不需要那兩個字。

再進子選單時第一列跟的是**待定值**（挑過 2 之後是 `不修改數量（2），回上一步`），因為那是
「現在的樣子」。

## 那一行提示永遠有話說

它回答的始終是同一個問題 —— **「我現在按下去會得到什麼」**（票券 40 給第一列立的規矩）。
所以它**不會因為讀不出來就消失**，只是換一副語氣：

| 框裡 | 那一行印 |
|---|---|
| 空 | `人數（8）、區間（3~5、3-5、10+）` ← 格式說明 |
| `3~5` | `路人（3-5）` ← 預覽 |
| `3~` | `⚠️ 「3~」還讀不出來 —— 現在離開會記成「路人（8）」` ← 警告 |

文案在票券 44 的 `countHintText` 裡，這一批只負責把它接上並證明它跟著框裡的字變。
⚠️ 它與票券 36 那條「標籤放結果、說明另外放」的分工要對一次 —— 兩者都不是選項列，
應該沒有衝突，實作前確認並把結論寫進註解。

## 待定人數是編輯狀態的一部分

挑了 2、回到主狀態時，那一批**還沒變** —— 變的是「按下去會得到什麼」。於是票券 40 第一列
自己就說對了：只改人數、沒碰名稱時它印 `✏️ 把「路人（8）」改成「路人（2）」`（`after` 用
待定值算）。**不必為這條路另外寫措辭。**

抬頭印的仍是**原值**（`✏️ 正在編輯「路人（8）」…`）—— 它說的是「我在編輯誰」，不是
「我打算改成什麼」，那是第一列的事（票券 36 的分工）。

## 讀不出來時離開 ＝ 第一列的值

空著 Enter、打到一半 Enter、點到外面 —— **都是第一列的值**。修改時那就是原值（或待定值），
不是「若干」。

⚠️ 這一條是票券 41 第一版寫成「若干」、後來被第七輪推翻的地方（使用者裁決 2026-09-12
再確認一次）：**寫成「若干」會讓實作在修改路徑上抹掉原值**，那正是前面好幾輪在補的坑。
新增路徑上第一列本來就是「若干」，所以那邊的結果不變（票券 49）。

Enter 與點到外面必須同一個結果，因為 `blur` 擋不住 —— 點到外面就是走了。若 Enter 擋住、
blur 不擋，同一個念頭就有兩種結果，而且其中一種看不見。

## 為什麼 blocked by 37

驗收裡那條「⌘Z 把打到一半的字還回來」**不是這張票要發明的行為** —— 票券 37 講的就是同一件事
（那串字從來不在 doc 裡，⌘Z 退得回 doc 卻退不回輸入框），只是它發生在實體欄位。

37 沒先修的話，這裡只有兩條路：要嘛在群演欄自己寫一套 undo 還字的機制（於是同一個 bug 有
兩種修法，而且其中一種只蓋得到人數格），要嘛把那條驗收放掉（於是打到一半的字真的會蒸發，
正是票券 41 第三輪說「真正要保住的只有一件事」的那一件）。所以 37 先做，這裡**沿用**它。
