# 41 — 群演人數常常只是大概，不該逼編劇給一個數字

**What to build:** 群演欄現在每一筆都印得出一個人數（`路人 x1`），因為 `parseExtra` 把
「只打描述」讀成**一位**（票券 09 的實作定案第 1 條：「人數沒有『未填』這個狀態」）。

編劇的反例（2026-09-11）：**劇本寫的人數常常只是大概，真正請幾個人是劇組看預算與場地決定
的。** 打「路人」而畫面回「路人 x1」，等於系統替編劇宣告了一個他沒說的數字 —— 而且宣告的
還是最不可能的那個（路人很少只有一個）。副導讀到 `x1` 會當成規格，不會當成「編劇沒說」。

**Blocked by:** 40

**Status:** open

## 這條裁決當初為什麼是那樣

票券 09 的理由是「`count` 不允許 null，而『一位』是這串字最誠實的讀法，比逼編劇每次都打
`x1` 好」。前半是資料層的自我設限，後半在「服務生」這種**確實是一位**的例子上成立 ——
但它推不到「路人」。真正該分開的是兩件事：

- **編劇打了數字**（`路人 x8`）—— 那是規格，照印。
- **編劇沒打數字**（`路人`）—— 那是「一群，幾個你們看著辦」，不是 1。

## 編劇裁決（2026-09-11）：群演欄分兩階段

```
第一階段  輸入群演名                第二階段  說人數
┌─────────────────────┐          ┌─────────────────────────────┐
│ 路人▌               │          │ 路人                        │
├─────────────────────┤          ├─────────────────────────────┤
│ ＋ 新增群演「路人」  │   →      │ 若干                        │
│ 👥 路人（別場用過）  │          │ 1                           │
└─────────────────────┘          ├─────────────────────────────┤
                                 │ ▌                           │
                                 │ 人數（8）、區間（3~5、3-5、  │
                                 │ 10+）            ← 唯讀提示  │
                                 └─────────────────────────────┘
```

**「若干」是編劇自己寫劇本時常用的寫法**（「一些人」「數人」同義），所以它不是「未填」的
委婉說法，而是**一個編劇真的會選的答案**。這一點決定了資料層的形狀：人數不是
「`number` 或 null」，是一個**有好幾種樣子的值**。

四種樣子：

| 樣子 | 編劇打的／選的 | 印出來 |
|---|---|---|
| 確切 | `8` | `路人（8）` |
| 區間 | `3-5`、`3~5` | `路人（3-5）` |
| 下限 | `10+` | `路人（10+）` |
| 若干 | 「若干」那一列 | `路人（若干）` |

**顯示改用括號，不用乘號**（編劇指定）：`x` 只讀得懂整數，`路人 x3-5` 會被讀成兩個數字
相乘或一段壞掉的字。括號對這四種樣子都成立，而且與場次表 `實體名（這一場的顯示名）` 那條
慣例同形 —— ⚠️ 兩者會在同一張表上出現，實作前確認不會讀成同一件事。

⚠️ **顯示改了，輸入不能跟著收窄**：本子裡已經有 `路人 x3` 這種資料，編劇手也記得 `x8`。
`parseExtra` 要繼續認 `x`／`×`／`*`，只是 `formatExtra` 不再印它。而且 `formatExtra` 的
輸出**會被回填進輸入框**（`editExtra` 拿它當可編輯文字），所以括號那個格式必須自己讀得回來
—— `parseExtra(formatExtra(e))` 等於 `e`，這條往返是這張票的硬約束。

## 第二階段的版面（編劇 2026-09-11 第二輪）

上面那張圖就是裁決後的樣子：**「若干」在最上面**，接著 `1`（「1 應該也是蠻常見的數字」），
分隔線之下是一個**自由輸入格**，格子底下一行**唯讀提示**說明打得出什麼。
原本提的 `10+／20+／30+／40+` 階梯**拿掉**（編劇：「好像可有可無」）—— 它是猜的，而自由
輸入格加即時預覽比猜四個數字誠實。

**那行唯讀提示一行兩用**：沒打字時是格式說明（`人數（8）、區間（3~5、3-5、10+）`），
打了字就換成**預覽**（打 `3~5` → `路人（3-5）`）。編劇原話是「如果不要預填，我覺得可以在
更下面呈現預覽」；同一行兩用是為了不多佔版面，⚠️ 但它與票券 36 那條「標籤放結果、說明另外
放」的分工要對一次 —— 兩者都不是選項列，應該沒有衝突，實作前確認。

**放寬解析**（編劇提）：

- 全形數字 `８` —— **已經有了**（`extras.ts` 的 `halfWidthDigits`）
- 全形符號 `＋`／`～`／`－`／`—`／`〜` —— 要補，注音鍵盤打出來的就是這些
- 中文數字（`三`、`十`、`廿`、`數十`）—— 建議**先不做**，列為未決：`十` 與 `十幾`、
  `二三十` 的邊界是另一個問題，而「數十」其實是「若干」那一格想講的事

## 第二階段的輸入格讀不出來時（編劇提問，2026-09-11 第三輪）

**裁決：空著直接 Enter ＝「若干」**（它就排在第一列）。剩下的問題是**打到一半**：
框裡是 `3~`、`一些`、`abc` 這種還讀不出來的字，這時 Enter 或**點到外面去**，畫面上該
出現什麼。

### 原則：那行預覽永遠有話說

它回答的始終是同一個問題 —— **「我現在按下去會得到什麼」**（票券 40 給第一列立的規矩，
這裡照搬）。所以它**不會因為讀不出來就消失**；讀不出來的時候，它就是那句提醒：

| 框裡 | 那一行印 |
|---|---|
| 空 | `人數（8）、區間（3~5、3-5、10+）` ← 格式說明 |
| `3~5` | `路人（3-5）` ← 預覽 |
| `3~` | `⚠️ 「3~」還讀不出來 —— 現在離開會記成「路人（若干）」` |

編劇問的「預覽不出來嗎？或是直接在預覽強調提示」——**後者**：同一行，換一副語氣。
預覽一旦會消失，它就變成一個「有時候在、有時候不在」的東西，那比沒有更難讀。

### 原則：Enter 與「點到外面」是同一個結果

**都定案成「若干」**，因為 `blur` 擋不住 —— 點到外面就是走了，沒有辦法把人留在框裡。
若 Enter 擋住、blur 不擋，同一個念頭就有兩種結果，而且其中一種看不見（§「同一個手勢不該
有兩種看不見的結果」，使用者裁決 2026-09-11，見 `editExtra`）。

所以**不採用**「讀不出來就不給定案、游標留在框裡閃一下」那條路。

### 為什麼這樣不會出事

第二階段不是「這一批存不存在」的關卡 —— **描述在第一階段就已經定案**，這裡只是補人數。
所以最壞的情況是拿到 `路人（若干）`，而那是一顆點得回去改的 chip，不是資料掉了。
真正要保住的只有一件事：**打到一半那串字別憑空蒸發**。

- ⌘Z 要把它還回來（票券 37 立的前例：undo 還回編劇打的字）
- 再點那顆 chip 回來改時，框裡是 `路人（若干）` —— 人數那一格是空的，不是 `若干` 兩個字
  卡在裡面擋著（⚠️ 這條與上面的 `parseExtra(formatExtra(e)) === e` 要一起想）

### 連帶：第二階段的 Esc 與「回上一步」

Esc／`↰ 回上一步`（票券 42）在第二階段 ＝ **回第一階段**，描述回到框裡可以改，
人數不定案。這是唯一一條「什麼都不記」的路 —— 它與上面那條「離開就記成若干」不衝突，
因為它是編劇**明講**的取消。

## 還沒決定的事

1. **第二階段可以跳過嗎？** 在人數選單上直接按 Enter（或離開欄位）時算什麼？
   建議：**「若干」**—— 它排在第一列，而且那是「他沒說」最誠實的讀法。這代表「若干」會變成
   最常見的值，副導看到的第一眼要能接受。
2. **第一階段一次打完的路還留著嗎？** `路人 x8`、`路人（3-5）`、`路人 10+` 直接 Enter 就
   跳過第二階段。建議留著 —— 打字快的編劇不該被選單擋。
3. **排序與加總。** 場次表要不要能依人數排？「若干」與「10+」怎麼參與？
   建議：每種樣子都算得出一個**下限**（若干 ＝ 沒有下限），排序用它，加總一律不做。
4. **中文數字要不要認**（見上）。
