# 41 — 群演人數常常只是大概，不該逼編劇給一個數字

**What to build:** 群演欄現在每一筆都印得出一個人數（`路人 x1`），因為 `parseExtra` 把
「只打描述」讀成**一位**（票券 09 的實作定案第 1 條：「人數沒有『未填』這個狀態」）。

編劇的反例（2026-09-11）：**劇本寫的人數常常只是大概，真正請幾個人是劇組看預算與場地決定
的。** 打「路人」而畫面回「路人 x1」，等於系統替編劇宣告了一個他沒說的數字 —— 而且宣告的
還是最不可能的那個（路人很少只有一個）。副導讀到 `x1` 會當成規格，不會當成「編劇沒說」。

**Blocked by:** 40

**Status:** open

## 這條裁決當初為什麼是那樣

票券 09 的理由是「`count` 不允許 null，而『一位』是這串字最誠實的讀法，比逼編劇每次都打
`x1` 好」。前半是資料層的自我設限，後半在「服務生」這種**確實是一位**的例子上成立 ——
但它推不到「路人」。真正該分開的是兩件事：

- **編劇打了數字**（`路人 x8`）—— 那是規格，照印。
- **編劇沒打數字**（`路人`）—— 那是「一群，幾個你們看著辦」，不是 1。

## 編劇裁決（2026-09-11）：群演欄分兩階段

```
第一階段  輸入群演名                第二階段  選人數
┌─────────────────────┐          ┌─────────────────────────────┐
│ 路人▌               │          │ 路人 ▌                      │
├─────────────────────┤          ├─────────────────────────────┤
│ ＋ 新增群演「路人」  │   →      │ 自訂人數／區間…（8、3-5、10+）│
│ 👥 路人（別場用過）  │          │ 若干                        │
└─────────────────────┘          │ 10+                         │
                                 │ 20+                         │
                                 │ 30+                         │
                                 │ 40+ …                       │
                                 └─────────────────────────────┘
```

**「若干」是編劇自己寫劇本時常用的寫法**（「一些人」「數人」同義），所以它不是「未填」的
委婉說法，而是**一個編劇真的會選的答案**。這一點決定了資料層的形狀：人數不是
「`number` 或 null」，是一個**有好幾種樣子的值**。

四種樣子：

| 樣子 | 編劇打的／選的 | 印出來 |
|---|---|---|
| 確切 | `8`、`路人 x8` | `路人 x8` |
| 區間 | `3-5`、`3~5` | `路人 x3-5` |
| 下限 | `10+`、`路人 x10+` | `路人 x10+` |
| 若干 | 「若干」那一列 | `路人 若干`（**不加 `x`** —— 它不是數字） |

## 要決定的事（動手前先問編劇）

1. **第二階段可以跳過嗎？** 在人數選單上直接按 Enter（或離開欄位）時算什麼？
   建議：**「若干」**—— 那是「他沒說」最誠實的讀法，也正是這張票要解的問題。
   但這代表「若干」會變成最常見的值，副導看到的第一眼要能接受。
2. **`服務生` 這種真的一位的怎麼寫？** 第二階段選「自訂人數 → 1」，還是人數選單上也給一列
   `1 人`？（若干 → 1 是最常被改的兩格之一，值得給捷徑。）
3. **`10+ / 20+ / 30+ / 40+` 的階梯到哪裡停？** 固定四列，還是隨場次規模長？
4. **第一階段一次打完的路還留著嗎？** `路人 x8`、`路人 x3-5`、`路人 x10+`、`路人 若干`
   直接 Enter 就跳過第二階段。建議留著 —— 打字快的編劇不該被選單擋。
5. **排序與加總。** 場次表要不要能依人數排？「若干」與「10+」怎麼參與？
   建議：每種樣子都算得出一個**下限**（若干 ＝ 沒有下限），排序用它，加總一律不做。

## 會動到的地方

- `packages/schema/src/extras.ts` —— `parseExtra`／`formatExtra`／`sceneExtras` 的容錯
  （現在人數壞掉補 1，那條也要跟著重讀：壞掉的人數補「若干」比補 1 誠實）
- `ExtraRef.count` 的型別（`number` → 上表那四種樣子。attr 不允許 undefined，見 §6.6，
  所以是一個有 tag 的物件而不是「可選欄位」）
- 群演欄的選單：從一階段變兩階段 —— 與 `entity-field.tsx` 的 `Stage` 是同一類東西，
  形狀值得對齊（票券 42 的「回上一步」在這裡同樣適用）
- 場次表第一層的群演欄、`extrasLabel`
- `entity-field.tsx` 的「從『路人 x8』裡升格一個人 —— 還剩 7」：人數是區間／下限／若干時
  「還剩」怎麼寫（`3-5` 升格一個剩 `2-4`？`若干` 升格一個還是 `若干`？）
- CONTEXT.md 的「群演」實作定案第 1 條（**這張票會推翻它**，要連同理由一起改寫）
