# 37 — ⌘Z 撤銷一筆 chip 時，字要回到輸入框（bug）

**症狀：** 在實體欄位把一個名字定案成 chip（打字新建、命中既有、齊聲、升格 —— 每一條路都一樣），
接著按 ⌘Z：文件那一半退得乾乾淨淨（chip 消失、升格的話群演也回到原本人數），但**輸入框是空的**。
編劇要重打一次那個名字才能改選別的。回報時的原話：「希望是退回原來打的名字（待選階段）」。

**Status:** open

## 根因（已定位，不必再查）

那串字**從來不在 doc 裡**。定案的最後一步是 `entity-field.tsx` 的 `reset()`，它把 `text` 清成 `""`；
⌘Z 之後 ProseMirror 把 doc 退回去，欄位跟著重繪成沒有那一筆 chip 的樣子 —— 而本地的 `text`
沒有任何人負責還原。

轉送的那一段是對的、不用動：`history-keys.ts` 的 `forwardHistoryKey` 只在**輸入框是空的**時候
才把 ⌘Z 交給文件（「框裡還有沒定案的字時不接手 —— 那一刻的 ⌘Z 是『撤銷我剛打的那幾個字』，
原生 undo 正是為它而生」）。缺的是**文件退回去之後**，欄位要把字接回來。

## 規則

> **⌘Z 撤銷的是「把字定案」這個動作，而那個動作的反面是字回來，不是字消失。**

這條不是為了升格才發明的。欄位裡已經有一模一樣的動作：`editRef`（點 chip、空欄位按 Backspace）
把 chip **還原成可編輯的文字** ——「不是刪掉再重打，字回到輸入框、游標接在後面」。⌘Z 該落在
同一個終點。

兩條規則會自己接起來，不衝突：字回來之後輸入框非空，**再按一次** ⌘Z 就照舊歸原生 undo
（撤銷你打的那幾個字）。

## 形狀

撤銷之後的欄位狀態，要與「點那個 chip」之後**完全一樣**：

- 字回到輸入框
- 選單開著、停在待選（`stage: "suggest"`、`active: 0`、`dismissed: false`）
- ⚠️ **`editing.current` 要接回那一筆引用**。少了它，原封不動再定案一次會被當成一個新名字
  （見 `resolve` 裡「名字沒改就是原封放回，用回它自己的 id」那條）。
- 反白與否照 `editRef` 的既有裁決：滑鼠點 chip 進來的不反白。⌘Z 進來的算哪一種，做的時候定，
  寫進 Comments。

**只在這個欄位還有焦點時做。** ⌘Z 是全域的 —— 焦點早就離開這一欄了還把字塞回去，等於系統
在編劇沒看的地方動他的欄位。焦點不在就只讓文件退，欄位不插手。

## 不在範圍

- 撤銷**兩筆以上**的定案。連按 ⌘Z 時只還原最近那一次；再往前的照舊只退文件。
- 升格的語意。這張票不碰 `takeOneFromExtra`、單一 transaction、群演減一 —— 票券 35 已驗。

## 驗收

- [ ] 打「小李」定案成 chip → ⌘Z **一次** → chip 消失、**「小李」回到輸入框**、選單開著。
- [ ] 承上，再按一次 ⌘Z → 走原生 undo，撤掉輸入框裡的字（不是又退一次文件）。
- [ ] 字回來之後原封不動再定案一次 → **同一筆實體**，人物表不多一列（`editing.current` 有接回來）。
- [ ] 升格那條路：⌘Z 一次 → 群演回到原本人數、chip 消失、名字回到輸入框（三件事同一次）。
- [ ] 命中既有人物那條路同上。
- [ ] 焦點已經離開這一欄時按 ⌘Z → 文件照退，**欄位不會突然被塞進一串字**。
- [ ] 注音組字期間的 ⌘Z 仍然整顆還給 IME（`forwardHistoryKey` 第一行，§7.6）。
