# 16 — 場次導覽 sidebar

**What to build:** 創作中的定位（§7.10）。**與「文件 sidebar」是兩回事** —— 導覽仍是純 routes ＋ hub。列出場次，每列形如 `S1 內 日 廚房`（欄序比照 §8），點擊捲動到該場。跟隨游標高亮。**含草稿場次並標示**。子場次縮排一級；群組成員各自一列、看得出同組；群組本身不列。可收合、**預設展開、狀態持久化**（130 場時是剛需、8 場時是噪音）。搜尋框：v1 只做**清單篩選**（比對場次號／地點／人物／時間），全文搜尋不做。**v1 不做 focus mode，也不做 metadata 的 global collapse**（收 sidebar 已吃掉絕大部分需求；chip row 的 global collapse 直接踩 §7.11 的防呆警告）。

**分工（多處以它為判準）**：sidebar ＝ 創作中的定位（跟隨游標高亮、**含草稿**、只為了跳）；場次表（票 15）＝ 交付用的投影（零新增資訊、給製作端、可印、可深連結）。**草稿是唯一的分歧。**

## Comments

**2026-10-22 實作（使用者裁決）：窄螢幕（< 64rem）改抽屜、預設收起。** 寬螢幕是稿子左邊的 sticky 一欄，預設展開，
收合狀態存 localStorage（一個人的閱讀習慣，不跟著劇本走）。窄螢幕放不下並排，展開就蓋掉整份稿子 —— 那裡是左下角
「場次」鈕叫出來的覆蓋式抽屜，每次載入都收著、點一場跳過去就收回、Esc／點稿子收回；開合不寫進持久化。

**實作落點與幾個規格沒寫死的選擇**：
- 列從**編輯器那一份場次號**（`editorSceneNumbers`，套上「離開時才判定」的鎖）推導，不讀 `projectSceneTable`（它濾掉草稿）
  —— gutter 印 `S5[D1]` 時 sidebar 也印 `S5[D1]`。推導是 `scene-nav/rows.ts` 的 `sceneNavRows`。
- 一列：`S` ＋ 場次號（草稿是它自己的標籤）、景的簡稱、光、**這一場的地點顯示名**。景的簡稱 `內／外／內外／雜` ——
  `內外景` 不能取首字，會跟 `內景` 撞成同一個 `內`。空欄不印。
- 草稿：場次號換草稿色（同 gutter），螢幕閱讀器另唸「草稿」。群組成員（連同它們的子場次）收在同一條細直線裡、
  `role="group"`／「對剪」；群組本身不佔一列。
- 點一列走 `revealScene`（與場次表預覽的「到劇本」同一個落點）：游標落進那一場、浮現底色，高亮因此跟過去。
  游標換場時 sidebar 只把目前那一列捲到剛好看得見。
- 只陪劇本：切到場次表時不出現（場次表本身就是一張場次清單）。
- 篩選與場次表**共用** `filterScenes`（原 `filterSceneTable` 泛化，由呼叫端交出要比的欄）：比對場次號／景／時間／
  地點／人物／群演，地點與人物比 `實體名（顯示名）`，所以畫面上沒印的實體名也找得到。新增：場次號前帶 `S` 也算
  （sidebar 印的是 `S5`），場次表同樣受惠。為此 `referenceLabel`／`extrasLabel` 從 `@scenephonie/schema` 對外開出。

待瀏覽器驗收：窄螢幕抽屜（本輪 Chrome 視窗縮不下去，沒驗到）；130 場時的捲動手感。
