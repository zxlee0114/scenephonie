# 52 — 握著一筆實體、清空重打前綴，要重新命中它自己

**What to build:** 原本握著 `Leon`，清空、打 `L` —— `👤 Leon` 那一列就該出來。**現在不會。**

`editRef` 把引用從 doc 上拿掉，只被這一場引用的實體於是暫時掉出 `existing()`，而
`editingMatch` 只認**完全相等**的名字。結果是：只被一場用到的實體重打前綴命中不了自己，
被多場用到的卻可以 —— **同一個手勢兩種結果，而差別在編劇看不見的地方**。

這是票券 38 那個 bug 的同一條裂縫，38 只補了「完全相等」那一格。

**Blocked by:** 40

**Status:** in-review

## 從哪來的

原本是票券 42 的第 4 條。42 是一張**措辭票**（`↩︎ 不修改，返回` 與 `↰ 回上一步` 要在每個
階段都看得見），而這一條是**既有的 bug**：不是措辭、不是階段、不需要等措辭那一側的任何
東西。留在 42 裡它會被措辭的討論壓著不做（使用者裁決 2026-09-12）。

## 建議做法

把手上那一筆當成一個**暫時仍存在**的候選丟進 `hits` 的比對（前綴／包含都算），而不是只在
「完全相等」那一格認它 —— 讓「拿在手上」與「還在目錄裡」在自動補全這一側**完全同形**。

⚠️ **不放寬到真正的孤兒**：ADR-0005（實體因引用而存在）那條線不動。差別是握在手上的那一筆
有一個明確的持有者，而孤兒沒有。

## 驗收

- [x] 握著 `Leon`、清空、打 `L` → 出現 `👤 Leon`（**即使它只被這一場引用過**）
- [x] 被多場引用的實體行為不變
- [x] 命中列 `👤 派出所（3 場）` 的場數沒有被弄丟
- [x] 真正的孤兒仍然不出現在候選裡（ADR-0005 不動）
- [x] 人物欄與地點欄行為一致

## Comments

### 2026-09-14 — 實作

`entity-field.tsx` 多一支 `candidates()`：`existing()` 再加上手上那一筆（它已經掉出去時才加，
放最前面以免被 5 列上限擠掉）。選單的候選與注音組字期間的預覽都改讀它 —— `exact` 與 `hits`
於是同一份清單，「拿在手上」與「還在目錄裡」在自動補全這一側完全同形。票券 38 只補了 `exact`
那一格，這裡補的是**同一條裂縫的另一半**。

- **抽成一支函式**而不是在選單那一段寫一句：這條例外原本已經有兩個落點（`editingMatch` 多認
  顯示名、`resolve` 走它），再散第三份的話 ADR-0005 那條邊界就沒有權威的實作點了。
- `existing()`、`byName()`、`resolve()` 都**沒有動**：孤兒沒有持有者，仍然不進候選。
  `byName()` 放寬的後果票券 38 那則寫過（升格那一列會說假話），方向不變。
- 已經在 `existing()` 裡的（被多場引用）走原本那條路，次序一個字沒動 —— 驗收第 2 條是恆等的。
- 場數（驗收第 3 條）本來就走 `scenesOf` 的 `heldScenes` 快照，這一改沒碰到它；補了回歸測試
  釘住「拿起來之前是 3 場，打前綴時仍印 3 場」。

九條測試在 `entity-field.test.tsx` 的「清空重打前綴，要重新命中手上那一筆（票券 52）」。
全套 560 passed、typecheck 與 lint 乾淨。**人工驗收待編劇跑一次真的編輯器。**

### 2026-09-14 — code review 收斂

兩軸各自抓到一條，都是這次改動**新引進**的，已修：

- **注音那條路沒跟上。** 組字期間的預覽仍然只讀 `existing()` —— 握著只被這一場引用的
  `派出所`、注音打「ㄆㄞˋ」，組字時預覽是空的，送出之後它才蹦出來。那還是同一個手勢兩種
  結果，只是換了個地方。預覽改讀同一支 `candidates()`，加了測試。
- **別名那兩列吃到了手上那一筆。** `🔗 作為既有實體的另一個名字…` 與它的第二步原本共用
  選單那個變數，於是候選一放寬，手上那一筆就會出現在「要指到哪一筆」的清單裡 —— 把自己
  設成自己的別名。那兩列問的是**別的**哪一筆，改回讀 `existing()`，加了測試。

另外決定**不改**一條：從 `hits` 選回手上那一筆時顯示名用**實體名**而不是框裡的字。審查認為
這與票券 38「手上那一筆保留這一場的別名」不一致，但兩者的前提不同 —— 38 保的是**原封放回**
（字一個都沒改），而走到 `hits` 的前提正是字已經改過了，那時框裡是剛打的半截（`派`），把它
當顯示名寫回去才是竄改。分界因此是 `exact`，這一條寫進了那段 `run()` 的註解。

⚠️ **範圍外**：順手把 `docs/adr/0005-entities-exist-by-reference.md` 的「邊界：正在被編輯的
那一筆不是孤兒」那一節改寫了 —— 它原本只寫到「判斷**這個名字命中了嗎**時多認手上那一筆」，
而這張票把它擴到整份候選清單與預覽。票券只說 ADR-0005 不動（指孤兒那條線沒鬆），沒有要求改
ADR；內容與裁決一致，要拿掉的話拿掉即可，程式不依賴它。
