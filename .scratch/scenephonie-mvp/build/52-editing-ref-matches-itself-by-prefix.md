# 52 — 握著一筆實體、清空重打前綴，要重新命中它自己

**What to build:** 原本握著 `Leon`，清空、打 `L` —— `👤 Leon` 那一列就該出來。**現在不會。**

`editRef` 把引用從 doc 上拿掉，只被這一場引用的實體於是暫時掉出 `existing()`，而
`editingMatch` 只認**完全相等**的名字。結果是：只被一場用到的實體重打前綴命中不了自己，
被多場用到的卻可以 —— **同一個手勢兩種結果，而差別在編劇看不見的地方**。

這是票券 38 那個 bug 的同一條裂縫，38 只補了「完全相等」那一格。

**Blocked by:** 40

**Status:** done

## 從哪來的

原本是票券 42 的第 4 條。42 是一張**措辭票**（`↩︎ 不修改，返回` 與 `↰ 回上一步` 要在每個
階段都看得見），而這一條是**既有的 bug**：不是措辭、不是階段、不需要等措辭那一側的任何
東西。留在 42 裡它會被措辭的討論壓著不做（使用者裁決 2026-09-12）。

## 建議做法

把手上那一筆當成一個**暫時仍存在**的候選丟進 `hits` 的比對（前綴／包含都算），而不是只在
「完全相等」那一格認它 —— 讓「拿在手上」與「還在目錄裡」在自動補全這一側**完全同形**。

⚠️ **不放寬到真正的孤兒**：ADR-0005（實體因引用而存在）那條線不動。差別是握在手上的那一筆
有一個明確的持有者，而孤兒沒有。

## 驗收

- [x] 握著 `Leon`、清空、打 `L` → 出現 `👤 Leon`（**即使它只被這一場引用過**）
- [x] 被多場引用的實體行為不變
- [x] 命中列的身分沒有被弄丟（2026-09-15 起**手上那一筆不印場數**了，但拿起來那一刻的
      快照仍然決定它印 `📍` 還是 `🕓`）
- [x] 真正的孤兒仍然不出現在候選裡（ADR-0005 不動）
- [x] 人物欄與地點欄行為一致
- [x] 只有這一場認識的那一筆印成一則歷史紀錄（`🕓 Leon`），一個數字都不印
      —— 別場也認識它時才換回 `👤 Leon（N 場）`（2026-09-14 追加）
- [x] 手上那一筆一個場數都不印（2026-09-15 第二輪追加）

  釘住「拿起來之前是 3 場，打前綴時仍印 3 場」。

九條測試在 `entity-field.test.tsx` 的「清空重打前綴，要重新命中手上那一筆（票券 52）」。

### 2026-09-14 — code review 收斂

兩軸各自抓到一條，都是這次改動**新引進**的，已修：

- **注音那條路沒跟上。** 組字期間的預覽仍然只讀 `existing()` —— 握著只被這一場引用的
  `派出所`、注音打「ㄆㄞˋ」，組字時預覽是空的，送出之後它才蹦出來。那還是同一個手勢兩種
  結果，只是換了個地方。預覽改讀同一支 `candidates()`，加了測試。
- **別名那兩列吃到了手上那一筆。** `🔗 作為既有實體的另一個名字…` 與它的第二步原本共用
  選單那個變數，於是候選一放寬，手上那一筆就會出現在「要指到哪一筆」的清單裡 —— 把自己
  設成自己的別名。那兩列問的是**別的**哪一筆，改回讀 `existing()`，加了測試。

另外決定**不改**一條：從 `hits` 選回手上那一筆時顯示名用**實體名**而不是框裡的字。審查認為
這與票券 38「手上那一筆保留這一場的別名」不一致，但兩者的前提不同 —— 38 保的是**原封放回**
（字一個都沒改），而走到 `hits` 的前提正是字已經改過了，那時框裡是剛打的半截（`派`），把它
當顯示名寫回去才是竄改。分界因此是 `exact`，這一條寫進了那段 `run()` 的註解。

⚠️ **範圍外**：順手把 `docs/adr/0005-entities-exist-by-reference.md` 的「邊界：正在被編輯的
那一筆不是孤兒」那一節改寫了 —— 它原本只寫到「判斷**這個名字命中了嗎**時多認手上那一筆」，
而這張票把它擴到整份候選清單與預覽。票券只說 ADR-0005 不動（指孤兒那條線沒鬆），沒有要求改
ADR；內容與裁決一致，要拿掉的話拿掉即可，程式不依賴它。

### 2026-09-14 — 追加裁決：那一列不是一筆實體，是一則歷史紀錄

人工驗收前使用者看了形狀，裁決把**呈現**拆開（票券原本只講「找不找得到」）：

> 我會想做這個功能的目的是提示，這是剛剛打過的名字，也許新的名字是該名字的某個變體。
> 但如果這是這位角色的第一場，只是因為編劇打錯了，就用實體的方式來提示，就會顯得奇怪。

候選有兩種來源，而它們不是同一種東西：別場也指著的那一筆是**劇中已經存在的那一位**，
手上這一筆可能只是三秒鐘前打錯的字。`（1 場）` 那個 `1` 指的就是編劇正站著的這一場 ——
印出來沒告訴他任何他不知道的事，卻拿「存在」這條定義替那個錯字背書。

- **記號**：`🕓`（`HISTORY_MARK`），仿 Google 查詢框底下的歷史紀錄提示。不印場數，別名那一句
  照印（它回答的是「框裡的字與這一列什麼關係」，與這筆實體有多大無關）。
- **判準**：**除了這一場有沒有別場認識它**（場數 ≤ 1），不是「像不像打錯的」—— 系統分不出
  打錯與真名，但分得出有沒有別場指著它。手上沒握著的那一筆即使只用在 1 場也照印身分與場數：
  那 1 場指的是別人，那才是編劇不知道的事。
- **範圍**：選單與組字預覽共用同一支 `candidateLabel`。同一筆東西在選字前後換一張臉，比印錯
  場數更糟。
- **行為一個字都沒變**：按下去仍然指回同一筆實體、不會多建一筆（票券 38 那條線）。改的只有
  它長什麼樣。

⚠️ 這推翻了票券 38／39 幾條測試裡的預期（`📍 派出所` → `🕓 派出所`、`📍 test（1 場）` →
`🕓 test`），那些斷言當初釘的是「那一列在不在」與別名那一句，記號是順帶寫進去的。順手修掉
一個假的 mock：票券 38 的「被引用兩次以上行為不變」餵的 usage 是 `1`，而場數含這一場，所以
它其實測的是「只有這一場」—— 改成 `2`，測試名這下是實話。ADR-0005 的邊界那一節也補了這條。

### 2026-09-15 — 追加裁決：正在編輯的那一場不算進場數

> 我覺得，正在編輯的那一場不要算進場數內。因為當編劇去編輯那個實體，就代表那個人或地點
> 不一定會留在那一個場次中。

**這推翻了 2026-09-11 的相反裁決**（票券 39 收票，CONTEXT.md 原文：「選單裡的『（N 場）』
含編劇正站著的這一場」）。同一個觀察兩種結論：

- 舊的：去留未定 → **不該讓數字少一**（拿起來不該讓一筆實體看起來變小）。
- 新的：去留未定 → **不該把它算進去**。

新的贏在那個數字**無論編劇接下來做什麼都成立**：留下它、換掉它、整筆移除，「除了這一場還有
N 場用到它」都是同一個 N。而且改名那一列的 `還有 N 場印著「X」` 本來就是這樣數的 —— 兩個
數字這下是同一個意思，不必在同一份選單裡分辨哪個含這一場、哪個不含。

- 實作仍然是**拿起來之前先問一次，記住那個數字減一**，不是「拿掉之後重數」：計數單位是場次，
  重數的話同一場的別欄（例如對白說話者）也指著它時，這一場會留在數字裡，而要扣掉的是整場。
  多了一條測試釘這件事。
- 與 2026-09-14 那條裁決落在同一個數字上：「除了這一場沒有別場認識它」現在就是**那個數字
  等於 0**，`🕓` 的判準因此從 `≤ 1` 變成 `!scenes`，更直接。
- 連帶改掉票券 39 那幾條測試的預期（`3 場` → `2 場`），以及 CONTEXT.md 那一條、ADR-0005
  邊界那一節、`HISTORY_MARK` 的註解。

### 2026-09-15 — 第二輪：手上那一筆不印場數

同一天稍早那條裁決（「不含編劇正站著的這一場」）被這一條取代。起因是使用者要了舊裁決的
前後文，而挖出來的東西與雙方的預設都不一樣：

**2026-09-11 那條不是一條設計裁決，是一張 bug 單。** 票券 39 收票第 1 條，標題原文是
「命中列的場次數少算一場（**bug，不是措辭**）」—— 編劇回報的是**數字在他手底下從 3 跳到
2**（`editRef` 先把引用從 doc 撤掉，`entityUsage` 於是少數一場）。「那筆實體並沒有變小，
編劇也還沒決定要不要留下它」是修法（快照）寫下來的**事後理由**，「含不含這一場」這個問題
從來沒有被真正問過。所以今天早上那句「同一個觀察兩種結論」太抬舉舊的了。

**裁決：手上那一筆一個數字都不印。**

> 編劇寫劇本的時候不會特別顧慮某個角色登場過的場數。

那個數字回答的是「這筆實體多大」，而編劇這一刻要的是**代價** —— 而代價那一句改名那一列
已經在講（`還有 N 場印著「X」`），講得比大小精確。連帶好處是「含不含這一場」整個問題消失：
同一份選單裡不會再有兩個意思不同的 N。場數只留給候選列裡**別的**那幾筆 —— 那幾場指的是
別人，那才是編劇不知道的事（2026-09-14 那條裁決已經是這個方向的一半）。

還有一個不好看但該講的地方促成了這個決定：新規則下三場用到它會印 `2 場`，**正是當初被判成
bug 的那個數字**。差別只在它從「不穩定的 2」變成「穩定的 2」—— 要靠這種解釋才站得住的畫面，
不如不印。

- **實作是一個 token**：`candidateLabel` 裡 `!onlyHere && scenes` 改成 `!held && scenes`。
  `heldScenes`（總數減一的快照）留著，因為 `🕓` 的判準仍然是它等於 0；`editRef` 的減一也
  留著，理由不變（重數會把這一場留在數字裡）。
- **測試**：兩條釘場數的改成釘記號 —— 「同一場的別欄也指著它」那條現在餵 usage 恆為 1，
  重數會得到 1（誤判成別場也認識它），減一得到 0 → `🕓`，減一與重數的差別這下正好落在
  記號的分界上。其餘 `（N 場）` 的斷言凡是手上那一筆的都拿掉括號。
- CONTEXT.md 那一條、ADR-0005 邊界那一節、`HISTORY_MARK` 與 `heldScenes` 的註解跟著改；
  CONTEXT.md 額外記下「2026-09-11 那條的真實來歷」，免得下一次又被當成一條對等的設計裁決。

**這張票最後長成三層，值得記一下它們的順序：**

1. **找不找得到**（票券原本的範圍）—— `candidates()`，讓「拿在手上」與「還在目錄裡」在自動

是**去翻了舊裁決的前後文** —— 2026-09-11 那條根本不是設計裁決，是一張 bug 單（數字在編劇手底下
從 3 跳到 2），「含不含這一場」從來沒有被問過。一條被誤認為對等的舊裁決，會讓新的討論以為自己
在做權衡，其實只是在跟一句事後理由角力。
