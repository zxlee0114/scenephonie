# 49 — 遷移批次 5：新增流程跟著對齊，對白欄與升格措辭不再印乘號

**What to build:** 最後一批呼叫點。兩件事：**新增**一批群演時的兩層流程（與編輯共用同一套
子選單，只是第一列沒有原數量可印），以及**對白人物欄**那一側 —— 在那裡新建群演、從群演裡
升格一個人，措辭都還印著乘號與「N 人」。

**Blocked by:** 48、46（升格剩多少是 46 算的）

**Status:** done

## 新增：一樣的兩層，第一列是「若干」

```
第一階段  輸入群演名                第二階段  說人數
┌─────────────────────┐          ┌─────────────────────────────┐
│ 路人▌               │          │ 若干                        │
├─────────────────────┤          │ 1                           │
│ ＋ 新增群演「路人」  │   →      ├─────────────────────────────┤
│ 👥 路人（別場用過）  │          │ ▌                           │
└─────────────────────┘          │ { 提示 ／ 預覽 ／ 警告 }     │
                                 └─────────────────────────────┘
```

規則收斂成一句：**沒說人數就問一次。**

| 框裡 | Enter 之後 |
|---|---|
| `路人（8）`、`路人 x8`、`路人 10+` | **直接定案** —— 人數就在那串字裡，他已經說了 |
| `路人` | 進第二層，第一列 `若干` |

**一次打完的路留著**（使用者裁決 2026-09-12）—— 打字快的編劇不該被選單擋。新增框的合約
與編輯框不同：它從零開始，整串都還沒定案，所以它**認尾綴**（票券 47 那條「編輯框不認」
只管編輯）。

空著 Enter／離開仍然是第一列，新增時那就是「若干」—— 他確實沒說。

**放手之後（或整欄空著）打字，兩階段就回來了** —— 那時沒有握著任何一批，走的是新增。

## 對白人物欄那一側

- **在那裡直接新建一批群演**：措辭 `新增群演「路人」8 人` 對區間／下限／若干都不成立
- **從那批人裡升格一個**：`從「路人 x8」裡升格一個人 —— 小明（群演剩 7 人）`
  ⚠️ 那句裡的乘號是**硬寫的**，沒有走 `formatExtra` —— 顯示改括號時它是最容易漏掉的一處
- 剩多少**不在這裡算**，票券 46 已經算好了（`3-5` → `2-4`、`若干` → `若干`、只有確切減得到 0）

措辭照票券 46 那張表。人數在這幾列裡是**措辭的一部分**，不是裝飾：升格那一列要在按下去
之前就說出那批人會變成什麼（ADR-0006：代價寫在按下去之前）。

## 這一批也是整合驗證點

前面四批各自 CI 綠，但沒有一批走過**整台編輯器**。這一批補**一條**煙霧測試：走一遍畫面之後，
場次 attr 裡躺的是新形態的值。不在這一層重測任何措辭 —— 那些都在前面幾批的元件測試裡。

#### 四個實作當下才定的事

1. **`statesCount` 是一支獨立函式，不是 `parseExtra` 多一個 `stated` 欄位。** 值上分不出
   `路人（若干）`（他說了）與 `路人`（他沒說）—— 只有「這串字裡有沒有讀得出來的尾綴」分得出來。
   本來想在 `parseExtra` 回傳裡多帶一個旗標，但那會讓 `parseExtra(formatExtra(e)) === e` 那條
   **往返硬約束**的測試從比整筆退化成比欄位。共用 `splitCount` 就不會有第二套解析。

2. **子選單的版面照票券 48，不照這張票的示意圖。** 這張票的圖把格子畫在 `若干`／`1` 底下，
   48 第二輪的編劇裁決把它移到第一列後面（焦點跳得遠就看不見它跳去哪）。這張票自己說的是
   「**與編輯共用同一套子選單**，只是第一列沒有原數量可印」—— 那句話比示意圖晚，也比較具體，
   所以新增那一層是 `若干`（第一列）／格子＋提示／`1`。`↩︎ 不修改，返回` 那一列**不在**新增
   這一側：手上沒握著任何一批，沒有一輪編輯可以作廢（退一階走 Esc，打的字留著）。

3. **第一列的措辭分兩態**：說了人數印整筆（`＋ 新增群演「路人（8）」`，按下去就是它），沒說
   只印名稱加一個 `…`（`＋ 新增群演「路人」…`）—— `…` 與 `修改數量…` 是同一個慣例：**還有一關
   要走**。舊措辭 `新增群演「路人」8 人` 讀的是舊欄位，在區間／下限／若干上都是謊。

4. **`Esc` 收掉建議清單之後 Enter 仍然會問。** 規則一步都不退（沒說人數就問一次）——
   Esc 收的是那份補字串的清單，不是那個問題。

#### 兩件記下來的事

- **驗收第 10 條「場次表與 PDF」按「（若有）」處理**：票券 15／18 還沒做，這兩個畫面此刻不存在。
  資料層那一半已經成立（`formatExtra`／`extrasLabel` 走 `extraCount`，若干印「若干」），
  schema 測試釘著；那兩張畫面長出來時不必再改這裡。
- ⚠️ **群演欄剛新增的一批，同一場的對白人物欄當下看不到它**（升格／齊聲那幾列要等重新掛載）。
  這是 NodeView 不因別的 node 的 attr 變動而重繪的既有行為，**不是這批造成的**，也不在這批
  的範圍 —— 整合煙霧測試因此把升格那一半跑在初始 doc 就有的那批人身上。要修的話是另一張票。

**驗收 2、3 通過**（一次打完直接定案、`路人 8` 是名字）。

#### 子選單版面第二輪（編劇裁決）

新增那一側改成與編輯那側**逐列對齊**，頭尾兩列說的話不同：

```
↰ 回上一步，改群演名稱      ← 編輯那側是 `↰ 不修改數量（8），回上一步`
▌                          ← 格子（兩側都在第二列）
若干                        ← **預設停在這一列**

✕ 放棄新增群演              ← 編輯那側是 `↩︎ 不修改，返回`
```

推翻的是上一版「第一列就是若干」那個安排。**「預設值印在看得見的地方」那條規矩沒有變**，
變的是它站在哪一列：第一列讓給 `↰`（兩層之間走得回頭這件事本來只有 Esc 一條看不見的路），
預設答案的角色交給**進來就停著的那一列**。空著 Enter、點到外面、按 `若干` —— 三者仍是同
一個結果。

兩處實作細節：

- 高亮在 `若干`、**DOM 焦點仍在格子裡**，所以「打到一半 Enter」一步都沒少（打字會把高亮
  拉回格子）。為此格子的 `onFocus` 加了一個例外：程式送進來的那一次不搶高亮。
- `✕` 是新記號，不沿用 `↩︎`：那邊有一批人要原封放回，這邊手上什麼都沒有，丟掉的是打到
  一半的那串字（連名稱一起清）。拿 `↩︎` 去印會承諾一個不存在的還原點。

#### 抬頭措辭（編劇逐字指定）

`新增群演「路人」，這批有幾個人？` → **`選擇群演「路人」數量`**，與編輯那側的
`修改數量（原本是 8）` 同一個句型。

#### 三處裁決的回應

1. `…` 後綴**暫定留著**，之後可能因 UI 再議。
2. 抬頭已改（見上）。
3. Esc 保留，但**多階層的「回上一步」現在有自己的一列**了 —— 不再只靠一個看不見的鍵。
4. 「點到外面 ＝ 回到預設」這條編劇接受，第一層 blur 不問人數的行為維持。

#### 兩則驗收回報的澄清（都不是這批的缺陷）

- **「放手」指的是 `↩︎ 不修改，返回` 或空框上的 Backspace，不是 Esc。** Esc 在編輯那一側
  收的是建議清單（chip 外殼還在、字全選），手上那一批**還握著** —— 所以接著打字走的是
  編輯。這是票券 42／48 的既有語意，上一輪我寫的驗收步驟用詞含糊。
- **對白人物欄打一個不相干的名字（`小明`）不出升格列是對的。** 那一列的命中條件是
  「`query` 包含群演名稱**或**以它開頭」（票券 35：打 `路人小明` 也要看得到）。要看升格
  措辭，打 `路人` 或 `路人小明`。
- 升格預覽吃到舊數量 —— 正是上一輪記下的 NodeView 重繪限制，另一張票。

### 2026-09-13 —— 人工驗收第二輪（子選單版面第三輪）

新增那一側的第二層收成**三列**：

```
↰ 回上一步，改群演名稱
▌                       ← 焦點與高亮都在這裡
不特別指定數量（若干）
✕ 放棄新增群演
```

三項編劇裁決：

1. **預設焦點與高亮都回到輸入框。** 上一輪把高亮放在 `若干` 那一列（好讓「什麼都不做會
   記成什麼」有個看得見的位置），實際看是**游標在格子裡閃、高亮在別的列上，找不到重點**。
   預設值改用那一列自己的措辭說，高亮就只說一件事：下一顆鍵會打在哪。
2. **`1` 那一列拿掉**（只在編輯那側留著）。新增這一關只有兩條路 —— 打一個數字，或者不說；
   `1` 與格子裡打一個 `1` 完全重複，夾在中間讓三條路看起來像四條。編輯那側它是真的捷徑
   （從 8 改成 1），照舊。
3. **`若干` → `不特別指定數量（若干）`**（只在新增那側）。那一列不再是「與 `1` 並列的一個
   數字」，而是**這一關的退場**：他不是挑了「若干」這個數量，他是決定不說。括號裡留著
   `若干`，因為那才是 chip 上與場次表上會看到的字。

⚠️ 這三項只動**新增**那一側。編輯那側是票券 48 驗收過並 merge 的版面，`1` 與 `若干` 在那裡
與 `不修改數量（8）` 是三個並列的答案，語意不同。要不要一起收窄是另一次裁決。
