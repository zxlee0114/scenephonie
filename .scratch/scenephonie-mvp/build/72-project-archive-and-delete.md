# 72 — 專案封存與刪除

**What to build:** 專案可以**封存**（從儀表板收起來，資料不動，隨時還原），也可以**刪除**（先進「已刪除」區
保留 30 天，期間可以救回；30 天後永久刪除，劇本、文件、備份、交付與分享連結全部清掉）。

**Blocked by:** 71

**Status:** ready-for-agent

## 為什麼

[71](./71-project-dashboard-and-create-flow.md) 把建立改成手動、片名可以留白之後，儀表板很快會堆出幾個
「未命名專案」。v1 原本沒有刪除專案這件事（票 06 的冪等論證就建立在「清不掉」上）。

## 已定（使用者裁決，2026-10-23 grilling）

1. **封存與刪除兩種都做。**
   - 封存：從儀表板主區收進「已封存」，資料不動，可以還原。
   - 刪除：進「已刪除」區保留 **30 天**，可以救回；卡片顯示「還剩 N 天」。過了就永久刪除。
2. **分享連結**（ADR-0008 的活連結與凍結連結）：
   - **封存期間兩種都照常有效** —— 封存是整理儀表板，不是收回作品；已經交出去的稿不能因此打不開。
   - **一進「已刪除」區兩種就全部失效，救回後恢復** —— 按刪除就是「我要收回這部作品」。
   - 失效的連結對訪客顯示的跟被撤銷的連結一樣（§ 分享連結：中性頁面「這條連結已停用」），
     不透露是封存、刪除還是撤銷。
   - 這不違反 ADR-0008：凍結連結承諾的是**內容不變**，不是**永遠打得開**；刪除與撤銷同類，是收回分享關係。
3. **永久刪除搭現有的排程** `/api/cron/guest-cleanup`（每天一次，票 07）。票 07 的立場是「同週期、同失敗後果的
   工作不另開排程」，這支清理同樣符合。端點仍然不收參數，只執行寫死的政策。

## 已定（使用者裁決，2026-10-25 grilling）

用詞見 CONTEXT.md「封存」「刪除（專案）」：封存 ↔ **取消封存**；刪除 ↔ **還原**；吐司上的是「復原」。

4. **封存與刪除互相獨立**：`projects.archived_at`、`projects.deleted_at` 兩欄可以同時有值，不需回填。
   還原只清 `deleted_at` —— 從已封存區刪的，還原後仍是已封存；從主區刪的回主區。
5. **已封存的專案什麼都沒變**：gate 不看 `archived_at`，照常打開、照常編輯。專案首頁頂端一條
   「這個專案已封存・取消封存」（只在專案首頁，不在編輯器）。
6. **已刪除的專案過不了 gate**：`authorizeProjectForUser`／`authorizeScreenplayForUser` 對 `deleted_at`
   不為 null 的專案回 `null` —— 所有頁面 404、存檔被拒（另一個分頁開著編輯器時會看到存檔失敗，接受）。
   **還原**走 gate 的一個窄入口（只給還原 action 用、回傳只有它吃的 handle 型別），handle 不多出狀態（不變式 H）。
   永久刪除由 cron 執行，不走 gate。
7. **分享連結失效在讀取時判斷**：解析連結時 join 專案看 `deleted_at`，連結那一列不動 —— 還原時沒有東西要還原；
   已刪除期間另外撤銷的連結，還原後仍是撤銷。
8. **沒有「立即永久刪除」**（v1）。只有排程在 30 天後刪。
9. **確認與吐司**：刪除時，專案有生效中的分享連結（未撤銷的活連結＋凍結連結）才先頁內確認，寫出
   「N 條分享連結會停用、30 天內可從已刪除還原」；沒有就直接刪。封存不確認。封存與刪除（含確認後的）
   都跳出「復原」吐司 —— 把 `documents/free-document-list.tsx` 的 `UndoToast` 抽出來共用。
10. **儀表板版面**：主區下方兩個收合區塊「已封存（N）」「已刪除（N）」，預設收起，數量為 0 就不出現。
11. **動作只在儀表板卡片的「⋯」選單**：主區卡片「封存／刪除」；已封存卡片「取消封存／刪除」；
    已刪除卡片沒有選單，只有「還原」與「還剩 N 天」。專案首頁不放這些動作。
12. **排序與倒數**：已封存區照最近編輯（同主區）；已刪除區最快到期在前（`deleted_at` 升冪）。
    「還剩 N 天」＝ `deleted_at + 30 天 − now` 無條件進位，不到一天寫「今天到期」—— 排程一天一次，
    實際消失在第 30～31 天之間，顯示只會比實際保守。
13. **永久刪除**：`projects` 一列 `DELETE`，其餘靠 FK cascade（已確認：`screenplays`、`screenplay_backups`、
    `documents`、`characters`、`locations`、`deliveries`、`share_links` 全是 `onDelete: cascade`）。
    交付隨之消失的理由寫進 ADR-0008〈收回〉一節（已補）。
14. **cron 改名** `/api/cron/guest-cleanup` → `/api/cron/daily-cleanup`，`vercel.json` 一起改，`CRON_SECRET` 不動。
15. **訪客**跟一般使用者一樣可以封存、刪除；訪客 TTL 先到就連人帶專案清掉，照舊。
16. `landingProject()` 註解裡「v1 沒有刪專案這件事」的冪等論證要改寫（現在只有訪客入口會走到它，
    而訪客每次都是新的使用者，軟刪除不影響它的正確性）。

## 驗收

**封存**
- [ ] 主區卡片選單「封存」→ 卡片移進「已封存」區，跳出「復原」吐司；按復原回主區。
- [ ] 已封存的專案點得開、改得動、存得進去；專案首頁有「這個專案已封存・取消封存」，按了回主區。
- [ ] 封存期間活連結與凍結連結照常打得開。
- [ ] 已封存區照最近編輯排序。

**刪除與還原**
- [ ] 沒有生效分享連結的專案按刪除不確認，直接進「已刪除」，跳出「復原」吐司。
- [ ] 有生效分享連結的專案按刪除，先頁內確認並寫出連結數（不用瀏覽器原生 dialog）；確認後同上。
- [ ] 已刪除的專案：專案首頁、劇本、文件、大綱網址全部 404；開著的編輯器存檔失敗。
- [ ] 已刪除期間它的活連結與凍結連結顯示「這條連結已停用」（與撤銷相同）；還原後恢復。
- [ ] 已刪除期間撤銷的連結，還原後仍是撤銷。
- [ ] 從主區刪除的還原回主區；從已封存區刪除的還原回已封存區。
- [ ] 已刪除卡片只有「還原」與「還剩 N 天」（無條件進位；不到一天「今天到期」）；最快到期的在前。
- [ ] 兩個收合區塊數量為 0 時不出現。

**排程**
- [ ] `/api/cron/daily-cleanup` 永久刪除 `deleted_at` 超過 30 天的專案，劇本、備份、文件、人物地點、交付、分享連結一併消失（整合測試）。
- [ ] 不到 30 天的、沒刪的都不動；訪客 TTL 與自由文件清理照舊。
- [ ] `vercel.json` 指向新路徑；舊路徑不存在。
