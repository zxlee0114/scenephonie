## 資料怎麼辦：reset，不寫遷移

使用者裁決 2026-09-12：**目前資料庫裡是開發資料，隨時可重置。** 所以不寫遷移、不升
`doc_schema_version`，定義新的 canonical shape 然後 reset 即可。

`doc_schema_version` **不升**，而理由不是「現在是開發資料」—— 是它的判準本來就沒被觸發。
那個模組自己寫著：「改 node schema **且舊 doc 無法原封不動被新 schema 讀出**時 +1」。
`extras` 是 `{ default: [] }`，PM 不驗陣列裡面裝什麼，帶舊欄位的 doc 照樣 `fromJSON` 得出來。
變的是**值語意**，而值語意的守門人是 `sceneExtras`（§6.6 的讀取路徑正規化）。

**定位寫進註解**（這一張票的一部分）：`doc_schema_version` 是「PM node schema 的可讀性」
版本，不是值語意的版本。前者變了會炸（節點型別消失、attr 被移除、`fromJSON` 丟例外），
後者只會讀出一個舊形狀的值 —— 那是 `sceneExtras` 的本分。不寫下來，下一個人會重新推導
一遍，而且可能推錯方向。

真正需要升版的長相長這樣：`extras` attr 改名、或群演從 attr 搬進 node。

## 留下來的那條容錯

票券 45 在 `sceneExtras` 裡留的「裸數字讀成確切 N」**不刪**。它被框成**容錯**而不是遷移：
不拿版本、不寫遷移鏈、不對外承諾。理由是複製貼上、匯入、測試 fixture 這些路徑繞得過寫入端，
而裸數字有一個唯一誠實的讀法。這條的框定要寫在註解裡，免得下一個人把它當成遺留債務刪掉。
