# 57 — 一格裡的 chip 選得起來（⌘A 與清空）

**What to build:** chip 欄位多一個**選取狀態**（一組被選中的 chip），`⌘A` 是它 v1 唯一的入口，
`Backspace` 把選中的那些一起拿掉。四個 chip 欄位（內外／時間以外的那四格：地點、登場人物、
對白人物、群演）共用同一套。

**Status:** open

**Blocked by:** 無（08 實體欄位、09 群演欄、34 chip 之間的方向鍵導航都已完成）

## 為什麼

**「這一格不要了」現在沒有手勢。** 一格裡有三個登場人物，要清掉只能按三次 Backspace ——
而且每一次 Backspace 都不是刪除，是把那一筆**拿回輸入框整串反白**（票券 39 的編輯入口），
所以實際上是六次按鍵，中間還經過三個「正在編輯某一筆」的中途狀態。編劇手指記得的那一招
（`⌘A` 然後 `⌫`）在這一格**什麼也選不到**。

**而 `⌘A` 現在會外洩。** chip 是 `tabIndex={-1}` 的元素（`chip-caret.ts`），焦點站在一顆 chip 上時
沒有人攔 `⌘A`，它冒泡到 ProseMirror 變成「選取整份劇本」；焦點在輸入框裡時則是原生的
「選這格輸入框的字」。兩種結果都不是編劇按下去時想要的那一件事。

**滑鼠那一側同樣選不到。** 拖曳游標掃過一排 chip 什麼也不會發生 —— 而且**不該**會發生，
理由見下面〈拖曳歸誰〉。

## 選取狀態的形狀

**一組 chip（無序集合），不是一段區間。** 一格裡的 chip 順序是編劇的**偏好**、不是語意
（實體之間沒有先後），所以「選第 1 和第 3 顆」是合法且有意義的狀態，不必是連續的。
v1 只有 `⌘A` 這一個入口 —— 它一次把集合撐滿整格 —— 但資料形狀先站對位置，
以後的 `⌘` 點選／`⇧` 點選不必重寫。

集合裡放什麼由實作決定（索引或 `id`），但**必須撐得過 chip 增刪**：選取期間唯一會改變
這一格內容的動作就是清空本身。

## `⌘A` 的兩段與那個出口

| 按下時的處境 | 第一次 `⌘A` | 再按一次 |
|---|---|---|
| 輸入框裡**有字** | 選那串字（原生） | 選滿這一格（所有 chip ＋ 那串字） |
| 輸入框**空著** | 選滿這一格 | 放行給 ProseMirror（選整份劇本） |
| 站在一顆 **chip** 上 | 選滿這一格 | 放行給 ProseMirror（選整份劇本） |

**「按到底會放行」是硬性要求，不是體貼。** 若這一排永遠吃掉 `⌘A`，編劇站在 chip row 上
想 `⌘A⌘C` 拷貝整份劇本就會**沒有任何辦法**做到 —— 偷走一顆全域的鍵而不留出口是死路。
放行之後接手的是既有的第三段（`.scene.is-node-selected`／整份 selection，見 `editor.css:142`）。

## 選中時，別的鍵在做什麼

整格選中時它**看起來就是一段反白**，編劇腦裡跑的是文字的規矩，所以就照文字的規矩：

- `Backspace`／`Delete` → 清空選中的那些 chip。
- **直接打字** → **取代**：選中的 chip 一起消失，那個字進輸入框開始打新的一筆。
- `Esc` → 解除選取，游標回輸入框。
- **方向鍵** → 解除選取、焦點落在那一端的 chip 或輸入框（維持選取並移動 anchor 是 `⇧←` 的事，
  不在本票）。
- **點一顆 chip** → 解除選取，照舊把那一筆拿回來改（**不是**從集合裡切換掉那一顆 ——
  「⌘ 點選」那個入口留給以後的任意子集票，現在不要先把「點 chip」這顆鍵花掉）。
- **點畫面別處／欄位失焦** → 解除選取。反白**不留在失焦的欄位上**。

**`⌘Z` 一步回到原狀。** 「打字取代」是一個動作不是兩個：撤銷之後 chip 全部回來、剛打的字消失。
（還字那條路沿用票券 37，不在這裡另寫一套。）

## 四格一致

地點、登場人物、對白人物、群演**同一套**，即使其中兩格最多只裝得下一顆 chip
（對白人物永遠單值；地點只有雜景場次吃得下第二個 —— 票券 08／使用者裁決 2026-09-10）。
單值格只是「集合大小恆為 1」的退化情形。

理由：規則要能用一句話講完 ——「`⌘A` ＝ 選滿這一格」。一旦分流，編劇得先知道自己站在哪
一種格子裡，而那件事**畫面上看不出來**（同一排、長得一樣）。雜景與否改變的是**容量**，
不是**選取**；容量那道關卡在打字進去的時候就把住了，位置是對的，不要在這裡再擋一次。

⚠️ 地點被清空會讓 metadata 變空，依 §5.3 落回**自動草稿** —— 那是既有規則自然生效，
本票不另外處理，但驗收時要看見它確實發生。

## 反白畫在哪

**每顆被選中的 chip 各自套 `--selection-bg`，＋ 相鄰兩顆都被選中時把中間那道縫也染色。**
整格選滿時自動連成一條，看起來就是一段反白；以後選子集時自然斷成幾段 —— 這是唯一一種
「今天的整格」與「以後的子集」共用同一套畫法的畫法，而選取狀態已經是一組 chip，
畫面不該比資料更窄。縫那一個 class 加在 `chip-row.tsx`（它本來就在決定每道縫長什麼樣）。

顏色就用 `--selection-bg`（選字的反白色，整場 NodeSelection 也是它）。票券 39 特地**不讓**
正在編輯的那顆 chip 用這個底色，理由正是「在文字框裡它會被讀成『這幾個字被選起來了』」
（`editor.css:745`）—— 反過來說，**真的被選起來時它就該是這個顏色**，那條前例在支持這裡。

輸入框那一段（`⌘A` 第二段把打到一半的字也選進來時）**維持瀏覽器原生的選字反白**，
同一個顏色，不必自己畫，整排看起來仍是連續的一條。

## 拖曳歸誰

**拖曳留給重排，多選永遠靠鍵盤與修飾鍵。**

開票時的兩難是「點擊已經拿去觸發編輯了，拖曳選取怎麼辦」。但拖曳 chip **重排**（以後要做，
不在 v1）與拖曳**框選**搶的是同一個起手點 —— 按住一顆 chip 然後移動滑鼠 —— 一個手勢只能
有一個意思。裁決是給重排（使用者裁決 2026-09-13）：

這一排的東西**已經不是文字了**，它是一排有邊框、點下去會開選單、可以被拿起來改的**物件**，
編劇對這種東西的直覺來自檔案總管而不是 Word。而「看起手點分流」（chip 上 ＝ 重排、空白處
起手 ＝ 框選）聽起來兩全，實際上把「這一下會發生什麼」變成一個**像素問題**：縫只有幾 px、
輸入框尾端那塊是可點的插入區，起手差兩格意思就相反，而失手的代價一邊只是選取、
另一邊是**動到資料**。

所以本票**不做**任何滑鼠拖曳。這不是「還沒做」，是定案。

## 為誰讓路（本票不做，但形狀要接得上）

- **剪貼另開一票。** 方向已經定了（使用者裁決 2026-09-13）：`text/plain` 寫人名給外面的世界，
  **另加一份自訂 MIME 帶 `{ id, displayName }`** 給 app 自己；貼回同專案的別場就是同一批實體，
  **跨劇本**依 ADR-0005／CONTEXT 退回名字比對（同名接既有實體、沒有就建新的）；貼進內文一律純文字。
  ⚠️ chip 是 `scene` 的 **attrs**（`appearingCharacters`／`location`／`extras`，見 `schema.ts:153`）
  **不是 doc content** —— ProseMirror 的剪貼簿完全管不到它們，那張票一定得自己攔 clipboard 事件。
  本票要交出的東西只有一個：一個讀得到「現在選了哪些」的狀態。
- **任意子集的入口**（`⌘` 點選／`⇧` 點選）：資料形狀已經收得下，入口以後再開。
- **`⇧←→` 延伸選取**：同上。
- **拖曳重排**：見上，起手點已經留給它了。

## 驗收

- [ ] 游標在空的登場人物欄裡，`⌘A` 選滿整格（三顆 chip 連成一條反白），`⌫` 一次清空
- [ ] 輸入框裡有字時，第一次 `⌘A` 只選那串字，第二次才連 chip 一起
- [ ] 已經選滿整格時再按 `⌘A`，選取的是整份劇本（不是繼續停在這一格）
- [ ] 站在一顆 chip 上（用 `←` 走進去）按 `⌘A`，同樣選滿整格
- [ ] 選滿之後直接打字：chip 全消失、那個字進輸入框；`⌘Z` **一步**回到三顆 chip 且字不見
- [ ] `Esc`、方向鍵、點別處、欄位失焦，四種都解除選取，且沒有一種留下反白
- [ ] 選取狀態下點一顆 chip ＝ 解除選取並把那一筆拿回來改（與平常點它一模一樣）
- [ ] 四格都成立，包含只有一顆 chip 的對白人物欄與非雜景場次的地點欄
- [ ] 清空地點欄之後，該場次依 §5.3 落回自動草稿
- [ ] 反白是「每顆 chip ＋ 它們之間的縫」，不是欄位那一層的一塊矩形（子集斷得開）
- [ ] 讀螢幕軟體說得出「選了幾個」與「清空了」
- [ ] 滑鼠拖過一排 chip **什麼都不發生**（這是預期行為，寫一個測試釘住它）

## Comments

### 2026-09-13 — 開票

使用者回報：「欄位中的 chip 無法透過 cmd + A 全選，也無法透過拖曳游標來多選，但由於編輯
狀態可因點擊觸發，對於拖曳選取感到有點兩難。」

grilling 走完八輪，八個裁決都在上面。其中三個值得記在這裡，因為它們推翻了開票時的直覺：

1. **主要用途是「清空」而不是「挑幾個」**（Q1）。編劇要挑 chip 通常是挑「那一個」（改名／換人），
   要挑一群幾乎只有「全部不要了」。所以 v1 的入口只有 `⌘A`，不是一套完整的多選 UI。
2. **選取狀態仍然是一組 chip 而不是一個布林旗標**（Q2）—— 因為順序是偏好不是語意，
   以後要挑不連續的幾顆，而反白的畫法、刪除、序列化這三件事不管選一顆還是選全部都得寫，
   做成集合幾乎不多花什麼。
3. **原本那個兩難不是要解的題，是要記下來的決定**（Q8）。拖曳給重排，選取永遠不靠拖。
