# 97 — ⌘Z 在等的那一次重繪被無關的重繪吃掉，字回不到框裡

**What to build:** 實體欄位按 ⌘Z 撤掉剛定案的那一筆時，欄位記下「在等的那一次重繪」（`whenFieldBecomes`），
**只看下一次重繪**：refs 退回定案前的樣子就把那串字放回框裡，對不上就丟掉。
只要 ⌘Z 與 refs 真正退回之間**插進一次無關的重繪**（Enter 定案時還沒落地的 state 更新、自動存檔狀態……），
那次重繪的 refs 還沒變 → 判成「對不上」丟掉 → refs 隨後退回來時已經沒人在等。chip 撤了，字沒回來。

CI 在票 86 merge 後的 main 上撈到（`entity-field.test.tsx`「⌘Z 一次退回 Enter 之前的樣子」）：
本機單跑約 1/30 失敗、6 個平行跑時重現；加 log 看到的順序是 `key undo` → `effect [巷口,警局]`（丟掉）→ `effect []`（沒人等）。

**Blocked by:** 無

**Status:** done

## 定案（使用者 2026-10-28）

- [x] **無關的重繪不算數**：按 ⌘Z／⌘⇧Z 那一刻多記一份當下的 refs。重繪時 refs **跟按鍵時一樣** → 不是那一步，繼續等；
  變成要等的形狀 → 接手；變成別的樣子 → 丟掉。
- [x] **一直沒等到就在下一次操作這一欄時作廢**：⌘Z 撤的若是別的步驟，這一欄不會變，等待會一直掛著 ——
  之後編劇手動 × 到剛好同一個形狀，字會憑空回來。所以編劇在這一欄打字、按鍵、按 × 時清掉它。
- [x] 那條測試的兩個斷言一起放進 `waitFor`（原本只等 chip 消失就同步讀 `input.value`）。
