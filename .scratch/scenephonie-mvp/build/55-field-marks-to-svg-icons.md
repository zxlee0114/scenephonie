# 55 — 欄位裡那些記號換成一套風格一致的 SVG（chore）

**What to build:** `field-marks.ts` 裡那七個記號目前是 emoji（`📍 👤 👥 ＋ ✏️ ↩︎ ↰ ✅ 💡`），
換成一套免費授權的 SVG 圖示，風格一致、不吃系統字。

**Status:** open

## 為什麼

emoji 的問題不是難看，是**不受控**：

- **跨平台長得不一樣** —— 同一顆 `✏️` 在 macOS／Windows／Android 是三種顏色與三種粗細，
  而這些記號在這份 UI 裡是**有意義的區別**（見 `field-marks.ts` 檔頭），不是裝飾。
- **對齊與大小吃系統 emoji 字型** —— 與旁邊的中文字不同基線，選單列的高度會抖。
- **挑得到的字很少** —— 票券 48 第二輪要一個「唯讀提示」的記號，`✏️` 已經被「編輯動作」
  佔走，剩下的候選（`💡 ℹ️ ⓘ`）不是與欄位的 `ⓘ` 說明鈕撞，就是語氣不對。換成圖庫之後
  這種選擇不再是「emoji 裡還剩什麼」。

## 範圍

- 只換**記號本身**，措辭一個字都不動。
- `field-marks.ts` 現在回傳字串，被 `label` 樣板直接串進文字裡（`` `${MARK} 文字` ``）。
  換成 SVG 就不能再串字串 —— 這是這張票真正的工作量：標籤得變成「記號 ＋ 文字」兩段，
  而**測試整批在比對那串文字**（`rows()` 讀 `textContent`）。設計這個分界時要讓測試仍然
  讀得出「這一列在說什麼」。
- ⚠️ 記號是**可及性**的一部分：現在讀螢幕軟體唸得到 `✏️`，換成 SVG 之後要有 `aria-hidden`
  ＋ 文字自己說完整句話，或給 `<title>`。兩者擇一，不能都沒有。

## 授權

免費不等於可用。要挑**明確允許商用且不要求逐頁署名**的（MIT／Apache-2.0／CC0）。
候選：Lucide（ISC）、Heroicons（MIT）、Phosphor（MIT）。選定後把授權寫進 `docs/`。

## 驗收

- [ ] 一套來源、一種筆畫粗細、一種尺寸
- [ ] 九個記號都有對應，語意分界不變（見 `field-marks.ts` 檔頭與 `CONFIRM_MARK`／`HINT_MARK` 的註解）
- [ ] 讀螢幕軟體唸得出每一列在說什麼
- [ ] 授權與來源寫進 `docs/`
