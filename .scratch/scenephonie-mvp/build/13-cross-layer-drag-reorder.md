# 13 — 跨層拖曳排序

**What to build:** 拖曳是**明確的使用者意圖，不是誤觸**，所以可以做鍵盤路徑不准做的事。三個方向都允許（§7.5）：子場次拖到主場次之間 → 升級；主場次拖進場次內部 → 降級；區塊跨層拖。三個方向都**無損** —— `sceneId` 全程存活，變的只有推導出來的場次號。**必須拒絕的落點**：帶著子場次的主場次不能被拖進另一個場次（會生出第三層）—— UI 表現是**那些位置不畫落點指示線**，而不是允許放下再彈錯誤。`moveScene` command 自身也要拒絕非法目標（縱深：落點線擋滑鼠，command 的拒絕擋伺服器端呼叫與日後 API）。連帶成本（規格明列，必須連成本一起做）：繞過 `isolating`（`isolating` 保留 —— 拿掉會讓跨場次鍵盤選取與刪除把兩場合併、`sceneId` 錨點消失）；處理「搬走最後一個區塊」後的空場次（沿用「補一個空動作區塊」），含「主場次自己最後一個區塊被拖走、只剩一個子場次」的變體；跟 ProseMirror 原生拖放搶事件；落點合法性從「同 kind」改成**依位置計算**；`isolating` 多一層巢狀，鍵盤選取／刪除／貼上的邊界行為要重測。
