# 67 — 新增下一場時，可以改成貼上剛複製的場次

**What to build:** 按「新增下一場」時，如果剪貼簿最新的一筆是一整場（或幾整場），先問一句：
要新增**空白場次**，還是**貼上複製的場次**。選貼上就把那幾場插在這裡，換新的 sceneId，跟複製貼上一樣（§6.5）。
剪貼簿最新的一筆不是場次，就照原本的做法直接新增空白場次，什麼都不問。

**為什麼：** 使用者驗收票 13 時提出（2026-10-22）。整場的複製、貼上現在已經能用（點場次號選起整場 → ⌘C →
游標放到某處 → ⌘V），但入口藏在鍵盤操作裡，而且貼上的位置取決於游標在哪。「新增下一場」本來就是使用者
想多一場時會按的按鈕，在這裡接上剪貼簿，複製一場就順得多。

**Blocked by:** 13（點場次號選起整場、貼上拿掉場次外殼的規則都在那張票）

**Status:** needs-triage

## 開工前要定的事

- **怎麼知道「剪貼簿最新的一筆是場次」**：
  - 讀系統剪貼簿（`navigator.clipboard.read`）：Chrome 第一次會跳權限詢問，Safari 每次會跳一個「貼上」小按鈕，
    體驗都不像一個按鈕該有的樣子；Firefox 對 HTML 格式的支援也不完整。
  - 只記編輯器自己的「上一次複製了哪幾場」：不用權限，但使用者之後在別的 app 複製了別的東西，編輯器不會知道，
    會拿舊的那份出來問。
  - 折衷：記住上一次複製的場次，再用不需權限就能拿到的線索比對（例如複製後有沒有在別處發生過複製事件）。
  - 建議先做「只記編輯器自己的」，問句裡顯示那幾場的場次號與標題，讓使用者自己認出是不是要的那份。
- **問法**：用現在的 point menu 錨在按鈕上（兩列：空白場次／貼上「S3 外 日 公園」），還是確認窗？
  建議 point menu，跟降級時問種類同一套，Esc ＝ 空白場次還是取消要定。
- **剪下的場次**：剪下後再按「新增下一場」選貼上，算搬移（保住 sceneId）還是複製（換新 id）？
  照 §6.5「剪下貼上保住 id」應該是搬移，但那幾場已經從原處消失了，要確認使用者的預期。
- **複製多場**：一次貼上全部，還是只貼第一場？
- **跨劇本**：從另一份劇本複製的場次能不能貼？人物、地點等實體引用要怎麼對應（目前貼上的去重怎麼處理要先查）。
- 子場次、群組成員被複製時，貼成普通的主場次還是保留原本的層級。
