# 91 — 第一句是對白時，前面插不進一段描述

**What to build:** 場次第一個區塊是對白，編劇想在它**前面**插一段描述。現在的路：

- 人物欄最前面按 Enter → 進台詞（`nodes/blocks` 的 Enter ＝ 進台詞）；
- 台詞開頭再按 Enter → 前面切出**另一句對白**，不是描述（票 62 對稱化之後的行為）。

想插的只是一段描述，卻得先生一句對白再按 Tab 轉型 —— 不直觀。

**Blocked by:** 無

**Status:** done

## 定案（grilling 2026-10-27，與 82、89 一起跑）

下面「開工前要定」的最後一條就是答案：問題的核心在 chip row 的 Enter 只會「走進去」、不會「生出一行」。

- [x] **chip row（群演欄）按 Enter ＝ 在內文最上方插一個新區塊，游標進去。** 第一個區塊本來就是空的，直接落進那個空區塊，
  不再多生一個。
- [x] 新區塊**一律是描述**（action）—— 要寫對白就 Tab 轉型（現行規則）。不照 `continue-block` 延續第一個區塊的型別：
  91 要的正是在對白前面插描述。
- [x] chip row 的 **Tab** 不變成插一行 —— 照順序走到第一個區塊（是對白就落人物欄，見 89）。Enter 與 Tab 從此分家。
- [x] 人物欄的 Enter（進台詞）、台詞開頭的 Enter（62：切出另一句對白）**都不動**。

**排在 82、89 之後**；與 89 都會動 `nodes/scene` 的 `enterBody`。

## 從哪來的

票 61 瀏覽器驗收時使用者提的（2026-10-27）：「Enter 現在在對白人物區塊的最前方的行為是到台詞的區塊，
再按一次會在前方造出另一個對話區塊，如果只是想要安插一個敘述在前方，似乎不是很直觀」。與 61 的方向鍵無關。

## 開工前要定（要做時再拷問）

- 哪一個手勢該是「在前面插一行」：人物欄最前面（有 chip 時游標在第一顆左邊）按 Enter？台詞開頭按 Enter？
  還是另一顆鍵？人物欄的 Enter 現在是「這一格好了，去台詞」—— 改掉它會碰到「打完人名按 Enter」這條主路徑。
- 插進來的那一行是什麼型別：一律描述（action）？還是看上下文（`continue-block` 的「下一個區塊型別」規則）？
- 一般文字編輯器的直覺：段落開頭按 Enter ＝ 在上面插一個空段落、游標留在原本那一段。要不要照這一條？
  與票 62「台詞開頭 Enter 切出第二句對白」怎麼並存？
- 只有第一個區塊會碰到嗎：中間的對白前面插描述，可以從上一個區塊末端 Enter 達成 —— 第一個區塊上面是
  chip row，從群演欄 Enter 是進內文（不是插一行）。這一條也許是問題的核心。

## Comments

**實作（2026-10-28，與 89 同一條分支）**

- 群演欄的 Enter 走 89 留下的 `ChipNav.enter` 出口 → `nodes/scene` 的 `insertBodyTop`：在第一個區塊之前插一段空描述、游標進去；
  一般的 transaction（同 `continue-block` 插一句的寫法），⌘Z 一下收回。
- 「第一個區塊本來就是空的」照字面收窄成**空描述**：空的對白／插入畫面不算 —— 要的是一段描述，就在它前面插。
- 群組：最後一個成員的群演欄 Enter → 第 1 段片段最上方（片段歸屬不動）；前面成員的 Enter 照舊去下一個成員那一排。
- 群演欄還有字沒定案時，第一下 Enter 照舊是定案成 chip，再一下才插（票券 34 的「這一格好了」）。
- ⌘↓ 不受影響：照舊直接進第一個區塊的內文。
