# 44 — expand：人數的四種樣子先與 `count: number` 並存

**What to build:** 把「人數」從一個 `number` 變成**一個有好幾種樣子的值**（票券 41 的核心
裁決），但**這一張票什麼畫面都不改**。做法是 expand–contract 的第一步：新形態**加在舊的旁邊**，
舊的一個字都不動，所以全部既有呼叫點照常編譯、CI 一次都不紅。

理由是 blast radius：`ExtraRef.count` 被 schema、command、群演欄、對白人物欄、升格措辭、
九個測試檔讀寫。一次換型別會讓整棵樹同時紅，那不是 tracer bullet 做得完的事，也沒辦法
「做完一半還能 demo」。所以先讓兩種形態並存，再一批一批把呼叫點搬過去（票券 45–49），
最後才刪掉舊的（票券 50）。

**Blocked by:** 無 —— 可以立刻開工

**Status:** ready-for-agent

## 四種樣子

| 樣子 | 編劇打的／選的 | 印出來 |
|---|---|---|
| 確切 | `8` | `路人（8）` |
| 區間 | `3-5`、`3~5` | `路人（3-5）` |
| 下限 | `10+` | `路人（10+）` |
| 若干 | 「若干」那一列 | `路人（若干）` |

「若干」**不是「未填」的委婉說法** —— 它是編劇自己寫劇本時就在用的寫法（「一些人」「數人」
同義），是一個他真的會選的答案。這一點是整個型別形狀的來源：人數不是「`number` 或 null」。

型別有 tag、不用可選欄位，因為 attr 不允許 undefined（§6.6）。

## 這一張票的第二件事：把「人數輸入」切成兩層

票券 41 第二輪之後，這張票的重心有一半在**那一行唯讀提示說什麼**（空著時是格式說明、
打了字是預覽、讀不出來是警告）。那是一個純函式，但它混了兩件事：**狀態解析**與**文案生成**。
兩層切開（使用者裁決 2026-09-12），否則每一種輸入都得用 jsdom 打字、讀 DOM 才測得到。

```
resolveCountInput(text) →
  | { state: "empty" }
  | { state: "parsed"; value: CountValue }
  | { state: "unreadable"; raw: string }

countHintText(result, fallback: CountValue, description: string) → string
countLowerBound(value: CountValue) → number | null      // 若干回 null
```

- `resolveCountInput` **不含任何中文** —— 它只認符號與數字
- `countHintText` **不含任何解析規則** —— 它只把狀態翻成話
- `fallback` 是「現在離開會記成什麼」：新增時是若干，修改時是原值（票券 41 第七、九輪）

切開的第二個好處：票券 40 第一列的 `✏️ 把「A」改成「B」` 要的是同一組值的另一種措辭，
它可以直接吃 `CountValue`，不必再走一次解析。

## 放寬解析（編劇提，票券 41 第二輪）

- 全形數字 `８` —— **已經有了**（`extras.ts` 的 `halfWidthDigits`），沿用
- 全形符號 `＋`／`～`／`－`／`—`／`〜` —— 要補，注音鍵盤打出來的就是這些
- 中文數字（`三`、`十`、`廿`、`數十`）—— **先不做**（使用者裁決 2026-09-12）。
  `十` 與 `十幾`、`二三十` 的邊界是另一個問題，而「數十」其實就是「若干」那一格想講的事。
  這條理由要寫進註解，不然下一個人會再問一次。不做不等於要擋：讀不出來就整串當描述，
  那條路已經在了。

## 並存怎麼並存

`ExtraRef` 多一個欄位裝新形態，`count: number` 原封不動留著。`sceneExtras`（讀取路徑的
正規化）兩邊都填得出來：舊資料只有數字時，新形態由它推出「確切 N」；反過來新形態存在時，
舊欄位填得出一個數字就填（下限、區間用下限；若干用 1）。

⚠️ **那個舊欄位在遷移窗口裡會說謊**（`路人（3-5）` 的舊欄位是 3）。這是 expand–contract
的已知代價，可以接受的條件是**沒有人再讀它**：票券 45–49 每搬完一批，讀它的地方就少一處，
票券 50 把它整個刪掉。所以這一串票**不要停在中間**。

## 驗收

- [ ] `CountValue` 四態齊全，有 tag，沒有可選欄位
- [ ] `resolveCountInput` 三態；`8`／`3-5`／`3~5`／`10+` 都讀得出來，全形數字與全形 `＋～－—〜` 一樣認
- [ ] `路人 8` 這種裸數字尾綴**不解析**（票券 43 的 ADR）
- [ ] `countHintText` 三態文案：空是格式說明、parsed 是預覽、unreadable 是警告**而且說得出現在離開會記成什麼**
- [ ] `countLowerBound`：確切回自己、區間與下限回下限、**若干回 `null`**
- [ ] 兩層真的分離：`resolveCountInput` 的測試裡沒有中文文案，`countHintText` 的測試裡沒有解析規則
- [ ] 全部測試在 Node 上跑，不需要 jsdom
- [ ] `ExtraRef` 新舊兩個形態並存，`sceneExtras` 兩邊都填
