# 26 — 重整後焦點落在文件末端（upkeep）

**What to build:** 進入 `/editor` 時，焦點與游標落在**文件內容的最後面**（最後一場的最後一個區塊末端），而不是第一場的「內外景」欄。

**為什麼是現在：** 票券 04 訂下「進入編輯器時焦點落在第一場的內外景欄」（§7.1），當時那是對的 —— 那時每次進站都是一份全新的空劇本，第一場就是唯一一場。票券 05 讓劇本會被存下來之後，這個行為的語意變了：使用者重整回來看到的是一份寫到一半的稿，游標卻被丟回開頭，等於每次重整都要自己捲到底、再點一下才能接著寫。

**這不是把 §7.1 推翻**，是把它的適用範圍講清楚：**新建的劇本**焦點落在第一場的內外景欄（那是「請你先填這裡」的引導）；**載入既有劇本**焦點落在文件末端（那是「你上次寫到這裡」）。兩者的判準都是「手不必先去點一下才能開始工作」。

**Blocked by:** 05（persistence 模組；焦點要分兩種情形，得先有「載入既有劇本」這件事）

**Status:** ready-for-agent

## 影響檔案

- `apps/web/src/editor/use-screenplay-editor.ts` —— `onCreate` 目前無條件 `requestFocus({ kind: "sceneMeta", sceneId: first })`；要能分辨「新建」與「載入既有」
- `apps/web/src/editor/focus.ts` —— 可能需要新的 `PendingFocus` 種類（例如 `{ kind: "documentEnd" }`），或直接用 `editor.commands.focus("end")`
- `apps/web/src/app/editor/page.tsx` —— 「這份劇本是剛建的還是載回來的」這個事實只有伺服器端知道，需要往下傳

## 待決

- 「新建 vs 載入」怎麼傳到編輯器？`loadOrCreateSoleScreenplay` 目前不回報它走了哪條路。最小改法是讓它多回一個布林；也可以由編輯器自己判斷（doc 只有一場且該場為空 ＝ 新建），但那是用形狀猜意圖，比較脆。傾向前者。
- 捲動：`focus("end")` 會把游標捲進畫面，但落點是「剛好可見」還是「畫面中央」與票券 27 相關，兩張票的驗收要對齊。

## 驗收

- [ ] 載入一份既有的、超過一個畫面高度的劇本，進站後游標在最後一個區塊末端，且該處在可視範圍內
- [ ] 進站後不必點擊或按鍵即可直接輸入，輸入內容出現在最後一個區塊末端
- [ ] 新建劇本（資料庫沒有任何劇本）時，焦點仍落在第一場的內外景欄（§7.1 不回歸）
- [ ] 焦點串接的既有測試（`scene-chips-focus.test.tsx`）不回歸
- [ ] `pnpm lint` / `typecheck` / `test` / `build` 全綠
