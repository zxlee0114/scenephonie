# 58 — 單值欄定案之後，游標卡在 chip 前面

**What to build:** 非雜景的地點欄（單值）拿起 chip 改完、按 Enter 定案，**輸入框留在那顆 chip
的前面**：

```
|[📍 派出所]        ← 現在
[📍 派出所]|        ← 該有的樣子
```

單值欄只裝得下一筆，輸入框的家就是隊尾 —— 沒有第二筆可以排在它後面，所以「游標停在前面」
沒有任何情境撐得住它。對白人物欄同一支元件、同一個症狀。

**Status:** done

## 從哪來的

票券 52 的人工驗收（2026-09-24）。與 52 無關 —— 52 動的是候選清單與那一列的樣子，這一條是
`merge` 的游標歸位，從票券 39 收票「放回去要回原位」那一條就在了。

## 根因

`caret` 記著手上那一筆原本站的那一格（票券 39：`a b |c` 裡把 b 放掉，游標留在那一格），而
`reset()` **刻意不清它** —— 註解寫著「`merge` 剛把它挪到新 chip 之後，那就是游標該在的地方」。
多值那條路確實挪了（`caret.current = at + added.length`），但**單值那條 early return 沒有**：

```ts
if (!multiple) {
  commit([added[added.length - 1]!], null);   // ← caret.current 還是 0
  return;
}
```

於是 `inputAt = min(0, 1) = 0`，輸入框渲染在 chip 前面。它傳給 `commit` 的 `at` 本來就是
`null`（隊尾），只是沒同步回 ref —— 同一件事兩個真相。
