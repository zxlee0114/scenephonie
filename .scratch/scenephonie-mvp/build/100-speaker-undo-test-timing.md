# 100 — 對白人物欄 ⌘Z 的兩條測試在 CI 上 flaky

**What to build:** 票券 98 merge 後 main 的 CI 紅在 `dialogue-speaker.test.tsx`「「↓ 移到台詞」之後的 ⌘Z」：
`expected '' to be '你不說話。'`。本機 6 個平行跑重現（48 次 4 次失敗）。產品行為沒問題，是測試的兩個時序：

1. **文件退回就同步讀框**：⌘Z 的文件那一側是同步的，字要等欄位下一次重繪才放回框裡（同票券 97 那條測試）。
   同樣寫法的還有「點走時搬進台詞的那一下也撤得回來」。
2. **⌘Z 按在 Enter 的焦點落地之前**：Enter 進台詞的 `focus()` 被 Tiptap 延到下一個 animation frame。測試只等台詞
   的字出現就撤 —— 機器忙時那一幀在撤銷把焦點交還人物欄**之後**才到，又把焦點拉回內文。真人按不出這麼快的 ⌘Z。

與 98 的改動無關：這兩條直接呼叫 `editor.commands.undo()`，不經按鍵那條路。

**Blocked by:** 無

**Status:** verified

## 定案

- [x] 兩條測試的「文件退回」與「字回到框裡」放進同一個 `waitFor`。
- [x] 「↓ 移到台詞」那條先等焦點落進內文再撤（照隔壁「台詞裡一次 ⌘Z」的寫法）。
- 驗證：同樣平行跑 60 次 0 失敗；web 全套 1072 passed。

## 從哪來的

票券 98 merge 後 main 的 CI（PR #115 那一輪同一份程式碼是綠的）。
