# 場次表與拍攝表單的真實欄位

Type: research
Status: resolved

## Question

實務上的**場次表（分場表）**到底有哪些欄位？其中哪些能純從劇本推導，哪些需要額外標註？

這張票決定 v1 場次表的規格，也決定資料模型要為第二層預留哪些擴充點。

素材：

- 拍攝常用表單總覽（HTML）— `https://papiin.com/article-detail-148`
- 真實場次表範例（實為 .docx，非 PDF）— `https://drive.google.com/uc?export=download&id=1SH3wINxC7f_h7mmDr2FCPUhcZARanZsk`

必須回答：

1. **場次表的完整欄位清單**
2. **每個欄位分層**：
   - **第一層（投影）** — 純粹從劇本推導，零新增資訊
   - **第二層（標註）** — 需要人另外填，但仍掛在場次上
   - **第三層（外部）** — 劇本裡根本沒有的資訊（演員檔期、場地、預算）
3. **papiin 頁面上還有哪些拍攝表單？** 各自與場次是什麼關係？
4. **這些表單如何識別場次？** 用場次號，還是別的？

第 4 點特別重要 — 如果業界表單一律以場次號互相參照，而場次號會因重排而變動，那「場次是穩定錨點」這條約束就需要一個對外的顯示層與對內的 id 分離設計。

產出：欄位分層對照表。第一層清單直接成為 v1 場次表規格；第二層清單成為資料模型的預留擴充點。

## Answer

完整研究報告：[`../research/scene-breakdown-fields.md`](../research/scene-breakdown-fields.md)

**1. 真實順場表為 14 欄：** 場景、場次、光、景、劇情概要、男一～女三、其他演員、美術道具、備註。

**2. 重大發現 —「男一～女三」欄填的是服裝代號，不是出席勾選。**
文件底部註解揭露這些欄位填的是服裝代號（如 `B1`/`B2` 表示同一人物的不同服裝版本）。也就是說，業界表單把「誰出場」與「穿哪套」**壓縮在同一欄**。這反而印證了分層模型：出席是第一層（可從劇本推導），服裝版本是第二層（需另外標註）。v1 只做第一層，不碰服裝，是對的。

**3. 欄位分層：**
- **第一層（投影）**：場次號、內／外、日／夜、地點、登場人物（出席語意）、~~摘要~~ ⚠️ **摘要已於 2026-08-18 移出第一層** — 作者指出順場表的劇情概要多由製表者撰寫，且編劇通常不逐場填寫，故非可靠投影。見 `CONTEXT.md`「摘要」詞條。
- **第二層（標註）**：服裝代號、美術道具、備註、預估時長
- **第三層（外部）**：演員檔期、場地租借、預算、天氣、通告單時間地點、後製技術參數

**4. papiin 列出 30+ 種拍攝表單，但只有一小群真正掛在單一場次上**（分場大綱、對白本、順場表、道具需求表、劇本計時樣表）。多數（拍攝計劃表、通告單、拍攝順序表、剪接編輯表）是跨場次重組，或完全獨立於場次結構（合約、預算、器材技術紀錄）。這佐證了「第三層是另一個產品」的判斷。

**5. 第 4 點（表單如何參照場次）— 明確答案：清一色用場次號。**
場記表明文欄位含「場次、鏡號」，拍片行事曆含「場次」，順場表第 2 欄就是「場次」。**調查到的表單中，沒有任何一個使用獨立於顯示序號之外的永久識別碼。**

### 對地圖的影響

「場次是穩定錨點」這條約束，**在業界沒有現成範本可循** — 它是我們要主動自建的機制，不是照抄慣例。這同時意味著：重排場次後下游文件對不上，是業界真實存在且未解的痛點，可能是本產品的隱藏賣點。

（研究報告將此推論標為中信心：只確認了「用場次號當 key」這個事實，未直接觀察到業界重排後如何同步下游文件。）

### 未解的三處

報告明確列為不確定、未強行分類：
- 「場景」欄與「景」欄的語意分別為何（14 欄中兩者並存）
- 「劇情概要」是否算第一層
- 群演如何歸屬
