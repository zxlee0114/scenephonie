# 草稿場次

Type: grilling
Status: resolved

## Question

空場次要怎麼處理？作者的構想：為場次加入「轉為草稿」的選項，草稿不進最終輸出；儲存時若場次沒填內／外、時間、地點或劇情，自動轉成草稿；草稿與正式場次要有視覺區隔。

要回答：草稿參不參與編號？「自動轉換」會不會跟使用者搶方向盤？草稿進不進場次表？

## Answer

### 1. 草稿不是一個要「轉換」的狀態，是**推導出來的**狀態

```
是草稿 = 使用者手動標記為草稿  或  metadata 不完整
```

**否決了「儲存時自動轉換」。** 理由：編劇很可能先寫劇情、metadata 後補，自動儲存會在他還在寫的當下把場次降級 —— 有東西在你背後改你的文件。改成推導之後就沒有「觸發時機」這個問題：欄位填完它自己變回正式場次，想把一場填得好好的戲壓成草稿就手動標記蓋過推導結果。

資料模型只多一個 `manualDraft` 布林值，**不存狀態機**。

### 2. 草稿不參與正式場次編號，但有自己的推導標籤

場次號的定義就是**輸出的顯示序號** —— 不進輸出的東西沒有序號可言。草稿被 `projectScenes()` 跳過，後面的正式場次照常往前遞補。這是免費的：場次號本來就是純函式算出來的，錨點掛在 `sceneId` 上，草稿轉正式時整批重編號完全無害。

**草稿標籤錨定在「前一場」，不是後一場**：`S11[D1]`、`S11[D2]`，然後下一個正式場次是 `S12`。

> 作者原本提的是 `S12[D1]`（錨定後一場）。**會撞號** —— 那個下一個正式場次本身就是 `S12`，文件裡會同時有 `S12[D1]` 和 `S12` 兩個東西頂著 12。改錨定前一場後不撞號，「它在 S11 後面」的定位資訊完整保留。

邊界情況：草稿排在全劇第一場之前 → `[D1]`（沒有前一場可錨）。

### 3. 草稿標籤也是推導值，任何旗標都掛在 `sceneId` 上

`S11[D1]` 跟場次號、子場次編號一樣是算出來的 —— 把那場草稿拖到別的位置，它就變成 `S3[D2]`。所以「不再提醒」記的必須是 `sceneId`，標籤只負責在彈窗裡讓人看懂是哪一場。

**這是約束 1 在本效力中第三次以同一形狀出現**：場次號、子場次編號、草稿編號都是推導值，都不進資料庫。

### 4. 草稿不進場次表

理由同不進 PDF：場次表是給製片看的，草稿是還沒想好的東西，讓製片看到只製造雜訊。

### 5. 草稿的子場次跟隨父場次

父場次是草稿 → 子場次一律是草稿。子場次可以單獨是草稿而父場次不是。（見票券 09）

### 6. 匯出防呆

彈窗的語意是**「這份 PDF 會少掉這幾場」**，不是「要不要輸出這一場」—— 草稿本來就不輸出。

```
本次輸出會略過 2 場草稿：
 ☐ S11[D1]「小明在雨中奔跑……」— 未填寫內／外、地點
 ☐ S17[D1]「……」— 手動標記為草稿
 ☐ 全選　　[ 之後不再提醒勾選的場次 ]
```

- **列出時要附內容首行摘錄**。草稿常常正是 metadata 沒填的那些場次，`S11[D1]` 對編劇來說是個空號，首行文字才是他認得出來的東西。
- **支援多選與全選**（作者要求）。
- **即使全部勾了「不再提醒」，輸出完成後仍要顯示一行「本次略過 N 場草稿」** —— 不擋流程、不需點掉。靜默地少印幾場，對一個要拿去投劇本獎的人是最糟的失敗模式；防呆的價值在這裡，不在彈窗本身。

### 7. 視覺區隔

草稿與正式場次在編輯器中要有視覺區隔（作者要求）。具體樣式屬原型打磨，不在此決定。
