# 插入的階層化：子場次

Type: grilling
Status: open
Blocked by: 07

## Question

插入現在必須裝得下「一小段有自己時空的戲」，而 metadata **正是場次的身分判準**（`CONTEXT.md`：時空變了，依定義就是另一個場次）。所以這不再是區塊型別的問題 —— 而是**場次序列要不要有階層**。

### 已定的方向（2026-08-21，作者裁決）

- **做階層**，深度**固定兩層**：主場次 → 子場次，子場次不能再有子場次。需要多個插入（蒙太奇）時水平展開，不遞迴。
- **子場次會出現在場次表上**。決定性論證：場次 metadata 只有兩個消費者 —— 場次表與 PDF 場次標題。若子場次不進場次表，它的 metadata 就沒有任何人看得到，是白工，而且會讓編劇誤以為製片看得到。「有 metadata」與「進場次表」必須同進同退。
- 作者的理由是製作面的：額外的場景需求必須讓製片知道。

### 背景：這是「插入戲」以更好的形狀回來

當初砍掉 `S5A` 的理由是「字母尾綴是假保護：搬移一次 `S5A` 就變成 `S2A`」。**父子關係沒有這個毛病** —— 子場次跟著父場次一起搬，語意不會說謊。同一個需求已經反覆出現三次（S5A → 塞進插入鏡頭 → 父子場次），它是真的。

地圖上「插入戲｜Out of scope」那一條已於 2026-08-21 撤銷。

### 要回答

1. **子場次的編號形式**（`S5-1` / `S5A` / 其他）。它是從父子關係**推導**出來的顯示值，不進文件也不進資料庫 —— 與場次號同一條規則。
2. **子場次在場次表上是獨立一列還是附屬列？** 排序位置？
3. **Tiptap schema 怎麼表達兩層？** `scene` 的 content 從 `sceneBlock+` 變成什麼？子場次是另一個 node type 還是同一個 type 帶深度屬性？
4. **拖曳跨層**：子場次能不能拖出來變主場次？主場次能不能拖進去變子場次？票券 03 那批 dnd bug（`isolating`、跟 PM 原生拖放搶事件、搬走最後一個區塊）會不會整批重來？
5. **刪除父場次時子場次怎麼辦？**
6. **metadata 繼承**：子場次預設帶入父場次的值 —— 快照還是連動？
7. **`@S5` 帶入被引用場次的 metadata** —— 快照還是連動？（注意：場次引用**本身**必須連動，因為場次號是算出來的顯示值，存字串會在重排後集體說謊。）
8. **PDF 上子場次的場次標題長什麼樣？** ⚠️ 票券 01 查證過：**三份台灣格式範本完全沒有觸及插入場次的情境**，沒有範本可循，這裡要自己發明。這是階層化的真實成本，會在 PDF 匯出時咬人。
9. **對票券 07（穩定錨點）的影響**是什麼？

### 不在這張票內（已定，不重議）

- 區塊型別「插入鏡頭」更名為**「插入畫面」**，只裝單一畫面描述。防線從「嚴格限定單一鏡頭」改寫成**不得長出運鏡、景別等欄位**（那條線本身不變，只是換一種守法）。長插入走子場次。
- 輸出時渲染為 `INS` 屬 PDF 模板決策（架構約束 2：呈現性資訊不進資料模型），歸票券 01／05。
