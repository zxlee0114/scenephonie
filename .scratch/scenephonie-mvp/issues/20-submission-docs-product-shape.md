# 交件文件在產品裡的形狀：人物介紹、交件大綱、關係圖

Type: grilling
Status: claimed
Blocked by: 18, 22

## Question

從[票券 18](./18-submission-documents-format.md) 畢業（2026-08-30）。票券 18 是 research，把**可查證的事實**全查完了 —— 單一 PDF、四區段順序、浮水印規則、字數上限。剩下三件是**產品決策**，research 不代答。

### 已經是事實、不必再議的部分（票券 18 已定）

- 交件是**單一 PDF**，順序固定：標題頁 → 長版劇情大綱 → 人物介紹 → 劇本內文，各自獨占一頁。
- **交件大綱不能從場次推導** —— GHSA 上限 800–1200 字，130 場的劇本每場一句就爆掉。
- **GHSA 明文禁止圖片**（含照片、關係圖）；**BAMID 明文可附人物關係圖**。兩者互斥。
- 人物介紹的**欄位與字數，兩個獎都留白** —— 沒有範本可抄，這正是要決定的原因。

### 要回答

1. **人物介紹在產品裡是什麼？** 票券 10 已定資料形狀（有序的人物引用清單，介紹內文放在**人物實體**的描述欄位上）。但那個描述欄位在 UI 上是**一個自由文字框**，還是**欄位化的表格**（年齡／職業／與主角的關係）？欄位化能讓 PDF 排得整齊，但它同時是**對編劇的負擔**，而且沒有任何獎項要求那些欄位。判準應該沿用 ADR-0006 那條：「欄位可以加，只要那一欄的值是編劇本來就會產生的副產品；不能加的是負擔。」

2. **交件大綱在產品裡是什麼？** 它不是分場大綱（那是另一份、已定為自由文字文件），也推導不出來。所以它是 `documents` 表的**第三個 `kind`**（票券 04 已預留這條路：「票券 18 若長出劇情大綱／故事大綱，加 `kind` 即可」）嗎？還是它根本不進 v1、由編劇自己在 Word 寫好貼進來？
   ⚠️ 注意 BAMID 的粒度是**四層**（logline ≤50 / 短綱 500–1000 / 完整故事大綱 5000–10000 / 分集大綱每集 600–800）。v1 要做幾層？這正是「一條路走通，但不堵死岔路」的典型場合。

3. **人物關係圖要不要做進 v1？** 傾向是**不做**（GHSA 直接禁止，做了在最主要的投稿情境用不上），但要確認：BAMID 那條「可附」是不是強到值得？若不做，v1 的 PDF 匯出要不要留一個「插入自備圖片頁」的逃生口？

4. **有圖／無圖必須跟著輸出目標走** —— 這意味著匯出時要選「投哪個獎」嗎？那會不會長成一個獎項清單，變成要**跟著簡章逐年維護**的東西（GHSA 的浮水印文字含屆別，票券 18 已指出它必須是可輸入參數）？還是只給一組開關（浮水印／關係圖／登場人物），讓編劇自己對照簡章勾？

### 不在這張票內

- **人物與地點的資料模型** —— 票券 10 已定，見 [ADR-0005](../../../docs/adr/0005-entities-exist-by-reference.md)。
- **PDF 的技術管線** —— 票券 05 已定 Puppeteer；票券 18 已確認單一 PDF 不需要 pdf-lib 合併層，模板形狀的四條規則也已寫定。
- **分場大綱要不要結構化** —— 地圖已定 v1 做成自由文字文件。
