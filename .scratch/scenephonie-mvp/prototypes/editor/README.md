# 編輯器原型 —— 丟棄式

回答票券 [區塊編輯器選型與 /scene 輸入體驗](../../issues/03-editor-prototype.md)。

**這是丟棄式程式碼。** 驗證完把結論寫進規格，程式碼不進真實專案。

## 跑起來

```bash
cd .scratch/scenephonie-mvp/prototypes/editor
pnpm install   # 只需第一次
pnpm dev
```

開 http://localhost:5173/

## 要驗什麼

### 1. 心流 —— 這是驗收標準

寫幾段真的劇本，不要只點來點去。**如果你自己都不想用這個東西寫東西，就是失敗**，該換方案而不是硬幹。

- <kbd>Tab</kbd> 循環切換區塊型別：動作 → 對白 → 插入鏡頭 → 動作
- <kbd>⌘</kbd>+<kbd>Enter</kbd>、`/next`，或場次腳部的按鈕 → 新增下一場

Tab 循環是刻意的設計選擇：動作與對白在寫作時交替太頻繁，每次都打斜線指令會毀掉心流。這是 Final Draft 那類軟體的做法。

### 1b. 場次之外不能打字

文件的 schema 是 `scene+` —— **場次是唯一的撰寫單位，場次之外沒有可編輯的空間**。試著把游標移到場次之間，或在文件最後面打字，都做不到。

這是把架構約束 1 從「靠慣例維持」升級成 schema 保證：任何文字都必然屬於某個場次，下游投影不會遇到不知道該歸給誰的孤兒段落。

指令也因此從 `/scene` 改名為 `/next`：你永遠在某個場次裡打字，「在場次裡建立場次」語意很怪，真正的動作是序列性的 —— 再開下一場。

**已知代價**：匯入既有劇本沒有落地區（貼上的散文無處可去）。匯入已排除在 v1 之外。

### 2. 三種 metadata 輸入方式（底部切換）

| 變體 | 做法 |
|---|---|
| **A · 內嵌簡表** | metadata 直接嵌在編輯器裡，像一列簡表 |
| **B · 側邊面板** | 編輯器只有唯讀摘要，游標所在場次在右側編輯 |
| **C · 漸進填寫** | <kbd>⌘</kbd>+<kbd>Enter</kbd> 觸發，不離開鍵盤依序問內外→時間→地點→人物 |

問的是：**哪一種在寫作途中最不打斷思路？**

### 2c. 重排與刪除

- **⠿ 拖曳** —— 場次可拖，場次內的動作／對白／插入鏡頭也可拖，且**能跨場次**。
- **點場次號 `SX`** —— 搬移到⋯（抽出來插到別處，其餘遞補）／與其他場次對調⋯（兩場互換，其餘不動）／刪除這一場（只剩一場時 disabled；確認彈窗內有「下次不再提醒」）。目標清單可用場次號、地點或人物篩選。

拖曳刻意不走 ProseMirror 內建的拖放：場次是 `isolating`，內建行為會擋掉跨場次搬區塊。`isolating` 要留著 —— 它保護的是鍵盤選取、刪除與貼上，那些才是會誤傷 sceneId 錨點的路徑。拖曳是明確的意圖，不是誤觸，所以自己算落點、自己送 transaction（`src/dnd.ts`）。

⚠️ **拖曳排序在地圖上仍屬 Out of scope**，做出來只是為了讓你用手感判斷值不值得拉回 v1。

### 3. 場次號是算出來的，sceneId 才是持久的

右側「場次表」是同一份資料的投影，零新增資訊。

**用場次表的 ↑↓、拖曳，或 `SX` 選單重排場次**，然後看：

- 場次號會變
- `sceneId` 不會變

這就是架構約束 1「場次是穩定錨點」。整份程式碼裡**沒有任何地方存過場次號** —— 它在 `numbering.ts` 即時算出來，編輯器裡的顯示透過 ProseMirror decoration 供給（不是節點屬性，見 `scene-schema.tsx` 的 `SceneNumbers`）。

### 3b. 沒有插入戲（S5A）—— 2026-08-20 拿掉

編號永遠是 1..N。字母尾綴是業界用來繞過「重新編號會讓已發出去的下游表單失效」的 workaround，而那個洞正是架構約束 1 要填的。原型也證實它是假保護：**S5A 一被搬走就變成 S2A**。

真正的觸發點不是「我要插一場」，是「這一版已經交出去了」—— 那是版本鎖定，不是場次屬性。字母尾綴應該是它的衍生結果。這個範圍決定交給票券 07。

（**插入鏡頭**這個區塊型別留著，那是票券 08 另一半的結論，是兩件事。）

### 4. 複製貼上會破壞錨點（已知缺陷，刻意留著）

選一整個場次複製貼上。場次表會標紅並警告：**貼上的複本沿用了原本的 sceneId**。

勾選底部「自動修復重複 id」再試一次，就修好了。

這是刻意做成可切換的 —— 因為它是個真實陷阱：sceneId 存在 node attribute 裡，而 attribute 會跟著複製貼上一起被序列化。**要有一個 `appendTransaction` 外掛主動去重**，不會自己好。

### 5. 沒有粗體斜體

`StarterKit` 裡的 bold / italic / strike / code 全部關掉了 —— 架構約束 2 說資料模型不含呈現性資訊。想確認「劇本內容純粹是結構 + 文字」的感覺對不對。
