# 交叉場次以場次群組表達，成員各佔頂層場次號

交叉場次（對剪：兩個以上的地方同時發生、交替著讀）在 v1 範圍內，**以場次群組表達**：

**群組 = N 個平行的成員場次 + 一串有序的片段**，每個片段標記它屬於哪一個成員。

成員場次就是**普通的場次** —— 各自完整的單值 metadata、各自的永久 id、各自一個**頂層場次號**（`26`、`27`、`28`），在場次表上各自一列。**群組本身不佔場次號、不進場次表**，它只影響 PDF 的印法與編輯器的操作。

群組存在的理由**只有一個：保住交錯**。片段的先後順序是推導不出來的真資訊，必須存下來。凡是不交錯的情境都不該用群組。

## 這條決策的前提

在資料模型裡，`警局偵訊室` 和 `港邊倉庫` **本來就是兩個場次** —— 場次的定義（時空一變就是新場次）不必為此鬆動。劇本把它們寫成一個場號是**呈現層**的事，為了讓讀者不必在兩場之間來回翻。

這個前提同時保住了兩樣東西：場次 metadata 全部維持**單值**（沒有「多值地點」這回事，雜景除外，見下），以及**「場次表是零新增資訊的投影」** —— 每個成員自帶完整 metadata，製作端要的資料是推導得出來的，不是製作端另填的。

美式對 INTERCUT 分裂成兩種寫法，而**製作端一致否決「一個 heading 裝兩地」那一種**：

> INTERCUT is just a shortcut where the writer doesn't have to repeat the SLUGS… but in production there are no shortcuts. If you put all the SLUGS in the script (with individual scene numbers), the Final Draft scene report will show each location with its separate scene numbers.

我們的加值**不在拓樸**（拓樸就是美式的寫法 A），而在於**美式靠編劇自律才寫得對** —— `INTERCUT` 之後的交替對白不寫 slug，哪一句在哪裡全靠讀者從人物推。我們每個片段都標記歸屬，**結構上不可能寫錯**。

## Considered Options

**群組佔一個場次號，成員推導出 `26A`／`26B`。** 否決。其一，`26A` 正是 [ADR-0002](./0002-scene-id-and-derived-scene-numbers.md) 與 [ADR-0003](./0003-inserted-scenes-as-subscenes.md) 兩度否決掉的字形 —— 這裡的 `26A` 確實是推導的、不會說謊，但它跟被否決的東西長得一模一樣，日後每次都要重新解釋一遍。其二，產品裡會出現**三種**編號形式（`26` 場次、`5.1` 子場次、`26A` 群組成員）。其三，`26A` 在美式是**鎖本之後的修訂編號**，與對剪無關，借過來用是誤植。

成員各佔頂層號的代價是：場次表上看不出這幾場是一組。**這不是損失** —— 場次表是給製作端的投影，而製作端要的正是把它們拆開排通告；「這是一組對剪」是敘事事實。若日後證明有需要，那是場次表加一個推導欄位的事，不動編號也不動資料模型。

**一個場次帶多值 metadata**（地點欄裝兩個地點）。否決：它同時撕掉場次的定義與場次表的投影性質。唯一的例外是**雜景**，而那個例外是有原則的 —— 我們刻意不要求編劇拆開雜景（業界現行寫法就是一句散文，拆開是新增資訊而非推導），既然承認一個雜景場次橫跨多地，它的地點欄就該誠實地裝得下多個值。雜景因此是場次定義唯一的逃生口，邊界是 `內外＝雜景`。

**用子場次（階層）表達對剪。** 否決：對剪的兩邊**地位相等**，沒有誰附屬於誰。硬塞進階層會讓 `26.1` 這個編號說謊。反過來，群組也吃不掉子場次 —— 插入戲確實是附屬關係。**兩套機制作用在不同層次，都要留著。**

**把「不交錯」的情境（複合地點、雜景）也塞進群組。** 部分否決：群組**能**裝雜景（不交錯的群組，每個成員一個片段），這作為編劇自願升級的選項保留；但**預設不要求**。至於連續動作跨越多個空間（公寓→陽台→回公寓），它的需求是**連續性**不是交錯，機制候選是子場次而非群組，已另開票券處理。

## Consequences

**成員場次沒有自己的內容。** 內容在片段裡。這是這個形狀誠實的代價，而且它只影響群組內部 —— 群組之外的場次一律照舊。它也正好對應現實：成員場次是**拍攝**的單位，片段是**閱讀**的單位。

**建立是重手勢、切換是輕手勢，兩者必須分開。** 建立群組走 `/對剪到…`（第二步沿用子場次那個「選既有場次或建立新的一場」），整段戲只做一次；切換片段歸屬走 `⌘+1`／`⌘+2`／`⌘+3` **直接定址**，一段對剪要用五到十次。不用循環鍵 —— 三地對剪也算常見，循環要編劇記住順序，那是心流的裂縫。`⌘+4` 在只有三個成員時是無效鍵，**永遠不會憑空建立場次**（沿用 ADR-0003 的規則：會產生永久錨點的動作，入口只有一個）。

**`/next` 與 `Tab` 的語意不變。** 群組裡按 `/next` 仍然是「結束目前的東西，建立下一個場次」—— 它結束群組，不是新增第四個成員。`Tab` 仍然只改區塊型別，永不動容器。

**PDF 沒有台灣範本可循。** 三份台灣格式範本完全沒有觸及交叉場次。依王瑋《淡入》（2020）的裁決規則（台灣未有明確規範之處以美式為準）採美式寫法 A：**先建立、再宣告、再交錯**。交錯段落的歸屬標記印**地點名**而非場次號 —— 場次號在同一頁重複出現，在台灣慣例裡很可能被讀成排版錯誤，而 PDF 的水準線是「拿去參賽會被接受」。標記必須能區別成員；顯示名相同時（同一套陳設、只差日夜）補印區別欄位，這由上面那條不變式保證做得到。

**草稿成員會讓整個群組印不出來。** 群組少一個成員就不是那段戲了，印出殘缺的對剪比不印更糟。匯出前的草稿清單要特別標示「這場屬於一個對剪群組」，讓編劇知道略過它的後果比表面上大。

**拖曳成本再增加。** 繼子場次之後，落點合法性又多了兩條：群組不能巢狀，一個場次不能同時屬於兩個群組。
