# 連續動作跨越多個空間以「接續子場次」表達，升級路徑留給重疊群組

一段連續動作跨越多個空間（公寓客廳 → 陽台 → 回客廳 → 廚房），在 v1 範圍內，**以子場次表達**，並在子場次上新增一個列舉欄位記錄它與主場次的關係：

```
子場次.種類 = 插入 | 接續
```

- **插入** —— 另一段時空的戲（閃回、閃進、夢境）。原本 [ADR-0003](./0003-inserted-scenes-as-subscenes.md) 的唯一用途。
- **接續** —— 連續動作走進另一個空間，中間沒有時間間隔。本 ADR 新增。

結構完全共用，[ADR-0003](./0003-inserted-scenes-as-subscenes.md) 的所有規則原封不動適用（完整 metadata、不繼承、自己的永久 id、進場次表、深度兩層、跟著主場次一起搬）。**只有語意分岔，結構不分岔。**

## 為什麼連續性是真資訊

美式劇本**沒有簡表**那個大格子，卻仍然發明了兩套機制標連續性（次場次標題 mini-slug、時段欄填 `CONTINUOUS`）。所以連續性不是被簡表這種呈現方式寵壞的東西，它獨立於呈現方式存在 —— 拆成三個相鄰的場次之後，**沒有任何東西說它們是一氣呵成的**，而那是製片排通告要用的事實。

但它在 v1 **沒有活的消費者**：真正的消費者是拍攝行程，而那是第三層、範圍外。因此本 ADR 的成本上限是「**免費**」，定義為三條測試：

1. 不新增資料欄位 —— **後改為**「不新增編劇的動作」，見下。
2. 不新增編劇要填的東西。
3. 不新增讀的人要懂的概念。

第 1 條在盤問中被修正：[票券 07](../../.scratch/scenephonie-mvp/issues/07-scene-numbering-and-anchor.md) 的**交付快照**已經立過先例 —— 一份 v1 完全沒有消費者、沒有任何 UI 的資料，理由是它「寫入時幾乎免費、事後補不回來」。`種類` 是同一個形狀：編劇按下 `/insert` 或 `/continue-to` 的那一刻，這個宣告是免費的；丟掉它，日後要撿回來就得叫編劇打開舊劇本逐個回頭標。**欄位可以加，只要那一欄的值是編劇本來就會產生的副產品；不能加的是負擔。**

## 主場次是結構事實，不是地理事實

「誰是主、誰是次」的判準是 [票券 10](../../.scratch/scenephonie-mvp/issues/10-character-location-entities.md) 定的：

> **主場次 ＝ 這段連續動作的起點場次**（也就是誰是父節點）。

美式的主／次標題也是階層拓樸，但**他們的階層建立在地點的包含關係上**（廚房在公寓裡面），而票券 10 已經否決地點實體之間的包含關係。**所以美式那條先例對我們是失效的** —— 不能用它替我們的階層背書，我們的「主」只剩下「戲從哪裡開始」。

這帶來一個真實的語意代價：父子關係宣告了「附屬」，而連續性其實只是「相鄰」，**結構說得比實情多**。本 ADR 選擇承認這個代價並用定義去消毒（`CONTEXT.md` 明寫「附屬是結構詞，不是敘事詞」），而不是換結構。

**沒有丟資訊**：「廚房是從陽台接下來的」仍然在**文件順序**裡 —— 廚房的片段緊接在陽台的片段之後。樹記錄「這一整段從客廳開始」，順序記錄「中間怎麼走」，兩者合起來是完整的。

## 不變式

**① 主場次的內容必須以主場次自己的內容開始。** 子場次不能是第一個孩子。

這不是新規定，是把「主場次 ＝ 起點場次」執行出來 —— 一個內容從子場次開始的主場次，它就不是起點場次，結構在說謊。副作用是編號與場次表的順序保持單調（`25 / 25.1 / 25.2`，且與閱讀順序一致），而不會出現 `25.1 / 25.2 / 25 / 25.3` 這種讀不出來的排列。由編輯器保證：空場次裡 `/insert` 與 `/continue-to` 不可用。

**② 子場次的 metadata 不得與主場次完全相同。** 相同的話依場次的定義它根本不是另一個場次。

沿用 [ADR-0004](./0004-scene-groups-for-intercut.md) 在群組成員上用過的同一招，**零新機制**：相同視為 metadata 不完整 → 自動是草稿 → 匯出前被攔。

## 升級路徑：留給重疊群組

長期而言**重疊群組**更貼近領域模型（成員平等，沒有假的附屬關係），但它在 v1 進不來：重疊的區間**不是樹**，而 Tiptap／ProseMirror 的文件模型嚴格是樹。群組可以像場次號那樣活在文件外面，但**場次號只被渲染，不被編輯**；群組要被建立、指派、拖曳。此外 PDF 的「以下對剪」宣告與 `⌘+1`／`⌘+2`／`⌘+3` 直接定址在重疊時都沒有答案。

**父子結構本身就是「有序片段 ＋ 歸屬對照」的樹狀寫法**，所以遷移是純程式可完成的，不需要編劇參與：

- 父場次每一段**連續的區塊** → 一個片段，歸屬父場次
- 每個子場次 → 一個片段，歸屬該子場次
- 同一棵樹上 `種類 = 接續` 的所有場次 → 一個連續群組

三個既有決策剛好扛住這次遷移：**metadata 完全不繼承**（ADR-0003，攤平時不必回父場次撈值）、**場次號是推導值**（[ADR-0002](./0002-scene-id-and-derived-scene-numbers.md)，`26.1` 變 `27` 不會斷任何引用）、**交付快照存推導結果而非輸入**（票券 07，紙上印過的號碼不被重算改寫 —— 這正是它當初憑原則預留、如今第一次真正兌現的情況）。

**保住這條路徑，v1 必須守四條：**

1. **`種類` 從 v1 就存。** 沒有它，遷移分不出插入與接續，得叫編劇回頭標。
2. **任何東西都不准引用「第幾個子場次」或 `26.1`，只能引用場次 id。**
3. **片段在 v1 不給 id、不給任何東西引用。** v1 的片段是隱含的；提早實體化會在「插入子場次把一個片段切成兩半」時製造一個沒人需要回答的繼承問題。
4. **子場次的內容型別必須是場次內容型別的子集**（深度兩層那條規則正好保證了這件事），這樣攤平是搬移而非轉換。

深度兩層在新模型裡自動消失，那是**放寬**，舊資料一律仍然合法。

## Considered Options

**場次群組（平行）。** 語意最誠實 —— 成員地位平等，沒有假的附屬；折返也漂亮（客廳一個成員、兩個片段）。而且它已經在 v1 裡，同樣免費。

否決的理由是**組合性**，不是它自身的缺陷：群組不能巢狀、一個場次不能同時屬於兩個群組（[ADR-0004](./0004-scene-groups-for-intercut.md)），所以「一段對剪，其中一邊是連續動作」表達不出來。而子場次與群組**天生組合** —— ADR-0004 明訂群組的成員場次可以有自己的子場次。**階層裝得進平行裡面，平行裝不進平行裡面。**

更根本地：群組和連續動作是**同一個層次**的東西，同層次的東西不會互相組合。要讓群組吃下兩者，就得開放重疊，而重疊撞編輯器的樹狀模型（見上）。

> ⚠️ [ADR-0004](./0004-scene-groups-for-intercut.md) 原本把這件事寫成「它的需求是連續性不是交錯，機制候選是子場次而非群組」，**那是宣告不是論證**；同一份 ADR 裡「群組不能巢狀、一個場次不能同時屬於兩個群組」也只是列在 Consequences 裡沒有理由。本 ADR 補上兩者的論證。順帶修正群組章程的措辭：群組真正保住的不是「交錯」，而是**閱讀的單位和拍攝的單位對不起來時的片段歸屬**（交錯是其中一例，折返是另一例）。這不改變 v1 的任何行為。

**指向場次 id 的指標（`接續自: sc_xxx`）。** 語意剛剛好 —— 它宣告「相鄰」，不宣告「附屬」。

⚠️ 先澄清一個混淆：[票券 17](../../.scratch/scenephonie-mvp/issues/17-continuous-action-across-spaces.md) 原本把它歸進被否決的**旗標**家族（`S5A`、平坦 + `depth`），**那是錯的**。布林旗標（「接續前一場」）指的是**位置**，位置一變就指到別人；指向 id 的指標指的是**那個場次本人**，怎麼搬都不會指錯。它不會說謊。

真正的否決理由是**它會失效**：把一場無關的戲拖到中間，指標仍然指著正確的場次，但那個宣告變成假的（兩者已經不相鄰）。於是要處理一個新狀態 —— 默默刪掉是在編劇背後改資料，跳警告是新增一個要懂的概念，什麼都不做則讓第三層照單全收一個假宣告。**父子沒有這個狀態，因為子場次跟著父場次一起搬，那個落點根本拖不進去 —— 不合法的狀態表示不出來。** 另外，指標救得了連續性，救不了折返（公寓客廳仍然拿到兩個場次號、場次表上兩列）。

**再造一個「連續動作序列」實體。** 否決：那是把場次群組抄一份拿掉交錯，做出一個結構相同、只有名字不同的概念。

**硬性要求接續子場次的時間欄與主場次相同（建立時鎖住）。** 否決：與 ADR-0003「metadata 完全不繼承」直接衝突，而預填會騙過草稿防呆。長鏡頭跨過黃昏到入夜也是可能的，不能硬攔。

**偵測到時間欄與主場次不同時跳提示**（沿用票券 10 給登場人物那套）。否決：作者提出更好的形狀 —— 時間欄本來就是下拉選單，把主場次的值**置頂並標注「（原場次）」**即可。它在錯誤發生**前**作用而非發生後補救，欄位仍然是空的（不預填、草稿防呆照常運作），而且反而少了一次捲動。

## Consequences

**`種類` 有一個 v1 消費者，雖然小。** 它決定時間下拉選單怎麼排：`接續` 把主場次的值置頂並標注「（原場次）」；`插入` 只標注、不置頂（閃回的時間常刻意與主場次相反，置頂會推編劇往錯的方向走）。地點欄兩者都不置頂 —— 接續的前提就是地點變了，主場次的地點保證是錯的答案。這讓一個原本純為升級路徑而存的欄位變得好辯護得多。

**入口分成兩個，用詞跟著分。** 概念不同，只是剛好共用結構，所以名字該說概念不該說結構：

| 代號           | 選單標籤                       | 建立什麼                       |
| -------------- | ------------------------------ | ------------------------------ |
| `/insert`      | **插入戲**（閃回、閃進、夢境） | `種類 = 插入` 的子場次         |
| `/continue-to` | **接續到…**                    | `種類 = 接續` 的子場次         |
| `/back-to`     | **回到 <主場次地點>**          | 不建立任何東西，游標跳回主場次 |

英文代號的理由是 `/` 之後打中文要切輸入法，那是心流的裂縫；中文標籤仍是編劇看到的字。標籤用「插入戲」而非「插入場次」，避免與**插入畫面**在口頭上撞車。

`/insert` 與 `/continue-to` **在主場次與子場次裡都可用，語意不變** —— 它們永遠是「在本主場次底下建立一個子場次」。深度兩層那條規則讓「在子場次裡按下去」只有一種合法解讀（建立兄弟），沒有歧義，因此**不違反 ADR-0003「入口只有一個」** —— 那條規則防的是同一個東西有兩條不同的生路，不是禁止同一個指令站在兩個位置。

**`/back-to` 不受「入口只有一個」管**，因為它不建立永久錨點。主手勢仍是**雙 Enter**（在子場次末尾的空區塊按 Enter 提升出去，ProseMirror 的 `liftEmptyBlock`）；選單項是可發現性的那一半，而且 `接續到…` 與 `回到 公寓客廳` 並排出現的那一刻，本身就在教這個模型長什麼樣。

**折返在 PDF 上印地點顯示名，不印場次號。** 重印 `26　內景　公寓客廳　夜` 已被 [ADR-0004](./0004-scene-groups-for-intercut.md) 的同一條理由否決（場次號在同一頁重複出現，在台灣慣例裡很可能被讀成排版錯誤，而 PDF 的水準線是「拿去參賽會被接受」）。

印法是 `回到　公寓客廳`。**不照抄美式的裸次標題**（`THE APARTMENT`）—— 那在英文裡讀得懂是因為場次標題全大寫，那個視覺文法本身在說「這是標題」；我們的 PDF 沒有大寫這回事，一行孤零零的 `公寓客廳` 沒有任何線索能與動作或漏字區別。「回到」兩個字由模板產生，**不進資料模型**，位階同 ADR-0004 的「以下對剪」。

推導規則兩條，全部從結構讀得出來，不必問編劇：

| 情況                                       | 印什麼           |
| ------------------------------------------ | ---------------- |
| 父場次一段**非空**內容，且之前出現過父內容 | `回到　公寓客廳` |
| 兩個子場次相鄰（中間沒有非空父內容）       | **不印**         |

「本場次第一次出現父內容」那個情況因不變式 ① 而不可能發生。空區塊不算內容 —— 這讓編劇雙 Enter 跳出來、卻又改打 `/continue-to` 時，標記**從頭到尾沒有出現過**，畫面不會自己閃一下。空區塊改用 placeholder 交代「你在哪一層」（縮排是另一半），placeholder 與標記同一位階，都不進資料模型。

**編輯器裡也要即時顯示這個標記**，機制與場次號相同（decoration）。只印在 PDF 會讓編劇跳出子場次後不知道自己在哪一層 —— 那正是編輯器選型票券那六個 bug 的病根：結構變了但畫面沒說。

**場次表不顯示 `種類`。** 第一層維持票券 02 定的六欄。連續性的消費者在第三層，現在加一欄是替一個還不存在的消費者改已定案的規格。折返本身是免費解決的 —— 客廳只有一列，因為折返的內容是父場次自己的區塊而非新場次。沿用 ADR-0004 留的退路：若日後證明有需要，那是場次表加一個推導欄位的事，`種類` 已經存在資料裡，不印不會讓資訊消失。

**插入畫面的界線不變，但逃生口的文案要改。** 第一條防線（與本場次同一個時空，時空一變就走子場次）完全適用，接續沒有製造新的模糊地帶。但區塊上原本那個「換了時空？改成子場次」的逃生口現在要列**兩個目的地**：「改成**插入戲** ／ 改成**接續**」。用詞刻意與 `/` 選單相同 —— 在第二個場合重複同一課，不必再學新東西。**不預設變成插入戲**：那會在編劇背後決定 `種類`，而那一欄的全部價值就在於它是編劇的宣告。

**編劇仍然可以什麼都不標。** 他大可在動作裡直接寫「兩人走進廚房」而不建立任何子場次，那時模型不知道戲換了空間。這是散文的固有漏洞（同**雜景**），產品不能取締散文；`種類` 只保證**標了的**是真的，不保證沒標的不存在。
