# 「場景」指敘事單位，地點一律稱「地點」

台灣影視圈對「場景」一詞的用法嚴重分歧：編劇教學文獻用它指**敘事上的事件或情境**（一個場景可橫跨多個場次，這正是「分場大綱 40 場、劇本卻 130 場」的來源），但順場表的欄位、以及日常對話（場景設計、勘景）用它指**地點**。而且指地點的用法在日常更常見。

我們選擇**「場景」＝敘事單位**（採用編劇教學文獻的正式定義），並讓地點一律稱「**地點**」。歧義的唯一實際碰撞點是我們會匯出的順場表 —— 該表慣例欄名為「場景」但內容是地點 —— 我們**在輸出時把該欄標為「地點」**，不沿用業界欄名。

## Considered Options

**另外替敘事單位取名，把「場景」讓給地點。** 候選字都有問題：`事件`（與程式的 event 撞）、`段落`（與 paragraph 撞）、`橋段`（通常指套路而非結構單位）、`情境`（太虛）。更根本的代價是，我們會失去與編劇教學文獻共用的詞彙，作者每次跟編劇溝通都得翻譯回「就是場景」。

為了單一碰撞點放棄整套領域詞彙，代價不划算 —— 尤其那個碰撞點可以靠輸出層改名直接消掉。

## Consequences

**內部詞彙與對外標籤刻意分離。** 這與場次號的處理是同一個思路（永久 id 對內、場次號對外顯示）。匯出任何業界表單時都要意識到：**欄名是輸出層的事，不該回頭污染領域模型。**

**跟劇組非編劇職位溝通時仍有誤讀風險。** 產品介面若對非編劇顯示「場景」，對方會讀成地點。若日後 UI 要面向劇組其他職位，此處需重新評估。
